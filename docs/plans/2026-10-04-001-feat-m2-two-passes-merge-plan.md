# feat: Два прохода и сборка (M2)

## Summary

Веха M2 — хребет риска роадмапа: второй проход после разворота пачки, сборка `interleave`,
защита от несовпадения числа страниц (модалка `mismatch`, сборка по совпавшим парам, первый
проход цел), аварийный переключатель «повернуть обороты на 180°», экраны `flip` и `merge`,
минимальное сохранение в один PDF — атомарно. Входы: роадмап → M2; `docs/duplexnt-tech.md`
разделы 5–6 (логика двух проходов, подтверждённая экспериментально); `docs/design/UI_SPEC.md`
разделы 3–5, 7.5; [ADR 0007](../decisions/0007-pdf-library.md) (`@cantoo/pdf-lib`) и амендмент
[ADR 0004](../decisions/0004-data-model.md) от 2026-10-04 (поворот 180° — атрибут прохода),
принятые при этом планировании; журнал M1 `docs/solutions/0002-m1-connect-single-pass.md`.

**Выход вехи (роадмап):** двусторонняя пачка с живого ET-3850 сохранена в PDF в правильном
порядке; сценарий замятия не теряет первый проход.

## Problem Frame

После M1 приложение сканирует один проход и показывает страницы в каркасе редактора; `flip` и
`merge` не рендерятся (временное ребро `scan → editor`, план M1 KTD-25), PDF не существует,
`pass-service` политикой запрещает новый проход при живой сессии. При этом инфраструктура под
M2 уже заложена: журнал v1 несёт номера проходов и состояние «прерван и принят как есть»
(введено специально для сборки), ключи страниц устойчивы, атомарная запись готова
(`src/core/storage/atomic-file.ts`); эмулятор задаёт пока только **число** листов в лотке
(`sheets` в `Scenario`) — содержимое лотка по заданиям и перезарядку между проходами
добавляет U4.

Критичный факт из M1: сбой «ролик не взял лист» выглядит как обычный `404` и **неотличим от
конца пачки** (журнал M1, U1). Единственная защита от молча потерянного листа — сверка числа
страниц двух проходов. `mismatch` в M2 — механизм безопасности данных, а не только UX.

Развилки, снятые при планировании ответами автора (2026-10-04):

1. **Библиотека PDF** → `@cantoo/pdf-lib` — [ADR 0007](../decisions/0007-pdf-library.md).
2. **Поворот оборотов на 180°** → флаг прохода оборотов в журнале + тумблер в редакторе —
   амендмент [ADR 0004](../decisions/0004-data-model.md); per-page правки остаются в M3.
3. **Минимальное сохранение** → кнопка «Сохранить документ» открывает системный диалог
   «Сохранить как»; модалка `save` целиком — M3 (KTD-3).
4. **Перфоманс-находки ревью M1** (полный JPEG в превью, лента без виртуализации, `no-store`)
   → осознанно в бэклог, с условием возврата: тормоза на живом двухпроходном смоуке (KTD-10).

## Requirements

Проверяемые требования; в скобках — источник.

**Второй проход**

- R1. После завершения нечётного прохода приложение показывает `flip`; следующий проход
  запускается **только по нажатию**, автоперехода нет (спека «Сканирование в два прохода»,
  UI_SPEC §4).
- R2. Счётчик чётного прохода — «Отсканировано N из M», где M — число страниц предыдущего
  нечётного прохода; счётчик может перевалить за M и не подрезается (UI_SPEC §3).
- R3. «Остановить» на проходе оборотов отбрасывает только снятое текущим запуском и ведёт на
  экран, с которого проход запущен: первый сегмент → `flip`, досканирование прерванного →
  удалён только идущий сегмент, экран `editor`; лицевой проход цел всегда (UI_SPEC §3
  «Отмена», ADR 0004).
- R4. Обрыв чётного прохода (замятие, сеть, падение) сохраняет полученные страницы, проход
  помечается прерванным; «принят как есть» участвует в сборке коротким (ADR 0004).
- R5. «Обороты не нужны» уводит одностороннюю пачку в сборку без второго прохода (UI_SPEC §4).
- R6. Перезапуск приложения между проходами возвращает на `flip`; второй проход можно
  продолжить (ADR 0004: «падение между проходами не стоит первого прохода»).

**Сборка**

- R7. Порядок по умолчанию — `interleave`: обороты приходят в обратном порядке, оборот листа k
  = страница N−k+1 чётного прохода (техбаза §5). Порядок — производное, в журнал не пишется
  (ADR 0004).
- R8. Несовпадение числа страниц: документ собирается по совпавшим парам, модалка `mismatch`
  сообщает фактические числа и называет листы без оборота; ни одна страница не выбрасывается
  (техбаза §6, UI_SPEC §7.5). Кнопок действия в модалке нет — досканирование появится с
  «Добавить» (M3+).
- R9. Переключатель «повернуть обороты на 180°»: одно обратимое решение на чётный проход,
  исходники не меняются, применяется к отображению и как `/Rotate` в PDF (амендмент ADR 0004).
- R10. Экран `merge` — процессный, без органов управления, уходит сам; статусная строка —
  фактический результат сборки, первой сообщает о несовпадении (UI_SPEC §5).

**Сохранение**

- R11. Сохранение одного PDF: JPEG вкладывается без перекодирования, поворот — свойством
  страницы, запись атомарна (temp → fsync → rename рядом с целью); сбой записи не портит ни
  целевой файл, ни сессию (ADR 0007, спека «Безопасность данных»).
- R12. Сохранение не удаляет сессию; отметка о сохранении — в журнале; предупреждения о
  несохранённом согласованы с ней (ADR 0004, UI_SPEC §7.4).

**Данные и платформа**

- R13. Журнал поднимается до версии 2 одним подъёмом (флаг поворота, отказ от оборотов,
  отметка о сохранении); чтение v1 обязательно (амендмент ADR 0004).
- R14. Возвращаются полные тексты `setup`/`scan` макета (план M1 KTD-25); слова «пачка» в
  текстах интерфейса нет (UI_SPEC §7.4); параметр «Пустые обороты» не показывается до M4.
- R15. Сценарии эмулятора — той же вехой: два прохода, недостающий лист, обрыв второго
  прохода (роадмап «Сквозные нити»).

## Key Technical Decisions

- **KTD-1. PDF — `@cantoo/pdf-lib`** — [ADR 0007](../decisions/0007-pdf-library.md), не дубль:
  `embedJpg` без перекодирования, `setRotation(degrees(180))`, devDependencies.
- **KTD-2. Поворот 180° — флаг прохода оборотов** (роль по KTD-4, не чётность номера) —
  амендмент [ADR 0004](../decisions/0004-data-model.md); тумблер в редакторе (через handoff —
  в макете его нет, UI_SPEC §11.7).
- **KTD-3. Сохранение M2 — системный диалог.** «Сохранить документ» в тулбаре редактора →
  `dialog.showSaveDialog` в main (файловые диалоги — обязанность main по ADR 0003) → один PDF
  со всеми страницами в собранном порядке. Имя, папку и подтверждение перезаписи даёт диалог
  ОС. Отклонена урезанная модалка `save`: её содержимое (границы, имена, «отдельные файлы»)
  опирается на редактор M3 — делали бы дважды.
- **KTD-4. Правило сборки, пар и роли прохода.** **«Нечётный/чётный» во всём плане — роль,
  а не чётность `pass.number`:** первый уцелевший (непустой, неотброшенный) проход сессии —
  лицевые, второй — обороты. Номера проходов не переиспользуются (ADR 0004), поэтому после
  «Остановить» на проходе оборотов повторный запуск получает номер 3 — и обязан вести себя как
  оборотный (счётчик «N из M», флаг поворота, сборка, `screenOf`). Чтение роли из
  `pass.number % 2` — ошибка. Сама сборка — чистая функция ядра над страницами двух проходов
  (`pagesOf`): `interleave(fronts, backs)` с разворотом `backs`. Пары считаются от начала
  прохода оборотов: его первая страница — оборот **последнего** листа лицевого прохода (физика
  разворота, техбаза §5). При нехватке оборотов непарными остаются листы с меньшими номерами;
  при избытке лишние обороты идут в конец набора и не выбрасываются. Функция возвращает и
  порядок, и отчёт (пары, непарные листы, лишние обороты) — отчёт кормит `merge`-статистику и
  `mismatch`.
- **KTD-5. Экран выводится из снимка, навигационного состояния нет** (конвенция M1,
  `src/renderer/src/state/screen.ts`). `flip` = сессия, где единственный уцелевший проход —
  лицевой (роль по KTD-4), он завершён или принят, и отказа от оборотов нет; «уцелевший»
  существенен — «Остановить» на проходе оборотов не должно оставить пустую запись прохода
  «последней» (вариант реализации: discard убирает опустевший проход целиком; номер не
  переиспользуется — ADR 0004). Отсюда бесплатно: «Остановить» на **первом сегменте** прохода
  оборотов возвращает на `flip` (R3) и перезапуск между проходами открывает `flip` (R6).
  «Остановить» при **досканировании** прерванного прохода оборотов — семантика M1 и UI_SPEC §3:
  удаляется только идущий сегмент, проход остаётся прерванным, экран — `editor` с
  `canResume`/`canAccept`. `merge` — эфемерная пауза UI при переходе «проход оборотов завершён →
  editor» (1600 мс; 1200 мс после «Обороты не нужны»); таймер живёт в renderer (состояние
  поверх `screenOf`) и обязан пережить StrictMode double-render (урок M1) — проверяется
  jsdom-тестом U9; после перезапуска пауза не повторяется — сборка уже видна в редакторе.
- **KTD-6. «Обороты не нужны» — durable-отметка в журнале v2.** Иначе перезапуск вернул бы
  закрытую одностороннюю пачку на `flip`. Эфемерное состояние renderer отклонено.
- **KTD-7. Журнал v2 — одним подъёмом** (R13): флаг поворота, отказ от оборотов, отметка о
  сохранении. Точная форма полей — решение реализации, фиксируется амендментом ADR 0004 по
  образцу «формы журнала версии 1» (правило то же: в журнале нет того, что выводится из
  другого).
- **KTD-8. Показ `mismatch` выводится из снимка, а не из перехода.** Модалка показывается при
  первом входе в `editor` за время жизни процесса, пока отчёт сборки несёт неподтверждённое
  несовпадение, — включая вход через «Оставить как есть» (приёмка короткого прохода оборотов
  завершает сборку так же, как переход через `merge`) и вход после перезапуска: `mismatch` —
  механизм безопасности данных, падение в окне паузы `merge` не должно проглотить его
  навсегда. Закрытие модалки — подтверждение (эфемерное, на время жизни процесса). До приёмки
  прерванного прохода оборотов лента показывает сборку по фактическим парам (отчёт — derived).
  Постоянная видимость несовпадения после закрытия модалки — пометка непарного листа в ленте
  (форма — handoff U7); полный блок «Проверка» — M3.
- **KTD-9. Размер страницы PDF — из размеров JPEG и DPI прохода** (пункты = пиксели / DPI ×
  72); формата-константы нет (правило «capabilities определяют UI», параметры прохода — в
  `origin` журнала). Предел пикселей страницы при сборке сверяется с `origin.pixelLimit` —
  потолок sharp не ослабляется (ревью M1, сессия 5). **Пересобранная сессия (`origin = null`,
  ADR 0004: журнал восстановлен по именам файлов)** всё равно сохраняется — данные пользователя
  спасаемы: DPI берётся из плотности JFIF, если она есть, иначе дефолт 300 dpi (размер страницы
  может отличаться от физического листа, страницы целы); предел пикселей — встроенный потолок
  sharp.
- **KTD-10. Перфоманс-находки M1 — в бэклог** («Входящие»: полный JPEG в превью при
  автоповторе, лента без виртуализации, `no-store` миниатюр). Условие возврата: заметные
  тормоза на живом двухпроходном смоуке M2.
- **KTD-11. Ожидание занятости на `flip` — существующим ретраем.** После «Остановить»
  устройство ~25 с отвечает `503` и прогоняет остаток пачки в лоток (журнал M1): запуск
  второго прохода в это окно переживается фазой `busy` ретрая M1; `flip` показывает состояние
  «сканер занят», текст напоминает собрать листы из выходного лотка. Опрос `AdfState` для
  подсветки кнопки — пост-MVP, не трогаем.
- **KTD-12. Память и процесс сборки PDF.** Худший замеренный случай — не «десятки страниц по
  сотни КБ»: по замерам M1 (журнал, KTD-36) страница 600 dpi в цвете — 3,4–3,5 МБ, двусторонняя
  пачка из 50 листов — ~350 МБ JPEG; `pdf-lib` держит документ в памяти и на `save()` создаёт
  вторую копию. Сборка идёт в main-процессе (ядро, вызванное обработчиком) — U5 обязан прогнать
  набор, эквивалентный худшему замеренному объёму, с наблюдением пика памяти и отзывчивости
  event loop (сборка асинхронна по страницам, между `embedJpg` управление возвращается циклу).
  Если прогон покажет блокировку или недопустимый пик — выделенный worker отдельным решением;
  условие названо здесь, механизм заранее не строим.

## High-Level Technical Design

Слои — без новых границ; один путь исполнения сохраняется (сканер/эмулятор/тесты через один
клиент).

```
renderer (React)                 core (без Electron)                    main
────────────────                 ───────────────────                    ────
screenOf(snapshot)               scan/pass-service ──→ escl/scan-job    bridge, события
  setup → scan → flip → scan →     startPass: чётный проход,           dialog.showSaveDialog
  merge(пауза UI) → editor         expected из нечётного                (путь для savePdf)
FlipScreen · MergeScreen         scan/assembly  ← НОВОЕ
MismatchModal · тумблер 180°       interleave + отчёт пар (derived)
кнопка «Сохранить документ»      pdf/assemble   ← НОВОЕ (@cantoo/pdf-lib)
                                 storage/journal v2 (+чтение v1)
                                 commands/handlers: declineBacks,
                                   setRotateBacks, savePdf
```

Поток второго прохода: `flip` → `startPass` (та же служба; политика «новый проход только без
сессии» заменяется правилом «чётный проход поверх завершённого/принятого нечётного») → страницы
пишутся как в M1 (сегменты, ключи `p02-s01-…`) → завершение → снимок меняется → UI показывает
`merge`-паузу → `editor` (+ `mismatch`, если пары не сошлись).

Поток сохранения: кнопка → `savePdf` через мост → main спрашивает путь диалогом → ядро строит
порядок (`assembly`), валидирует страницы, собирает PDF (`pdf/assemble`), пишет атомарно рядом
с целью → отметка в журнале → тост. Сборка и запись не блокируют интерфейс — механизм и
проверка объёма — KTD-12.

Снимок (`src/shared/snapshot.ts`) расширяется: ожидаемое число страниц чётного прохода, флаг
поворота, отказ от оборотов, отчёт сборки (для `merge`/`mismatch`/редактора), отметка
сохранения. Экран — по-прежнему чистая функция от снимка.

## Implementation Units

Порядок = порядок выполнения. Гейт каждого юнита: typecheck + lint + format:check + test:all
зелёные; коммит `feat(m2): U<N> …` в ветке `feat/m2`.

### U1. Журнал версии 2 и чтение версии 1

- **Что:** подъём `JOURNAL_VERSION` до 2; поля по KTD-2/6/7: флаг поворота оборотов (атрибут
  прохода оборотов — роль по KTD-4), отказ от оборотов, отметка о сохранении; отметка о
  сохранении **снимается любой последующей правкой, влияющей на вывод** (`setRotateBacks`,
  новые страницы) — иначе после «сохранил → включил тумблер» индикация соврёт «сохранено», а
  на диске лежит неправильный PDF. Чтение v1 (отсутствие новых полей
  = значения по умолчанию); запись всегда v2. Форма полей фиксируется амендментом ADR 0004.
- **Файлы:** `src/core/storage/journal.ts`, `src/core/storage/session-store.ts` (методы
  установки флагов), `src/shared/snapshot.ts`; тесты рядом (`journal.test.ts`,
  `session-store.test.ts`).
- **Требования:** R13; поля для R5/R9/R12.
- **Паттерны:** строгая zod-схема, «запись проверяется той же схемой, что и чтение»;
  `versioned-file.ts` — несовместимость будущих версий уже обрабатывается.
- **Тесты:** round-trip v2; чтение журнала v1 даёт дефолты и переписывается как v2; данные
  версии 3 → режим `incompatible` (существующий тест расширить); флаги переживают
  перезапуск-сверку (`reconcile`); «в журнале нет выводимого» — порядок сборки не пишется.
- **Гейт:** стандартный.

### U2. Сборка: `interleave`, пары, отчёт (ядро, derived)

- **Что:** модуль `src/core/scan/assembly.ts` (KTD-4): из снимка сессии (страницы проходов,
  состояния, флаги v2) строит порядок по умолчанию и отчёт — совпавшие пары, листы без
  оборота (с номерами), лишние обороты, участие прерванно-принятого прохода. Учитывает «обороты
  не нужны» (только лицевые) и поворот (прокидывается признаком к страницам чётного прохода).
- **Файлы:** `src/core/scan/assembly.ts` + `assembly.test.ts`; расширение
  `src/shared/snapshot.ts` (отчёт сборки в снимке).
- **Требования:** R7, R8 (расчётная часть), R9 (признак поворота), R4 (короткий принятый
  проход).
- **Тесты (табличные, обязательная зона тест-политики):** равные проходы 3+3 → 1л,1о,2л,2о,3л,3о;
  чётный короче на 1 → непарный лист №1 (младший), пары не съехали; чётный длиннее (двойной
  захват в первом) → лишние обороты в конце, не выброшены; «обороты не нужны» → только лицевые;

  возвращается к состоянию «flip»; при досканировании прерванного — семантика M1 (удаляется
  только идущий сегмент, проход остаётся прерванным, экран `editor`). Роль прохода везде — по

### U5. Сборка PDF в ядре

- **Файлы:** `package.json`, `src/core/pdf/assemble.ts` + `assemble.test.ts`.

  порядок, если сессия упрётся).

  фикстурных JPEG устройства: байты потока изображения в PDF **равны исходнику** (нет

- Перфоманс-находки ревью M1: полный JPEG в превью при автоповторе, лента без виртуализации,
  `no-store` миниатюр (KTD-10; условие возврата — тормоза на живом смоуке M2).
- `canResume` не сверяет параметры прохода с нынешними capabilities (остаточный риск M1, на
  втором проходе актуальнее — если не закроется попутно в U3, строка в бэклог).

## System-Wide Impact

- **Формат журнала: версия 2** — первый подъём версии; чтение v1 обязано жить (амендмент ADR
  0004). До первого выпуска миграция не нужна.
- **Новая зависимость** `@cantoo/pdf-lib` (devDependencies, бандлится Vite) — ADR 0007;
  `electron-builder.yml` не меняется (белый список пакует бандл).
- **Снимок и мост растут**: новые команды (`declineBacks`, `setRotateBacks`, `savePdf`) и поля
  снимка — по правилам моста (одна функция на команду, валидация в ядре).
- **Первая запись за пределы каталога данных** (PDF в папку пользователя) — та же атомарная
  утилита, temp рядом с целью.
- Доки: спека (стек, `<не определено>`), UI_SPEC (ребро M1, §3–5, §11.7), роадмап, бэклог.

## Risks & Dependencies

- **Физика двух проходов на живом железе** (риск #1): interleave подтверждён экспериментально
  (техбаза §5), но сквозной путь через приложение впервые. Де-риск: правило пар — табличные
  тесты (U2), эмулятор повторяет живые следы (U4), живой прогон с пронумерованными листами
  (U10).
- **`embedJpg` на реальных JPEG устройства**: формат проверен в M1 (baseline, без EXIF/ICC), но
  библиотека новая. Де-риск: тесты U5 против фикстур с устройства, сравнение байтов потока;
  провал → запасной `@pdfme/pdf-lib` (ADR 0007, drop-in тот же API).
- **Неоднозначность пар при несовпадении**: при потере листа в середине второго прохода
  истинное соответствие неизвестно в принципе. Принято: пары по позиции (KTD-4), текст модалки
  говорит «скорее всего» и называет листы по правилу; страницы не выбрасываются — ошибку
  правит человек в редакторе (M3 — досканирование).
- **Занятость после «Остановить» (~25 с)**: старт второго прохода сразу после остановки
  первого увидит `503`. Де-риск: существующий ретрай + состояние на `flip` (KTD-11), сценарий
  в смоуке.
- **Журнал v2**: ошибка схемы ломает совместимость. Де-риск: один подъём за веху (KTD-7),
  тесты чтения v1, строгая схема «запись = чтение».
- **Перезапуск между проходами** — новое поведение возобновления. Де-риск: derived-правило
  (KTD-5) + тест «новая служба над тем же корнем» (U4); UX подтверждается handoff'ом (U7).

## Acceptance Examples

- AE1. Эмулятор, 3 листа двусторонне: проход 1 (1л, 2л, 3л) → `flip` → проход 2 (3о, 2о, 1о) →
  `merge` → редактор показывает 1л, 1о, 2л, 2о, 3л, 3о; сохранённый PDF — 6 страниц в этом
  порядке.
- AE2. Живой ET-3850, пронумерованная двусторонняя пачка → PDF в правильном порядке (выход
  вехи).
- AE3. Эмулятор, второй проход отдаёт на лист меньше: `merge` сообщает о несовпадении первым,
  `mismatch` называет лист без оборота, документ собран по совпавшим парам, страницы первого
  прохода целы на диске.
- AE4. Обрыв второго прохода (`PageFault`): проход прерван, страницы целы, «Оставить как есть»
  → сборка по фактическим парам; «Досканировать остаток» доводит проход.
- AE5. «Обороты не нужны» → `merge` (1,2 с) → редактор только с лицевыми; после перезапуска —
  редактор, не `flip`.
- AE6. «Остановить» на первом сегменте второго прохода → возврат на `flip`, страницы второго
  прохода отброшены, первый цел; повторный запуск работает (учтя ~25 с занятости), и проход
  №3 ведёт себя как оборотный: счётчик «N из M», сборка, флаг поворота. «Остановить» при
  досканировании прерванных оборотов → удалён только идущий сегмент, экран `editor` (как M1).
- AE7. Перезапуск приложения между проходами → `flip` с числом листов первого прохода; второй
  проход доводится до конца.
- AE8. Тумблер «повернуть обороты на 180°»: обороты развёрнуты в превью и несут `/Rotate 180`
  в PDF; выключение возвращает; исходные файлы не изменились (байт в байт).
- AE9. Счётчик второго прохода переваливает («4 из 3», эмулятор) — показывается как есть;
  лишний оборот в наборе, не выброшен.
- AE10. Сбой записи PDF на шаге rename (`intercept-fs`): старый файл цел, сессия цела, ошибка
  с внятным текстом; повторное сохранение проходит.
- AE11. Журнал v1 от M1-сборки открывается, работает, переписывается как v2; журнал «версии 3»
  → экран несовместимости, запись заблокирована.
- AE12. «Сохранил PDF → включил тумблер 180°» → индикатор несохранённого вернулся; повторное
  сохранение пишет исправленную версию.
- AE13. Перезапуск приложения в окне паузы `merge` при несовпадении → `editor` показывает
  `mismatch` при первом входе; несовпадение не проглочено.
