# feat: модалки закрываются по Esc (B-11)

## Summary

Esc в модалке делает то же, что её кнопка отмены или закрытия. Модалка несовпадения набора — решение без отмены, она по Esc не закрывается. Клик по затемнению по-прежнему ничего не делает. Вход — карточка B-11 в бэклоге и решения автора от 2026-10-27. Новый UI не нужен, меняется правило UI_SPEC §7.

## Problem Frame

Сейчас модалку закрывает только кнопка: `components/Modal.tsx` ловит из клавиш лишь Tab (ловушка фокуса), а UI_SPEC §7 прямо пишет «закрытия по клику вне окна и по Esc в макете нет». Человек привык закрывать окно по Esc и вынужден тянуться к мыши или проходить Tab'ом до «Отмены».

При планировании карточку уточнили по коду. `mismatch` (несовпадение проходов) — не решение, а сообщение с одной кнопкой «Понятно»: «закрыть — нормальный исход» (комментарий модалки). Поэтому Esc её закрывает. Решение без отмены есть только у модалки несовпадения набора (`SetMismatchModal`).

---

## Requirements

- R1. Esc в модалке вызывает ту же функцию, что её кнопка отмены или закрытия:

  | Модалка    | Кнопка, которую повторяет Esc                                         |
  | ---------- | --------------------------------------------------------------------- |
  | `device`   | «Отмена»; во время подключения она доступна и отменяет его            |
  | `add`      | «Отмена»                                                              |
  | `newscan`  | «Отмена»                                                              |
  | `revert`   | «Отмена»                                                              |
  | `save`     | выбор — «Отмена»; частичный сбой — «Закрыть»; всё записано — «Готово» |
  | `mismatch` | «Понятно»                                                             |

- R2. Когда кнопка, которую повторяет Esc, недоступна (`save` во время записи, `newscan` во время закрытия сессии), Esc ничего не делает.
- R3. Модалка несовпадения набора по Esc не закрывается, как и сейчас.
- R4. Клик по затемнению без действия, как сейчас.
- R5. Обработанный Esc не уходит дальше модалки: экран под ней его не видит.
- R6. UI_SPEC §7 описывает новое правило.

---

## Key Technical Decisions

- **KTD-1. Одно необязательное свойство общей модалки.** У `Modal` появляется обработчик Esc. Каждая модалка передаёт ту же функцию, что висит на её кнопке отмены, а если кнопка недоступна — ничего не передаёт. Правило «Esc = эта кнопка» живёт в одном месте модалки и не расходится с кнопкой. Отклонено: слушатель Esc на `document` в каждой модалке — дубли и риск двух модалок, ловящих одно нажатие.
- **KTD-2. Esc ловится на окне модалки, там же, где ловушка Tab.** Фокус заперт в окне, а при `busy` держится на самом окне, так что нажатие доходит. Обработанный Esc глушится (`preventDefault`, `stopPropagation`): под модалкой лента редактора сжимает выделение по Esc, и это не должно срабатывать вместе с закрытием.
- **KTD-3. Esc закрывает и тогда, когда фокус в текстовом поле модалки.** Например, адрес в `device` или имена в `save`. Это обычное поведение диалога, а потеря ввода та же, что у «Отмены». Отклонено: первый Esc только снимает фокус с поля — непривычно и не просили.

## Implementation Units

### U1. Esc в общей модалке

- **Что:** у `Modal` появляется необязательный обработчик Esc. Нажатие Esc на окне вызывает его и глушит событие, а без обработчика ничего не происходит. Обновляется шапка-комментарий модалки.
- **Файлы:** `src/renderer/src/components/Modal.tsx`; тесты — `src/renderer/src/components/Modal.test.tsx`.
- **Тесты:**
  - С обработчиком Esc вызывает его один раз, а событие не всплывает до родителя (слушатель `keydown` на обёртке не срабатывает).
  - Без обработчика Esc ничего не делает, модалка на месте.
  - Другие клавиши (Enter, буквы) обработчик не вызывают; Tab по-прежнему ходит по кольцу.
- **Гейт:** typecheck, lint и test зелёные; коммит `feat(b-11): U1 …`.

### U2. Модалки передают свою отмену

- **Что:** модалки из R1 передают обработчик, `SetMismatchModal` — нет (R3). В `save` и `newscan` во время записи и закрытия обработчика нет (R2).
- **Файлы:**
  - `src/renderer/src/modals/DeviceModal.tsx`, `AddModal.tsx`, `NewScanModal.tsx`, `RevertModal.tsx`, `SaveModal.tsx`, `MismatchModal.tsx`;
  - тесты — `DeviceModal.test.tsx`, `AddModal.test.tsx`, `NewScanModal.test.tsx`, `SaveModal.test.tsx`, `MismatchModal.test.tsx`, `SetMismatchModal.test.tsx` (существующий тест «Esc не закрывает» остаётся), `RevertModal` — в `src/renderer/src/screens/EditorScreen.dnd.test.tsx`, где он уже проверяется.
- **Тесты:**
  - Каждая модалка из R1: Esc вызывает тот же колбэк, что кнопка.
  - `device`: Esc во время подключения вызывает `onClose`.
  - `save`: выбор — `onClose`; частичный сбой — `onClose`; всё записано — `onSaved` с отчётом; во время записи Esc ничего не делает.
  - `newscan`: во время закрытия Esc ничего не делает.
  - `revert`: Esc отменяет без сброса правок (`onCancel`, а не `onConfirm`).
  - Модалка несовпадения набора: Esc по-прежнему не закрывает.
- **Гейт:** как U1; коммит `feat(b-11): U2 …`.

### U3. Доки и приёмка

- **Что:**
  - UI_SPEC §7 — «Закрытие — „Отмена“, действие или Esc (= кнопка отмены или закрытия); клик вне окна без действия; модалка несовпадения набора по Esc не закрывается».

## Scope Boundaries

- Клик по затемнению не трогаем (R4).
- Esc вне модалок (лента, поля имён в редакторе) работает как раньше.
- Внешний вид модалок не меняется, референс для Claude Design не перегенерируется.

## Risks & Dependencies

- **Esc под модалкой.** Лента редактора и поле имени реагируют на Esc. Де-риск: KTD-2 глушит событие и тест U1 это проверяет; смоук — Esc в `save` поверх редактора с выделением не сжимает выделение.

## Acceptance Examples

- AE1. «Сохранить» → Esc: модалка закрылась, ничего не записано.
- AE2. «+ Добавить» → Esc: закрылась, сканирование не началось.
- AE3. Подключение сканера: ввести адрес → Esc: модалка закрылась.
- AE4. «Вернуть» → Esc: правки на месте.
- AE5. Несовпадение набора: Esc ничего не делает.
