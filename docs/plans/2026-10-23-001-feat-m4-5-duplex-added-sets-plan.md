# feat: Двусторонние добавленные наборы — пара проходов по якорю (M4.5)

## Goal Capsule

- **Objective:** к готовому документу добавляются двусторонние листы за один цикл: «Добавить» →
  «Двустороннее сканирование» → лица → разворот → обороты → редактор, где набор стоит одним
  блоком «ДN» по якорю с лицами и оборотами в правильном порядке; несовпадение внутри набора не
  теряет страниц и предлагает переснять; ничего не выбрасывается молча.
- **Means:** журнал v7 с ролями «лица набора» / «обороты набора», ссылкой пары и решением по
  оборотам на наборе (амендмент ADR 0004 от 2026-10-23); политика ролей в одном месте
  (`nextKindOf` / `planPass`); чередование внутри блока набора в `placeAdded`; флаг 180° на проходе
  оборотов каждой пары с адресной командой; детектор пустых по роли «обороты» любой пачки; те же
  экраны `scan` / `flip` / `merge` с акцентом добавленного набора; модалка несовпадения набора.
- **Product authority:** брейншторм (origin), роадмап M4.5, бэклог B-2, спека «Добавление к
  документу», UI_SPEC §7.2 и мок (карточка «Двусторонняя пачка»), ADR 0004 (амендменты
  2026-10-07, 2026-10-22, 2026-10-23); решения автора при планировании 2026-10-23 (Problem
  Frame).
- **Stop conditions:** страницы оборотов набора удалены без явного действия; второй порядок
  страниц рядом с автопорядком; свои экраны для набора вместо общих; режим раздельных наборов
  внутри пары; тумблер 180°, крутящий все обороты сессии разом; детектор на лицах или
  односторонних наборах; «Список наборов».

---

## Summary

«+ Добавить» получает карточки «Одностороннее сканирование» и «Двустороннее сканирование».
Двустороннее — пара проходов: ядро ведёт её само по той же очереди ролей, что и основную пачку, с
экранами `scan`, `flip` и `merge` в акценте добавленного набора. Сборка кладёт блок набора по якорю
с чередованием лиц и оборотов; при несовпадении — двумя подблоками, а модалка предлагает переснять
обороты набора или оставить как есть. Тумблер 180° в подвале крутит обороты пачки текущей страницы.
Детектор пустых оборотов оценивает обороты набора по режиму сессии. Журнал поднимается до v7.

---

## Problem Frame

Две карточки «Добавить» сканируют одно и то же — лицо (M3.5, KTD-5); оборот к готовому документу
добавляется отдельным набором с ручным разворотом и расстановкой. Пары, `flip`, тумблер 180°,
несовпадение и детектор завязаны на единственные роли `fronts` / `backs` сессии; добавленные
проходы ставятся односторонними блоками и из всего этого исключены (origin, Problem Frame).

Вопросы origin'а сняты при планировании 2026-10-23 (ответы автора):

- форма пары в журнале — новые роли `addedFronts` / `addedBacks` со ссылкой `pair` и решением
  `backsDecision` на проходе лиц набора → амендмент ADR 0004 (KTD1);
- показ модалки несовпадения набора после перезапуска — «Оставить как есть» durable на наборе
  (KTD1, ADR);
- «Переснять обороты набора» — отброс прохода оборотов по явному действию, не пометка (KTD1, ADR);
- сканер сменился между проходами пары — обороты набора идут на текущем сканере с текущими
  параметрами, как у основной пачки; origin R10 сужен до досканирования прерванного прохода;
- принятие коротких оборотов набора плашкой = «Оставить как есть», модалка не показывается;
- скрытие пустых оборотов действует и в подблоках несовпавшего набора;
- кнопки «Убрать набор» на `flip` набора нет — до «Списка наборов».

## Requirements

**Модалка «Добавить»**

- R1. Две карточки-радио: «Одностороннее сканирование» (один или несколько листов, обороты не
  сканируем) и «Двустороннее сканирование» (два прохода с разворотом на 180°, как основной
  документ); по умолчанию выбрана двусторонняя, если доступна, иначе односторонняя; выключенная
  карточка не выбирается и не влияет на сводку и «Начать скан»; карточек «Односторонние листы» /
  «Один лист» и подсказки о ручном обороте нет. (origin R1)
- R2. Места вставки и сводка подвала — без изменений; сводка называет сценарий. (origin R2)
- R3. В режиме раздельных наборов карточка «Двустороннее сканирование» неактивна с подписью
  «сначала соберите документ»; одностороннее — как в M3.5. В режиме «собрано» двустороннее
  доступно. (origin R3)
- R4. «Начать скан» двустороннего — одно намерение; ядро само назначает второй проход набора при
  следующем запуске без намерения. Число листов приложение не спрашивает. (origin R4)

**Пара проходов**

- R5. Лица набора — `scan` с акцентом набора, счётчик без общего числа; «Остановить» на первом
  сегменте отбрасывает набор (до первой страницы и после — отмена отбрасывает полученное, спека),
  при досканировании — только досканированное, набор остаётся прерванным; обрыв после первой
  страницы — прерванный проход с досканированием в тот же проход (плашка редактора), набор до
  оборотов показан односторонним блоком. (origin R5; уточнено при U8 — решение автора
  2026-10-24)
- R6. После завершённых или принятых лиц набора — `flip` для набора: ожидаемое число = страницы
  лиц набора, тексты и проверки основной пачки, акцент набора; «Обороты не нужны» —
  `backsDecision: declined`, набор остаётся односторонним, `flip` больше не показывается.
  (origin R6)
- R7. Обороты набора — `scan` с ожидаемым числом; «Остановить» и обрыв: при нуле страниц проход
  снимается и экран возвращается на `flip` набора; при ≥1 странице — прерванный проход с
  досканированием, плашка и действия те же, что у прерванных оборотов основной пачки; при
  досканировании «Остановить» отбрасывает только досканированное. (origin R7; «Остановить» после
  первой страницы оставляет полученное — решение автора на приёмке 2026-10-24)
- R8. Перезапуск между лицами и оборотами набора открывает `flip` для набора; перезапуск во время
  лиц или оборотов набора — редактор с плашкой прерванного прохода; во время паузы `merge` —
  редактор, поздние оценки тостом. (origin R8, R20)
- R9. После завершённых или принятых оборотов набора и после отказа от них — пауза `merge` с
  ожиданием незавершённых оценок сессии; затем редактор, тост «добавлено N» по показанной ленте
  (скрытые названы отдельно), посадка на первую показанную страницу набора; один тост на пару.
  (origin R9)
- R10. Обороты набора — новый проход на текущем сканере с текущими параметрами, как обороты
  основной пачки; досканирование прерванного прохода набора — только на сканере прохода
  (KTD-27 M3.5). (origin R10, сужено)
- R11. Запуск без намерения при ожидающей паре начинает её обороты; при прерванном последнем
  проходе — досканирование; иначе очередь M2 (`fronts` → `backs` → отказ). (origin R4)

**Сборка и лента**

- R12. При равном числе страниц блок набора — чередование: оборот листа _i_ набора — страница
  _F−1−i_ прохода оборотов набора; блок встаёт по якорю прохода лиц по правилу вставки M3.5 в
  режимах пары и «собрано» (в режиме наборов добавляются только односторонние — R3);
  досканированный сегмент любого прохода пары попадает в чередование автопорядка. При ручном
  порядке страницы оборотов набора встают в подблок оборотов за соседом по проходу:
  `settled`-проекция идущего или короткого прохода оборотов набора — всегда подблоки, как у
  оборотов основной пачки (M3.6, ревью #1); чередование действует только в автопорядке. (origin
  R11)
- R13. Страницы пары: тег «ДN» на обеих сторонах, сторона и лист внутри набора в подписях, превью и
  «Деталях»; нумерация «ДN» — по наборам (пара = один номер), в порядке номера прохода лиц. (origin
  R12)
- R14. При неравном числе страниц (прерванные, принятые или завершённые обороты набора) блок —
  подблок лиц в порядке сканирования, затем подблок оборотов в порядке документа (обратном подаче);
  тег «ДN», сторона есть, номер листа не присваивается; правки, разрезы и сохранение обычные.
  (origin R13)
- R15. При первом входе в редактор после завершённых оборотов набора с неравным числом и
  `backsDecision: none` — модалка «Обороты набора не сошлись: N лиц, M оборотов» с действиями
  «Переснять обороты набора» (отброс прохода оборотов, затем `flip` набора) и «Оставить как есть»
  (`backsDecision: kept`). Модалка закрывается только одним из двух действий: Esc и клик по
  подложке её не закрывают (как `mismatch` M3.6). Показывается при первом входе в редактор за
  процесс, пока `backsDecision: none` и числа не равны — в том числе после перезапуска без
  решения. Принятые плашкой короткие обороты набора ставят `kept` без модалки. Повторное
  несовпадение после пересъёмки — модалка снова. (origin R14)
- R16. Тумблер 180° крутит обороты пачки текущей страницы (основная или набор «ДN»), подпись
  называет пачку; при текущей на пачке без оборотов — недоступен с причиной; скрыт, только если
  оборотов нет ни у одной пачки. Флаг — на проходе оборотов этой пачки; переключение — шаг undo,
  как сегодня. (origin R15)
- R17. Детектор оценивает обороты набора по режиму сессии, включая подблоки несовпавшего набора;
  «Это не пустая страница» и «добавить пустые» работают для них; лица и односторонние наборы оценок
  не получают. (origin R16)
- R18. Якорь «После текущей» со скрытым хвостом пустых оборотов любой пачки ставит набор после
  хвоста. (origin R17)
- R19. Одностороннее сканирование — поведение M3.5 без изменений. (origin R18)
- R20. Сохранение при прерванных или несовпавших оборотах набора не блокируется: в PDF идут
  подблоки; при идущем проходе — отказ как сегодня.

**Журнал, сверка, эмулятор**

- R21. Журнал v7 по амендменту ADR 0004 от 2026-10-23: роли `addedFronts` / `addedBacks`, поля
  `pair` и `backsDecision`; чтение v1–v6 цепочкой дефолтов, сверка переписывает файл; v8+ —
  несовместимость. (origin R19)
- R22. Сверка при запуске восстанавливает пару из фактов журнала идемпотентно; усыновлённые по
  файлам проходы получают `added` с `after: null`; обороты набора с пропавшим проходом лиц — в конец
  ленты стороной «оборот», плашка `pagesLost`. (origin R20)
- R23. Эмулятор: сценарии пары — совпадение, несовпадение с «Переснять» и «Оставить», обрыв
  оборотов набора с досканированием, перезапуск между проходами пары, отказ от оборотов набора,
  «Остановить» на лицах набора до первой страницы. (origin R21)

## Key Technical Decisions

- **KTD1. Форма журнала v7 — амендмент ADR 0004 от 2026-10-23.** Роли `addedFronts` /
  `addedBacks` (новые элементы `PASS_KINDS`), `pair: number | null` у оборотов набора,
  `backsDecision: 'none' | 'declined' | 'kept' | null` у лиц набора; `after` — у `added` и
  `addedFronts`; zod-`refine` на согласованность полей с ролью. «Набор ждёт обороты» выводится из
  фактов (лица со страницами, завершённые или принятые, `none`, без оборотов со страницами) и не
  хранится. _Отклонено:_ поле пары при роли `added` (компилятор не ловит пропущенные места);
  подтверждение модалки за процесс; пометка «заменён» вместо отброса прохода. Подробности — ADR.
- **KTD2. Политика ролей остаётся в одном месте: `nextKindOf` + `planPass` + `passesByKind`.**
  `passesByKind` возвращает дополнительно `addedFronts: T[]` и `addedBacks: T[]`; новый помощник
  `addedSetsOf(passes)` в `src/shared/snapshot.ts` собирает наборы по порядку номера прохода лиц:
  `{ set, fronts, backs, decision, sides }`, где `set` — номер «ДN» (с единицы, по порядку номера
  прохода лиц), `fronts` — номер прохода лиц, `backs` — номер прохода оборотов или `null`,
  `sides: 'one' | 'two'` — одна нумерация и один идентификатор набора для ядра, моста и renderer.
  `nextKindOf(journal)` остаётся `PassKind` (`fronts` → `backs` → `addedBacks` при ожидающей паре →
  `added`); `pendingPairOf(journal)` рядом с ним в `journal.ts` даёт `pair` и `expected`.
  `planPass(null)`: resumable последний → ожидающая пара → очередь. Намерение модалки:
  `AddedPassIntent.kind: 'added' | 'addedFronts'`. Ветки `planPass`, `checkIntent`, `resumable`
  выносятся в `src/core/storage/pass-policy.ts` (импортирует `nextKindOf` и `pendingPairOf`) —
  `session-store.ts` на границе R21. _Отклонено:_ вторая очередь ролей в службе проходов.
- **KTD3. Команды решения набора — адресные, с проверкой ядра.** `declineBacks()` без аргумента
  адресуется ожидающей паре, если она есть, иначе сессии (экран `flip` один, команда одна —
  KTD-4 M2); `keepSetBacks({ set })` пишет `kept`; `rescanSetBacks({ set })` отбрасывает проход
  оборотов набора (запись журнала → удаление файлов → чистка `derived` и правок по мёртвым ключам,
  как `prune` M4) и отвечает снимком, после которого `screenOf` даёт `flip` набора; `acceptPass`
  прерванных оборотов набора с неравным числом ставит `kept`. Конфликты: `noPendingSet`,
  `setNotMismatched`, `pairInSets` (двустороннее недоступно в режиме раздельных наборов — R3,
  ядро отказывает и без UI), `passRunning`, `saving`. Вход валидируется схемой: `set` — номер «ДN»,
  ядро находит проходы через `addedSetsOf` и отвечает `noPendingSet`, если такого набора нет.
  _Отклонено:_ «Переснять» как новый проход с пометкой прежнего — третье состояние без
  потребителя (ADR).
- **KTD4. Флаг 180° — карта по проходам внутри одного `setEdits`.** Второй аргумент `setEdits`
  становится `rotate180: Record<number, boolean>` (номер прохода оборотов → флаг); ядро принимает
  только проходы ролей `backs` и `addedBacks`, иначе `noBacksPass`, и пишет флаг на проход.
  История редактора держит `rotate180: ReadonlyMap<number, boolean>`, `REVERTED` — пустая карта;
  тумблер, Ctrl+Z и «Вернуть» остаются одним `setEdits` и одним `seq`, как сегодня. Сборка кладёт
  флаг на страницы его прохода (`BasePage.rotate180` вместо `base.rotateBacks`). Подвал: цель
  тумблера — проход оборотов пачки текущей страницы (`AddedSet.backs` или `backs` сессии),
  `origins` редактора расширяются до карты `ключ → { pass, kind }`. _Отклонено:_ отдельная команда
  `setRotate180({ pass, on })` — «Вернуть» и undo поверх него требовали бы нескольких команд,
  записей и снимков с видимым промежуточным состоянием (ревью плана).
- **KTD5. Чередование набора — в `placeAdded`, одна точка для трёх режимов.** Блок пары при
  равном числе страниц — interleave (оборот _i_ = `backs[F−1−i]`), иначе два подблока; страницы
  оборотов набора — `side: 'back'`, `ofBacks: true` (флаги детектора), `sheet` — номер листа внутри
  набора при чередовании, `null` в подблоках; `addedSetOf` нумерует по `addedSetsOf`. В режиме
  «собрано» пара вне записи встаёт блоком по якорю, не по одной странице. `AssemblyReport.sets:
AddedSetReport[]` (`set`, `fronts`, `backs`, `backsState`, `decision`, `mismatch`, `sides`) и
  `report.pendingSet: number | null` — для `flip`, `merge`, модалки и тумблера. Зеркало
  `assembly-fixture.ts` и guard-таблица — в том же юните, с правками (урок M3.6 #8). _Отклонено:_
  мини-режим наборов для пары (origin).
- **KTD6. Детектор — по роли «обороты» любой пачки.** `pagesToScore` и `detectsBlank` принимают
  `backs` и `addedBacks`; порог не трогаем. Пауза `merge` ждёт все незавершённые оценки сессии
  (`assembly.blank.pending`), как сегодня; в подблоках несовпавшего набора `hide` скрывает (сборки
  впереди нет). _Отклонено:_ ждать только оценки набора — второй счётчик без выигрыша.
- **KTD7. Экраны — предикаты от снимка, без своих экранов.** `flipForm`: ожидающая пара
  (`report.pendingSet !== null`) → `flip` с приоритетом над `editor`; основная пара — как раньше.
  `flipBusy`: `kind ∈ {backs, addedBacks}`. `report.pendingSet` — номер «ДN»; `FlipScreen` берёт
  число из `report.sets.find((it) => it.set === pendingSet)` или `report.fronts`. Пауза `merge` и
  посадка в `App` выводятся из «пара набора завершена / принята / отказ» по снимку + `Launch`
  (урок M3.5 ревью 3: не из «последнего прохода»); дедуп — по `session.id + set`. N тоста и ключ
  посадки — по показанной ленте снимка: страницы `assembly.order` с `addedSet === set` (скрытые —
  по флагу `blank` среди них), посадка — первая из них; `fresh`/`keysBefore` для пары не
  используются. Модалка несовпадения набора — `modals/SetMismatchModal.tsx`, предикат
  `setMismatchDue(report)` в `assembly-outcome.ts`: набор с завершёнными оборотами, неравным
  числом и `decision: none`; показ — первый вход в редактор за процесс, ключ подтверждения
  `session.id + set`; закрытие — только действиями. Тост при несовпадении — после закрытия
  модалки; числа модалки — по страницам проходов, не по показанной ленте. _Отклонено:_ отдельный
  поток экранов набора (origin).
- **KTD8. Handoff состояний до renderer — утверждение автора как гейт.**
  `docs/design/handoffs/2026-10-m4-5-states.md` по шаблону: две карточки `add` и выключенная
  карточка; `scan` оборотов набора (тег «ДОБАВЛЯЕМ · ОБОРОТЫ», счётчик «из N»); `flip` набора
  (кикер с числом листов набора, акцент); `merge` набора (строки лиц/оборотов набора); модалка
  несовпадения набора; подпись тумблера («обороты основного документа» / «обороты набора Д2»);
  теги оборота набора («Д1» + «об» или один тег — решает handoff, без умножения расхождения цветов
  `pass-2/3`); тост с скрытыми. Слова «пачка» и «стопка» в UI запрещены.

## High-Level Technical Design

Очередь ролей и экраны (политика — ядро; экран — чистая функция от снимка):

```mermaid
stateDiagram-v2
  [*] --> setup
  setup --> scan_fronts: startPass(null) → fronts
  scan_fronts --> flip_main: completed | accepted
  flip_main --> scan_backs: startPass(null) → backs
  flip_main --> editor: declineBacks → session.backsDeclined
  scan_backs --> merge --> editor
  editor --> scan_set_fronts: startPass({kind: addedFronts, after})
  editor --> scan_added: startPass({kind: added, after}) → editor
  scan_set_fronts --> flip_set: completed | accepted (pendingSet)
  scan_set_fronts --> editor: interrupted ≥1 стр. (плашка) | 0 стр. (набор отброшен)
  flip_set --> scan_set_backs: startPass(null) → addedBacks{pair, expected}
  flip_set --> merge: declineBacks → backsDecision declined
  scan_set_backs --> merge: completed | accepted
  scan_set_backs --> flip_set: 0 стр. (проход снят)
  scan_set_backs --> editor: interrupted ≥1 стр. (плашка, подблоки)
  merge --> editor: blank.pending = 0
  editor --> set_mismatch: первый вход, backs ≠ fronts, decision none
  set_mismatch --> flip_set: rescanSetBacks (отброс прохода)
  set_mismatch --> editor: keepSetBacks → kept
```

Данные пары (журнал → сборка → снимок):

```text
journal.passes
  #3 addedFronts { after: p01…07, backsDecision: none }
  #4 addedBacks  { pair: 3, rotate180: false }
        │ passesByKind / addedSetsOf
        ▼
AddedSet { set: 1, fronts: #3, backs: #4, decision: none, sides: 'two' }
        │ placeAdded: якорь #3.after → блок [f1, b1, f2, b2, …] | [f1 f2 f3 | b1 b2]
        ▼
SessionAssembly.order (AssembledPage: addedSet 1, side, sheet, blank, angle по rotate180 прохода)
SessionAssembly.report.sets[0] / report.pendingSet → screenOf, FlipScreen, MergeScreen, модалка, тумблер
```

Команды моста (новые и изменённые): `startPass(AddedPassIntent{kind: 'added' | 'addedFronts',
after})`, `declineBacks()` (адресация в ядре), `keepSetBacks({set})`, `rescanSetBacks({set})`,
`setEdits(edits, rotate180: Record<number, boolean>)`.

## Risks & Dependencies

  на страницы оборотов набора никто не ссылается (ADR).

  `pass-service.ts` 959, `pass-service.test.ts` 1084, `reconcile.test.ts` 1182) → выносы
  (`pass-policy.ts`, хуки) и новые тестовые файлы названы в юнитах.

  набора с таймаутом 20 с, смоук не параллельно с `test:all`, текст ошибки сохранять.
- **Физика набора не проверена на железе** — обороты набора после разворота приходят в правильной
