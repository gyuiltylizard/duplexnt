# feat: quick wins B-16–B-18 (B-16, B-17, B-18)

## Summary

Три карточки «Quick wins» бэклога одной веткой `feat/b-16-18-quick-wins`: склейка уведомлений о
снимке в renderer (B-16), шесть мелких UX-дыр из ревью M1–M6 (B-17) и оценки пустоты в общем
`settleDerived`, чтобы после «Нового сканирования» не оставался пустой каталог производного
(B-18). Вход —
карточки бэклога, сверенные с кодом 2026-10-30 (разбор «Входящих», коммит `b28ef32`). Без моков,
без решений автора, без правок дизайн-системы. Прецедент формы — план B-3.

## Problem Frame

- **B-16.** На страницу прохода приходится 3–5 `notify()` (приём, вердикт пустоты, вердикт
  перекоса, исход коррекции, смены фазы). `notify` в `pass-service.ts` синхронный, main шлёт
  `snapshotChanged {seq}` на каждое, `snapshot-store.ts` на каждое событие зовёт `refresh()` →
  `getSnapshot()` с полной сборкой (`assembleSession` + факты выравнивания) и structured clone по
  IPC. Единственный гард — `apply` отбрасывает ответ с `seq` не новее текущего, но уже после
  того, как main его собрал.
- **B-17.** Шесть мест, где пользователь не получает отклика или получает неверный текст:
  1. отказ «Остановить» с любым кодом, кроме `sessionCloseFailed`, молчит (`App.tsx`,
     `stopPass`);
  2. тост «Сканер подключён: …» после ручного ввода называет введённый адрес
     (`DeviceModal.tsx`, `label = trimmed`), а не имя сканера;
  3. порт больше 65535 проходит фильтр из пяти цифр, main отвечает `invalidInput`, renderer
     показывает общий `device.address.invalid` про хост;
  4. сбой `getSaveFolder` оставляет поле папки пустым без объяснения (`SaveModal.tsx`,
     `folder` остаётся `null`), пока пользователь не нажмёт «Выбрать…»;
  5. «Это не пустая страница» гасится только `saving || assembling`; при команде правки в
     полёте `edits.edit` возвращает `false`, второй клик глотается (`EditorInspector.tsx`,
     `EditorScreen.tsx` `markNotBlank`); действия выравнивания `edits.busy` уже учитывают;
  6. документ из одних скрытых между показанными: `shownDocumentsOf` даёт ему `count: 0`,
     лента его не рисует, но тулбар «документ N из M» считает (`EditorToolbar.tsx`,
     `documents.length`), а «✕» на следующем разделителе снимает разрез перед невидимым
     документом и сливает группу с ним, а не с видимым соседом (`unsplit` → `withoutCut`).
- **B-18.** `closeDirectory` ждёт `settleDerived` (перекос и коррекция) и сносит
  `derived/<id>`; оценка пустоты в полёте после этого создаёт `derived/<id>/blank` заново
  (`blank-scores.ts`, `mkdir` перед записью кэша), а проверка `alive` удаляет только файл.
  Каталог живёт до следующего запуска (`dropForeignCaches`). До `closeDirectory` доходит
  «Новое сканирование» (`closeSession`) и «Остановить» лишь когда страниц не остаётся; оценки
  пустоты идут только по проходам оборотов, то есть при живых лицах — значит, сценарий дыры —
  «Новое сканирование» во время оценок, а не «Остановить» (при остановке оборотов каталог
  сессии остаётся законно, в нём миниатюры живых лиц).

Развилки, снятые при планировании (подтверждены автором 2026-10-30): склейка — на стороне
renderer'а; «✕» рядом с невидимым документом сливает с ближайшим видимым (снимает оба разреза),
а не прячется — иначе невидимый разрез нельзя убрать, не показав «Пустые».

## Requirements

**B-16 — снимок**

- R1. Пока запрос снимка в полёте, новые события моста не порождают новых запросов: после
  ответа делается ровно один повтор, если за это время приходило хоть одно событие.
- R2. Порядок применения не меняется: устаревший ответ (`seq` не новее) отбрасывается, как
  сейчас; последний снимок всегда доезжает до экрана.
- R3. Эффект измерен на эмуляторном проходе в 50 листов: число вызовов `getSnapshot` до и
  после — в журнале решения.

**B-17 — мелкие UX-дыры**

- R4. Любой отказ «Остановить» показывается тостом: `sessionCloseFailed` — прежний текст,
  остальные коды — `toast.stopFailed` «Не удалось остановить: {{error}}» с причиной из
  `errorTextInline` (в тесте — и `storageFailed`, и `sessionConflict`).
- R5. Тост после подключения называет имя сканера из ответа ядра; имени нет — адрес, как
  сейчас.
- R6. Порт вне 1–65535 в «Дополнительно» получает свой текст `device.address.invalidPort`
  «Порт должен быть от 1 до 65535» до отправки команды — в строке статуса модалки цветом
  `--color-danger`, там же и так же, как прежний `device.address.invalid`, не тостом; фильтр
  ввода остаётся.
- R7. Если папка сохранения не прочиталась (единственный путь — исключение IPC: ядро отвечает
  `ok` всегда, откатываясь на папку по умолчанию), модалка показывает подсказку в строке
  статуса «Папка не прочиталась — запись пойдёт в папку по умолчанию; „Выбрать…“ покажет
  путь» и не блокирует запись: папку знает ядро. Повторного автоопроса нет; отмена диалога
  «Выбрать…» оставляет подсказку. Штатный путь не меняется.
- R8. «Это не пустая страница» недоступна и при команде правки в полёте (`edits.busy`), как
  действия выравнивания; без отдельной подсказки — состояние мгновенное. Гасится только эта
  кнопка: общий `locked` инспектора (секция выравнивания, «Вернуть») не меняется.
- R9. Документ из одних скрытых не считается в «документ N из M» — и M, и N считаются по
  видимым; при M = 0 остаётся нынешнее состояние «Все страницы скрыты» (UI_SPEC). «✕» на
  разделителе, перед которым стоит такой документ, сливает текущий документ с ближайшим
  видимым слева одной правкой (Ctrl+Z отменяет целиком), снимая все разрезы между ними; имя
  итогового документа — имя левого видимого, имена снятых границ уходят (правило R12 M3);
  скрытые страницы невидимого документа становятся частью слитого — ничего не теряется и не
  выбрасывается. Если видимого документа слева нет (первый документ ленты — из одних скрытых),
  «✕» на разделителе не показывается: осознанное ограничение, такой разрез снимается при
  показанных «Пустых».

**B-18 — оценки пустоты**

- R10. `settleDerived` отменяет и дожидается оценки пустоты наравне с перекосом и коррекцией:
  после закрытия каталога сессии `derived/<id>` не появляется заново.
- R11. Отменённая оценка не пишет кэш и не ставит вердикт; при следующем открытии сессии
  страница оценивается заново (поведение `alive` сохраняется).

## Key Technical Decisions

- **KTD-1. Склейка в renderer, не в main.** `snapshot-store.ts` — единственная точка, где ходят
  за снимком; флаг «в полёте» + «dirty» и один повтор закрывают все источники событий разом, не
  трогая `notify` и очереди ядра. _Отклонено:_ один `send` на макрозадачу в main — склеивает
  только события, но не защищает от второго `getSnapshot`, если renderer сам перечитывает
  (StrictMode, повторная подписка).
- **KTD-2. Проверка порта — в renderer до команды.** Схема main (`z.number().max(65535)`)
  остаётся стражем входа, но текст про порт пользователь получает локально: не нужно
  протаскивать `field` из ошибки схемы через мост. _Отклонено:_ разбор `details.field` ответа —
  у ошибки схемы поля нет, у `parseScannerAddress` есть; два пути ради одного текста.
- **KTD-3. Имя сканера — из ответа команды `connectScanner`.** Сейчас команда отвечает
  `ok(undefined)` (`bridge.ts`: `value: undefined`; обработчик идёт через обёртку `done`).
  Ответ становится `ScannerInfo` через `scannerInfoOf(storedScannerOf(connected))` (паттерн
  `resumeTarget` в `pass-service.ts`), обработчик — мимо `done`. Снимок в момент тоста может
  быть ещё прежним, поэтому читать имя из него нельзя. _Отклонено:_ ждать следующего снимка
  в App — лишняя машина состояний ради тоста.
- **KTD-4. Сброс оценок пустоты — тот же контракт, что у перекоса:** `abort()` + `settle()` у
  `BlankScores`, `settleDerived` зовёт их параллельно с `skew` и очередью коррекции. Отмена
  проверяется до `mkdir` и до записи кэша; поведение `alive` после записи сохраняется. Парный
  шаг — **возобновление:** на путях, где каталог сессии остаётся (`sessionCloseFailed`,
  `stopPass` с оставшимися страницами), `resumeDerived` сегодня перезапускает только
  `measurePending()` и очередь коррекции; оценки пустоты он тоже должен перезапустить
  (`detectBlank` для `pagesToScore(...)`, идемпотентно), иначе страницы останутся `pending` до
  перезапуска, `blankPending` заблокирует сохранение, а `measurePending` замрёт, потому что
  ждёт вердиктов пустоты.
  _Отклонено:_ удалять каталог повторно после `settleReads` — лечит симптом, оценка в полёте
  всё равно может пережить удаление.
- **KTD-5. «✕» рядом с невидимым документом.** Цель слияния — ближайший видимый документ
  слева; снимаются все разрезы между ним и текущим одной командой правок — существующим
  `withoutCut` по убыванию индекса, без новой функции. Решение автора 2026-10-30 (карточка
  B-17 говорила «не сливать» — при закрытии отметить в бэклоге); счётчик тулбара — по документам
  с `count > 0`.

## High-Level Technical Design

- `src/renderer/src/state/snapshot-store.ts` — `refresh()` становится машинкой из двух флагов:
  `inFlight`, `dirty`; событие при `inFlight` ставит `dirty`, завершение запроса при `dirty`
  делает один повтор. Снаружи контракт `SnapshotStore` не меняется.
- `src/renderer/src/App.tsx` — `stopPass`: ветка общего отказа; `deviceConnected` получает имя.
  `src/renderer/src/modals/DeviceModal.tsx` — локальная проверка порта и ключ локали; имя из
  ответа команды. `src/core/commands/handlers.ts` + `src/shared/bridge.ts` — ответ
  `connectScanner`, если сейчас без значения.
- `src/renderer/src/modals/SaveModal.tsx` — состояние «папка неизвестна» с подсказкой; кнопка
  записи гасится, пока папки нет.
- `src/renderer/src/screens/EditorScreen.tsx` — отдельный признак для кнопки инспектора
  (`locked || edits.busy`), `EditorInspector.tsx` принимает его пропсом; `unsplit` считает цель
  слияния по `shownDocuments`; `EditorRail.tsx` — «✕» разделителя показывается только при
  видимом документе слева; `src/renderer/src/screens/EditorToolbar.tsx` — N и M по видимым;
  `src/renderer/src/state/shown.ts` — хелпер «ближайший видимый документ слева».
- `src/core/storage/blank-scores.ts` — `abort()` / `settle()` (контроллер + множество
  незавершённых оценок), `src/core/scan/pass-service.ts` — `settleDerived` и `resumeDerived`.

## Implementation Units

### U1. Склейка запросов снимка (B-16)

- **Что:** R1–R2 — флаги «в полёте» / «dirty» в `refresh()`, один повтор после ответа; поведение
  при ошибке запроса — повтор тоже один, если был `dirty`.
- **Файлы:** `src/renderer/src/state/snapshot-store.ts`,
  `src/renderer/src/state/snapshot-store.test.ts`.
- **Тесты:** пять событий во время одного запроса → ровно два `getSnapshot`; событие без
  запроса в полёте → один запрос; ответ с устаревшим `seq` после повтора отбрасывается;
  отказ запроса при `dirty` → один повтор; отписка последнего подписчика во время полёта не
  даёт повтора после переподписки сверх штатного `refresh()`; StrictMode-цикл (подписка →
  отписка → подписка) — как сейчас.
- **Гейт:** typecheck + lint + test зелёные; коммит `feat(b-16): U1 …`.

### U2. Замер коалесинга (B-16)

  счётчик вызовов в `src/preload/api.ts` (не коммитится), замер на `main` и на ветке в одном

  видимом документе слева, `unsplit` с разделителя находит ближайший видимый документ слева
  (хелпер в `shown.ts`) и снимает все разрезы между ним и текущим одной правкой —
  существующим `withoutCut` по убыванию индекса.
- **Файлы:** `src/renderer/src/screens/EditorScreen.tsx`,
  `src/renderer/src/screens/EditorInspector.tsx`, `src/renderer/src/screens/EditorRail.tsx`,
  `src/renderer/src/screens/EditorToolbar.tsx`, `src/renderer/src/state/shown.ts`,

- **Тесты:** кнопка «Это не пустая страница» выключена, пока команда правки в полёте, включена

  «✕» на разделителе третьего → в правках нет ни одного из двух разрезов, имя документа — имя

  соседях — как сейчас (один разрез); первый документ скрытый-только → «✕» у следующего
  разделителя не показывается; все документы скрытые-только → состояние «Все страницы скрыты»
  без «документ N из M».
- **Гейт:** typecheck + lint + test зелёные; коммит `feat(b-17): U5 …`.

### U6. Оценки пустоты в `settleDerived` (B-18)

- **Что:** R10–R11 — `BlankScores.abort()` / `settle()`: контроллер отмены, множество
  незавершённых `detect`; отмена проверяется после чтения страницы и после детектора — до
  `mkdir` и записи кэша (проверка до `source.readPage` — по месту: чтение страницы закрытой
  сессии и так отвечает отказом); `pass-service.settleDerived` зовёт их вместе со `skew` и
  очередью; `resumeDerived` перезапускает `detectBlank` для `pagesToScore(store.snapshot())`
  (KTD-4). Заглушек `BlankScores` в тестах нет — везде настоящий `createBlankScores`.
- **Файлы:** `src/core/storage/blank-scores.ts`, `test/integration/blank-scores.test.ts`,
  `src/core/scan/pass-service.ts`, `test/integration/blank-backs.emulator.test.ts`.
- **Тесты (ядро):** `abort()` во время детектора → кэш не записан, вердикта нет, `settle()`
  разрешается; `abort()` без оценок → `settle()` сразу; после `abort()` новая `ensure`
  оценивает заново. **Интеграция:** «Новое сканирование» (`closeSession`) во время оценок с
  медленным детектором (`counting(delayMs)`) → после ответа команды каталога `derived/<id>`
  закрытой сессии нет и он не появляется после `settle`; `closeSession` с `sessionCloseFailed`

  `blank.pending` возвращается к 0, сохранение не заблокировано; ранее записанные вердикты другой
  сессии не задеты.
- **Гейт:** typecheck + lint + test зелёные; коммит `feat(b-18): U6 …`.

## System-Wide Impact

- Ответ `connectScanner` меняет тип через мост (`bridge.ts`); preload — прямой
  `ipcRenderer.invoke`, валидации ответа в renderer нет, обратная совместимость не нужна (один
  процесс).
- Новые ключи локали: `toast.stopFailed` «Не удалось остановить: {{error}}»,
  `device.address.invalidPort` «Порт должен быть от 1 до 65535», подсказка папки «Папка не
  прочиталась — запись пойдёт в папку по умолчанию; „Выбрать…“ покажет путь». Тексты — в
  рамках существующих паттернов тостов и строк статуса, нового UI (мока) не требуют.
- `BlankScores` получает два метода; заглушек в тестах нет. `settle()` оценок ждёт и задачи в
  общем лимитере производного — закрытие каталога при длинной очереди миниатюр задержится (как
  уже с `skew`); отметить в журнале.

## Risks & Dependencies

- Склейка может задержать первый кадр после события на один круг запроса — проверяется тестом
  R2 и на глаз в смоуке (лента `scan` идёт без рывков).
- Отмена оценки пустоты в момент записи кэша: защищает существующий `alive` + `unlink`; новая
  проверка стоит до `mkdir`, окно между ними покрывается интеграционным тестом с задержкой.
- `withoutCut` по нескольким индексам: индексы разрезов сдвигаются после каждого снятия —
  снимать по убыванию; покрыто тестом `EditorScreen.blank.test.tsx` (оба разреза сняты).
- Коалесинг и StrictMode: повторная подписка делает штатный `refresh()`; флаг «в полёте» не
  должен его проглотить — покрыто тестом U1.

## Acceptance Examples

- AE1. Проход 50 листов на эмуляторе: вызовов `getSnapshot` заметно меньше, чем событий
