# feat: мелкие доделки UI с приёмок M3 и M3.5 (B-3)

## Summary

Четыре замечания автора со смоук-приёмок M3 (2026-10-06) и M3.5 (2026-10-09), которым не нужен
новый мок: тексты экранов без номеров проходов, кнопка «Новое сканирование» в редакторе,
кегль split-бара и запоминание размера и положения окна. Вход — карточка B-3 бэклога и
согласованные с автором формулировки (2026-10-26). Правки в рамках DESIGN_SYSTEM, без handoff'а.

## Problem Frame

- Тег экрана `scan` — «ПРОХОД 1 · ЛИЦЕВЫЕ СТОРОНЫ» / «ПРОХОД 2 · ОБОРОТЫ»: номер прохода
  пользователю ничего не говорит, а после перезапуска оборотов показывает «ПРОХОД 3». То же в
  мете досканирования («досканируем проход 2») и в заголовках модалки `mismatch` («В первом
  проходе 12 листов, во втором — 11»).
- В левой зоне тулбара `editor` (288 px) «↺ Новое сканирование» и «+ Добавить» делят ширину
  поровну (`flex: 1`), по ~110 px на текст; «↺ Новое сканирование» в 13 px шире — текст
  вылезает за рамку кнопки (`white-space: nowrap` у `.btn`).
- Надпись split-бара «+ Новый документ» стоит впритык к краям миниатюры; она уже на самом
  мелком токене шкалы (`--font-size-xxs`, 9.5 px).
- Окно создаётся фиксированным 1100×760 (`src/main/index.ts`): растянутое под редактор окно при
  следующем запуске снова маленькое.

Формулировки согласованы с автором: «СКАНИРУЕМ ЛИЦЕВЫЕ СТОРОНЫ», «СКАНИРУЕМ ОБОРОТЫ»,
«досканируем обороты · до обрыва было N», «Лицевых сторон 12, оборотов — 11». Тексты, где
«проход» стоит без номера (ошибки, подсказки, кикер «НЕ СХОДЯТСЯ ПРОХОДЫ», «Начинаем проход…»),
не трогаются — решение автора.

## Requirements

**Тексты**

- R1. Тег экрана `scan` основной пачки — без номера: «СКАНИРУЕМ ЛИЦЕВЫЕ СТОРОНЫ» / «СКАНИРУЕМ
  ОБОРОТЫ». Теги добавленных наборов («ДОБАВЛЯЕМ …») не меняются.
- R2. Мета досканирования основной пачки — по роли, без номера: «досканируем лицевые стороны» /
  «досканируем обороты · до обрыва было N».
- R3. Заголовки модалки `mismatch` — без порядковых номеров проходов: «Лицевых сторон N,
  оборотов — M» (меньше оборотов) и «Оборотов больше, чем лицевых сторон: M против N» (больше).

**Тулбар и миниатюра**

- R4. «↺ Новое сканирование» и «+ Добавить» помещаются в левую зону тулбара `editor` без выхода
  текста за рамку кнопки.
- R5. Надпись split-бара — на ступень мельче нынешней; ступень заведена токеном в DESIGN_SYSTEM.

**Окно**

- R6. Границы окна и признак «развёрнуто» помнятся между запусками; при развёрнутом окне
  помнятся границы до разворота.
- R7. Если сохранённые границы не попадают ни на один из нынешних мониторов (монитор отключён) —
  окно открывается размером по умолчанию на основном мониторе; признак «развёрнуто» в силе.
- R8. Файл состояния окна пишется атомарно (temp → fsync → rename) с проверкой схемы до и после;
  нечитаемый отодвигается, более новой версии — не переписывается. Его отсутствие или порча
  не мешают запуску.

## Key Technical Decisions

- **KTD-1. Состояние окна — отдельный файл `window.json` в корне данных, не поле настроек.**
  Довод: поле в `settings.json` подняло бы схему настроек до v4, и откат на прежнюю версию
  приложения счёл бы настройки несовместимыми и заморозил их (запомненный сканер, папка) ради
  размеров окна. Отдельный файл версионируется сам и при порче теряет только размер окна.
  _Отклонено:_ поле `window` в настройках v4; `electron-window-state` (новая зависимость ради
  ~60 строк, без атомарной записи).
- **KTD-2. Хранилище — в ядре, расстановка — чистая функция в main.** Чтение и запись — через
  `versioned-file` ядра (те же правила, что у настроек). Проверка «попадает ли на монитор» —
  чистая функция над прямоугольниками рабочих областей, без Electron, под обычным Node (по
  образцу `window-close.ts`).
- **KTD-3. Когда писать:** по событиям конца перемещения и изменения размера (`moved`,
  `resized`), разворота (`maximize`, `unmaximize`) — с задержкой ~0,5 с, и при `close`. Запись
  только при закрытии терялась бы при падении процесса и не успевала бы до выхода.
- **KTD-4. Видимость на мониторе:** окно считается видимым, если полоса заголовка (верх окна)
  пересекается с рабочей областью какого-либо монитора хотя бы на 100×24 px. Размер, больший
  рабочей области, ужимается до неё.
- **KTD-5. Кнопки тулбара — по содержимому.** `flex: 1 1 auto` вместо поровну: длинная
  «Новое сканирование» берёт больше места, чем «+ Добавить»; запасной `text-overflow: ellipsis`
  на случай более длинного текста.
- **KTD-6. Новый токен `--font-size-xxxs` (8.5 px)** — только для split-бара: шкала кеглей идёт
  через DESIGN_SYSTEM (`tokens:sync`), значение не задаётся в CSS напрямую.

## High-Level Technical Design

- `locales/ru/common.json` — ключи `scan.tag*`, `scan.resumeMeta*`, `mismatch.*.title`;
  `ScanScreen.tsx` перестаёт передавать номер прохода в тег и мету основной пачки.
- `editor-screen.css` — левая зона тулбара и `.thumb__split`; токен — в `DESIGN_SYSTEM.md`.
- `src/core/storage/window-state.ts` (новый) — схема v1 `{ version, bounds, maximized }`,
  `openWindowStateStore(dataRoot)`: `get()` и `save(state)` через очередь записи; путь —
  в `layoutOf` (`windowFile`). Экспорт из `@core`.
- `src/main/window-bounds.ts` (новый) — `placeWindow(saved, workAreas, defaults)` и
  `trackWindowState(window, save)` с задержкой; `index.ts` читает состояние до `createWindow`.

## Implementation Units

### U1. Тексты без номеров проходов

- **Что:** R1–R3 — ключи локали, `tagOf` и мета досканирования в `ScanScreen.tsx`, заголовки
  `MismatchModal`.
- **Файлы:** `locales/ru/common.json`, `src/renderer/src/screens/ScanScreen.tsx`, тесты экрана
  `scan` и модалки `mismatch`, `docs/design/UI_SPEC.md` (§3 «Тег прохода», §модалка `mismatch`).
- **Тесты:** обновлённые ожидания текстов; тег основной пачки после перезапуска оборотов — без
  номера.
- **Гейт:** typecheck + lint + test зелёные; коммит `feat(b-3): U1 …`.

### U2. Тулбар и split-бар

- **Что:** R4–R5 — CSS левой зоны тулбара, токен `--font-size-xxxs`, split-бар на нём.
- **Файлы:** `src/renderer/src/screens/editor-screen.css`, `docs/design/DESIGN_SYSTEM.md`,
  `src/renderer/src/styles/tokens.css` (через `npm run tokens:sync`).
- **Тесты:** проверка синхронности токенов (существующая); глазами — в смоуке.
- **Гейт:** typecheck + lint + test зелёные; коммит `feat(b-3): U2 …`.

### U3. Запоминание окна

- **Что:** R6–R8 — хранилище в ядре, расстановка и слежение в main, подключение в `index.ts`.
- **Файлы:** `src/core/storage/window-state.ts` (+ тест), `src/core/storage/layout.ts`,
  `src/core/index.ts`, `src/main/window-bounds.ts` (+ тест), `src/main/index.ts`.
- **Тесты:** round-trip; нет файла → `null`; нечитаемый — отодвинут, `null`; более новой версии
  — `null` и не переписывается; негодное значение не пишется. `placeWindow`: видимое окно — как
  было; монитор отключён — по умолчанию; частично за краем — видимое; больше рабочей области —
  ужато. Слежение: серия событий даёт одну запись; при развёрнутом — границы до разворота.
- **Гейт:** typecheck + lint + test зелёные; коммит `feat(b-3): U3 …`.

### U4. Доки, смоук, журнал

- **Что:** журнал `docs/solutions/0010-b-3-ui-small-fixes.md`, раскладка каталога данных в
  спеке / `layout.ts`, бэклог; `test:all`; смоук; приёмка автора.
- **Гейт:** `test:all` зелёный; коммит `docs(b-3): U4 …`; merge — после явного ОК автора.

## Scope Boundaries

- Тексты с «проход» без номера — вне (решение автора 2026-10-26).
- Анимации и редизайн `merge` — B-4, B-5.
- Полноэкранный режим окна не запоминается (в приложении его нет).

## System-Wide Impact

- Новый файл в каталоге данных (`window.json`) — производное в смысле ADR 0004: потеря не
  теряет ничего пользовательского; ADR не нужен (порог: не схема данных сессии, дёшево
  переиграть).
- DESIGN_SYSTEM: новая ступень шкалы кеглей.

## Risks & Dependencies

- Кнопки тулбара на нестандартном масштабе Windows (125–150 %) — смоук на машине автора.
- События `moved` / `resized` на Windows приходят в конце операции; если нет — задержка
  справляется и с потоком `move` / `resize`.

- AE2. Модалка несовпадения: «Лицевых сторон 3, оборотов — 2».
