## Сессия 1 — реализация

Вход — приоритет автора 2026-10-26: кластер «Полировка UI с приёмок» первым в очереди, B-3 —
сразу без мока, движение (B-4) и `merge` (B-5) — брифами для Claude Design. Формулировки
текстов согласованы с автором в чате до плана.

### U1. Тексты без номеров проходов — ✅

`scan.tag` / `scan.tagBacks` — «СКАНИРУЕМ ЛИЦЕВЫЕ СТОРОНЫ» / «СКАНИРУЕМ ОБОРОТЫ»; `tagOf` в
`ScanScreen.tsx` больше не берёт номер. Мета досканирования основной пачки — по роли:
`scan.resumeMeta` (лица) и новый `scan.resumeMetaBacks`. Заголовки `mismatch`: «Лицевых сторон
N, оборотов — M» — одна форма без плюралов (число стоит после слова, согласование не нужно),
«Оборотов больше, чем лицевых сторон: M против N». UI_SPEC §3 (тег, мета) и §7.5 — по факту.

Не тронуты по решению автора: «проход» без номера в ошибках и подсказках, кикер «НЕ СХОДЯТСЯ
ПРОХОДЫ», «Начинаем проход…», «ПРОХОД ПРЕРВАН» на плашке.

**Готово:** typecheck + lint + test зелёные. Коммит `feat(b-3): U1 …` (`9d8a030`).

### U2. Тулбар и split-бар — ✅

Причина вылезания текста: кнопки левой зоны делили 288 px поровну (`flex: 1`), а
«↺ Новое сканирование» в 13 px шире своей половины, у `.btn` — `white-space: nowrap`. Теперь
`flex: 1 1 auto` (ширина по тексту) и `overflow: hidden` на случай текста длиннее зоны.

Split-бар уже стоял на самом мелком токене (`--font-size-xxs`, 9.5 px) — «на кегль меньше» дал
новый токен `--font-size-xxxs` (8.5 px) в DESIGN_SYSTEM (только для split-бара), `tokens:sync`.

**Отклонение от плана:** CDP-смоук показал, что по тексту двум кнопкам в 288 px запаса нет —
«+ Добавить» обрезалась на пиксель (`scrollWidth` 89 при `clientWidth` 88). Поля зоны сужены
`--space-7` → `--space-5`; после — 163 и 92 px, без обрезки. Коммит `fix(b-3): U2 …`
(`2357c70`).

Замер split-бара на эмуляторе: плашка 110 px, текст 90 px — по 10 px с каждой стороны (на 9.5 px
было бы около 5).

**Готово:** typecheck + lint + test зелёные. Коммит `feat(b-3): U2 …` (`0a65050`).

### U3. Запоминание окна — ✅

- `src/core/storage/window-state.ts` — схема v1 `{ version, bounds, maximized }`, чтение и запись
  через `versioned-file` по образцу `unclosed-jobs.ts`: нечитаемый файл отодвигается, более
  новой версии или не прочитанный — не переписывается, состояние тогда живёт в памяти. Путь —
  `layoutOf(...).windowFile` (`window.json` в корне данных).
- `src/main/window-bounds.ts` — без Electron: `placeWindow` (заголовок окна должен заходить на
  рабочую область монитора хотя бы на 100×16 px, иначе размер по умолчанию; окно больше области
  ужимается и сдвигается внутрь; «развёрнуто» в силе в обоих случаях) и `trackWindowState`
  (`moved` / `resized` / `maximize` / `unmaximize` — с задержкой 0,5 с, `close` — сразу,
  свёрнутое не пишется, дробные границы округляются).
- `index.ts`: состояние читается до `createWindow` (мониторы известны после `ready`);
  развёрнутое окно показывается через `maximize()`.

Размер по умолчанию — 1100×760, как было (в карточке бэклога ошибочно стояло 1280×800).

**Готово:** typecheck + lint + test зелёные. Коммит `feat(b-3): U3 …` (`a8c24c7`).

### U4. Проверка и доки — ✅

- `test:all` зелёный: 110 файлов / 2223 теста + интеграция 20 файлов / 208 тестов (4 пропущены
  — живой сканер не задан).
- CDP-смоук `temp/smoke-b3.mjs` (вне git, dev, эмулятор, изолированный `DUPLEXNT_USER_DATA`):
  окно открылось ровно по заранее записанному `window.json` (1320×860 в 140,90) и после
  перезапуска; теги «СКАНИРУЕМ …», нет «ПРОХОД N»; кнопки тулбара без обрезки; split-бар
  8.5 px с полями 10 px; модалка «Лицевых сторон 3, оборотов — 2». **Зелёный.**
- Грабля: запись окна через CDP не проверить — `Browser.getWindowForTarget` /
  `setWindowBounds` в Electron нет ни у страницы, ни у браузерной цели. Запись при
  перетаскивании и развороте — юнит-тестами слежения и ручным чеклистом (AE5).
- Чеклист приёмки — `docs/output/2026-10-26-smoke-checklist-b-3-acceptance.md` (вне git).
