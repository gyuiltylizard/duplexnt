## Что сделано

1. **Тулбар редактора.** «↺ Новое сканирование» / «+ Добавить» → «↺ Новый скан» / «+ Добавить
   листы», обе кнопки поровну (`flex: 1 1 0`): в зоне 288 px каждая 130 px; при полях `space-4`
   «+ Добавить листы» не хватало 2 px (scrollWidth 130 при clientWidth 128) — поля `space-3`, текст
   влезает с запасом. Кнопка плашки прерванного прохода несёт ту же подпись. «Новое сканирование»
   остаётся именем действия в модалке `newscan` и в тосте после сохранения (UI_SPEC § 7.4).
2. **Кнопка состояния выравнивания.** «Оставить оригинал» → «Оригинал» (и варианты с числом:
   «Оригинал — N стр.», «Оригинал — k из N выделенных»), «Выровнять» без изменений;
   `.inspector__section--straight .inspector__blank-action { min-width: 128px }` — проверено живьём:
   128 px в обоих состояниях. Текст модалки `revert` — «…и выбор «Оригинал»».
3. **Тексты секции ВЫРАВНИВАНИЕ** без вида искажения: выправлена — «Обнаружены искажения —
   страница выровнена.»; оригинал — «Показан исходный скан. Выровненный вид можно вернуть.»; не
   по чему мерить / форма не сошлась / не помогло — одинаково «Не удалось автоматически выровнять
   страницу.»; отложенные — «Не удалось выровнять: не хватило места на диске. Освободите место —
   при следующем запуске приложение попробует снова.» / «Не удалось выровнять из-за сбоя — …».
   Причина как категория осталась в `title` пилюли и глифа, факте ДЕТАЛЕЙ и пункте ПРОВЕРКИ.
4. **Ссылка на проект** — место выбрано автором из трёх вариантов: подвал инспектора, прижат к
   низу (`.inspector__footer { margin-top: auto }`, плашка правок переехала внутрь подвала и больше
   не прижимается сама). Строка «Duplexn't · о проекте ↗» (`APP_NAME` подстановкой), цвет
   подсказки, подчёркивание при наведении, фокус-кольцо как у кнопок. Команда моста
   `openProjectPage` без входа: renderer URL не передаёт, `PROJECT_PAGE_URL` живёт в
   `src/main/index.ts` (`shell.openExternal`; с B-40 сменится на страницу Pages); отказ —
   `storageFailed` / `openExternal` → тост «Не удалось открыть браузер: …». Контракт `bridge.ts`,
   `preload/api.ts`, `commands/handlers.ts` (+ тест), фикстуры `stubApi`, тест экрана.

## П. 5: шлифовка текстов

Автор прошёл таблицу аудита 2026-11-02, ветка `fix/b-42-copy` от `main`. Таблицу собрали до п. 1–4, поэтому
её текст сверялся с локалью на `c321e59`: прочие расхождения с текущей локалью — старые строки, а не
правки автора, и они не применялись (иначе откатились бы п. 2–3).

Внесено девять правок автора: `errors.notEsclScanner`, `errors.scannerUnreachable`, `errors.storageFailed`,
`errors.pdfPageTooLarge`, `setup.params.straightenModeHint.auto` и `.off`, `device.search.failure.socket`,
`toast.stopCloseFailed`, `toast.saveNoResponse`. Домыслено при внесении, вынесено автору на проверку:
`storageFailed` — в пометке «данные на.», убрано «на диск»; `pdfPageTooLarge` — падеж («слишком большой
размер»); подсказка режима — запятая и «сохранён». Автор подтвердил все три 2026-11-02.

Номер страницы в `pdfPageTooLarge` — по решению автора: `errorText` подставлений не делал, поэтому заведён вариант `errorReasons.pdfPageTooLarge.page`, базовый текст остался запасным. Номер считается внутри собираемого файла, строка итога называет этот файл.

Попутно: `errorReasons.scannerUnreachable.timeout` — та же фраза, что `scannerUnreachable`, держится
одинаковой; четыре текста про наборы называли кнопку «+ Добавить» — теперь «+ Добавить листы», хвост п. 1.
UI_SPEC § выбора режима, отказа «Остановить», подсказки наборов обновлены; `design:snapshot` переснят.
