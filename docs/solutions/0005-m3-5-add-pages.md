## Сессия 1 — журнал v4 и сборка по якорям в ядре

### U1. Журнал версии 4: роль прохода и якорь — ✅ зелёный

`journal.ts`: `JOURNAL_VERSION = 4`; на проходе `kind: 'fronts' | 'backs' | 'added'` и
`after: ключ | null` (схема: `after` только у `added`; `isPageKey`). Разбор цепочкой
v1 → v2 → v3 → v4: `upgradeToV4` раздаёт роли по позиции среди проходов **со страницами**
(первый — лицевые, второй — обороты, остальные — добавленные), якоря `null`. `passesByKind(journal)`
→ `{fronts, backs, added[]}` заменил `survivingPassesOf`/`backsPassOf`; роль есть только у прохода
хотя бы с одной страницей (KTD-4). `nextKindOf(journal)` — роль по очереди (лицевые → обороты,
пока не отказались → добавленный): один помощник и для `beginPass` без намерения, и для сверки.
Тип `PassKind`/`PASS_KINDS` — в `src/shared/snapshot.ts`: его ждут и схема, и renderer (U5).

Хранилище: `beginPass(origin, intent)` — `intent: AddedPassIntent | null`; `added` без сессии —
`noSession`, якорь не из сессии — `invalidInput{field: 'after'}` (R9, проверка принадлежности —
в хранилище, формат ключа — схема команды в U3). `setEdits` кладёт `rotate180` на
`passesByKind().backs`; `declineBacks` отказывает только при `backs !== null`. Снимок несёт
`kind`/`after`. Сверка: `adopt` раздаёт роли созданным проходам после сборки списка, по
возрастанию номера, через `nextKindOf` (R6) — порядок обхода каталога на роль не влияет (тест
подменяет `readdir` на обратный).

**Уточнение к ADR (не отклонение):** ограничение «лицевых и оборотов не больше одного каждого»
схема считает по проходам **со страницами**. Иначе после сбоя до первой страницы (сегмент оборотов
прерван с нулём страниц и остался в журнале) повторный запуск оборотов — второй `kind: 'backs'` —
не записался бы. Так же считает и `upgradeToV4`: пустой проход получает роль, которую занял бы
следующий со страницами.

Разрез `session-store.test.ts` (1341 строки → три файла по правилу размера): `session-store.test.ts`
(проход, досканирование, отказы, сбои записи), `session-store.lifecycle.test.ts` (закрытие,
пустая сессия, потолки, нечитаемый журнал), `session-store.flags.test.ts` (флаги, правки, роли
M3.5). Общие хелперы — `test/support/session-store.ts`: в `src/` продуктовому файлу импорт из
`test/` закрыт lint'ом, а хелперам нужен перехват ФС.

Фикстуры renderer (`PassSnapshot` в тестах) получили `kind`/`after` по номеру прохода (1 —
лицевые, иначе обороты) — только ради typecheck; renderer читает роль по позиции до U5.

**Готово:** typecheck + lint + format:check + test:all зелёные. Коммит `f5871c5`
`feat(m3.5): U1 — журнал v4: роль прохода (kind) и якорь вставки (after)`.

### U2. Ядро: сборка по якорям и одно правило rebase порядка — ✅ зелёный

`assembly.ts`: `passesByKindOf(passes)` — зеркало `passesByKind` для снимка (роль только у
прохода со страницами); `autoAssembly` — пары `fronts`/`backs`, затем блоки добавленных наборов по
возрастанию номера прохода: `splice` сразу за якорем (якорь внутри чужого блока — за ним; `null`,
ключ не из сессии или более позднего прохода — в конец). Досканированный сегмент — в конце блока
сам собой: страницы прохода идут подряд. Отчёт и `rotateBacks` — только `backs`. `AssembledPage`
получил `addedSet: number | null` — номер набора от 1 среди добавленных со страницами (один
нулабельный номер вместо пары «признак + номер»). Второй проход основной роли (схема журнала его
не пропустит) страницы не теряет — идёт добавленным набором: инвариант «каждая страница ровно
один раз» держится при любом снимке.

`edits.ts`: `rebaseOrder(before, after, order)` (KTD-3) — новый ключ встаёт в `order` сразу за
ближайшим предшественником по новому автопорядку, который в `order` есть; без предшественника —
не размещается (лента показывает его в конце через `visibleKeysOf`, как раньше); новые ключи
обходятся в порядке автопорядка, каждый видит уже вставленные. Вызов — внутри `rebaseEdits` до
`remapCuts`: разрезы переезжают по видимой ленте уже с новым порядком. Хранилище (`withRebasedEdits`)
не менялось — правило работает на каждом коммите страницы, и три страницы тремя коммитами дают
то же, что один коммит сверки.

Тесты: табличные на размещение (пример из HTD целиком, якорь-оборот, удалённый/потерянный/
исчезнувший/поздний якорь, досканированный сегмент, пустые проходы, `[fronts, added]` при
`backsDeclined`, «Вернуть»), `rebaseOrder` (полный/неполный порядок, без предшественника, три
ключа разом = по одному, перетащенный первый набор), разрезы и документы, store-уровень
(досканирование лицевых и добавленный набор при ручном порядке с разрезом). Тест AE9 M3 «новые
страницы в конце» заменён на «на своём месте» в трёх местах: `edits.test`, `session-store.flags.test`,
`editor-save.emulator.test` (интеграция).

**Отклонение от плана (осознанное):** `survivingOf` в `assembly.ts` оставлен до U3 — его ещё
читает политика `pass-service` (файл U3); тост `toast.appended` и его тест в renderer — U5 по
плану (строка 330), ядро уже кладёт страницы на место.

**Готово:** typecheck + lint + format:check + test:all зелёные. Коммит `feat(m3.5): U2 …`.

## Сессия 2 — политика и мост; split-бар; handoff

### U3. Служба, мост и команды — ✅ зелёный

`StartPassRequest = AddedPassIntent | null` в `shared/bridge.ts` (`AddedPassIntent` переехал
из хранилища в shared — его ждут и схема, и renderer). `startPassRequestSchema` (строгий
объект `{kind: 'added', after: ключ | null}` или `null`), обработчик через `parseInput` —
`startPass` ушёл из списка «команд без входа» в тестах обработчиков. `pass-service.startPass(request)`:
`added` — `noSession` без сессии, `passInterrupted` при прерванном последнем (иначе `resumable()`
застревал бы на нём), `invalidInput{field: 'after'}` для якоря не из сессии — всё до сети;
обходит `backsDeclined`/`backsPresent`; `expected = null`. Без намерения — политика M2, но роль
по `kind` (`passesByKindOf`), `expected` только у `backs`; `survivingOf` в `assembly.ts` стал
приватным. `Run` несёт `kind` и `request`: `PassProgress.kind` в снимке, намерение — в
`beginPass`. Новый код `passInterrupted`, тексты `backsPresent`/`backsDeclined` переписаны
(больше не «тупик»). Renderer и preload зовут `startPass(null)`; фикстуры `PassProgress`
получили `kind` (по `expected`: число → `backs`, `null` → `fronts`).

Интеграция через эмулятор (`test/integration/added-pass.emulator.test.ts`): набор после лица 2
— роль и якорь в журнале, страницы за якорем, отчёт пар прежний, снимки `scan` без «из M»;
обрыв со страницами → `passInterrupted` на повторное добавление, досканирование тем же
проходом; обрыв до первой страницы → отчёт `{end: 'interrupted', pages: 0, error}` при живой
сессии (как у оборотов в M2), проход отброшен.

**Готово:** typecheck + lint + format:check + test:all зелёные. Коммит `0f8c087`
`feat(m3.5): U3 — startPass с намерением: политика добавленного набора, схема и мост`.

### Ревью сессий 1–2 (simplify + code-review) — ✅ применено

Simplify (четыре угла: reuse, simplification, efficiency, altitude), коммит `b1e8340`:

- **Политика запуска — в одном слое.** Служба повторяла правила хранилища своими словами
  (членство якоря через `passes.some`, «есть сессия» через `snapshot() === null`, роль — своё
  дерево вместо `nextKindOf`). Теперь `store.planPass(request)` — чистый запрос над журналом:
  `noSession` / `passInterrupted` / якорь / `backsDeclined` / `backsPresent` / досканирование /
  роль и «из M»; служба зовёт его до сети, `beginPass` проверяет намерение той же `checkIntent`.
- **Один помощник ролей** — `passesByKind<T>(passes, hasPages)` в `src/shared/snapshot.ts`
  (KTD-4 буквально: журнал, снимок, дальше renderer); `rolesOf(journal)` в `journal.ts`;
  зеркало в `assembly.ts` с «второй fronts идёт добавленным» и `.sort` ушло вместе с тестом на
  невозможное состояние. `pageKeySchema` — одна схема ключа на правки, журнал и вход команд.
- `adopt`: роль при создании прохода с обходом файлов по возрастанию номера — без второго
  цикла и множества `created`. `rebaseOrder`/`rebaseEdits` — без мёртвых веток. `addedSet` —
  картой при сборке, а не полем автопорядка.
- Renderer: `pickModifierHeld` — одно правило модификаторов на клик и клавиши; сжатие
  выделения — `onMouseDown` на трёх поверхностях (тулбар, превью, инспектор) с исключением
  органов управления, вместо чёрного списка на `<main>` с `railRef` и `[role="dialog"]`.
- Тесты: `rolesOf`, `journalOnDisk`, `ok = unwrap` в `test/support/session-store.ts`;
  `gatedConnector` на уровне модуля; один билдер прохода в `journal.test`; тесты `planPass`.
- Пропущено осознанно: скрытие split-бара CSS-классом вместо пропа (ререндер ленты на Shift —
  единицы мс, тесты проверяют отсутствие бара в DOM); дубли `FAST`/`OPTIONS`/`connect` в
  интеграционных тестах и литералы `PassSnapshot` в `App.test`/`ScanScreen.test` — паттерн
  старше вехи, не трогаем попутно.

Код-ревью (8 находок), коммит фиксов — следующий:

- **Исправлено:** `declineBacks` убирает пустой прерванный проход оборотов — иначе
  «Досканировать» начинало бы обороты вопреки отказу, а «Добавить» ждало бы «оставить как
  есть» (находка про `planPass(null)` после отказа); хвост `planPass` — очередь через
  `nextKindOf`, «добавленный» без намерения → `backsDeclined`/`backsPresent` (правило в одном
  месте, мёртвая ветка ушла); сжатие выделения — только левой кнопкой (ПКМ по превью не
  трогает выделение); `modeOf` принимает структурный тип модификаторов без приведения к
  `MouseEvent`.
- **Не баг:** расхождение роли между `planPass` и `beginPass` во время `prepare` — служба
  держит `run` и отклоняет `declineBacks`/`closeSession`/`acceptPass`/`setEdits` как
  `passRunning`; зафиксировано комментарием в `beginPass`.
- **Отложено в U5 (по плану):** renderer читает обороты по позиции (`survivingPasses[1]` в
  `EditorScreen`, `history.ts`, `screen.ts`) и тег `scan` по `expected !== null` — U5 переводит
  на `kind` через shared `passesByKind`.
- **Принято как есть:** `passInterrupted` при прерванном проходе с неизвестными параметрами —
  текст предлагает и «оставить как есть», это и есть выход (плашка S17 без «Досканировать»).

## Сессия 3 — роль по `kind` в renderer, экраны, модалка `add`, `mismatch`

### U5. Renderer: роль по `kind`, экраны и App — ✅ зелёный

`state/screen.ts`: `rolesOf(passes)` через shared `passesByKind` — единственное место правила
ролей в renderer (KTD-4); `survivingPasses` ушёл. `flipForm` — только при одном уцелевшем лицевом
(обороты или добавленный набор уцелели — `editor`: разворот позади); `flipBusy` — только у
`kind: 'backs'` (добавленный с `flip` не запускается). `history.editStateOf` и тумблер 180° в
`EditorScreen` читают обороты по `kind`; фикстуры с ролью по позиции получили `kind: 'backs'`.
`assembly-fixture.assemblyOf` повторяет KTD-2 (блоки добавленных за якорем, `addedSet` от 1);
расхождение с ядром ловит табличный тест `test/guards/assembly-fixture.test.ts` — живёт вне
обоих слоёв (node-проект), 18 сессий, `toEqual` всей сборки. `mismatchDue(report, passes)` —
`false` при добавленном наборе со страницами (KTD-7); то же условие кормит подсказку
инспектора в U6.

`App`: память о запуске — `Launch {epoch, sessionId, keysBefore}` ставится в `startPass` для
любого запроса; посадка (`Landing`) ловится корректировкой состояния при рендере, как пауза
`merge`: в `editor` той же сессии появились ключи, которых до запуска не было → если последний
проход `added` и не прерван — тост «Добавлено N» (N — новые видимые страницы) с меткой
«один раз» (`showToast(..., tag)` идемпотентен под StrictMode) и текущая — первая новая
(`EditorScreen` получает `key={landing.epoch}` и `initialCurrent`; `useEditorEdits` стартует с
`single(initialCurrent)`, экран прокручивает к ней `scrollIntoView` ближайшим краем при
монтировании). Прерван — посадка без тоста (плашка S4). Пауза `merge` — по `assemblyLanded` и
`lastPass.kind !== 'added'`: роль у последнего прохода сессии, он и шёл — покрывает и
досканирование добавленного набора, где запрос `null`. Отказ запуска с намерением `added` —
тост `toast.addFailed` 6 с (`ok:false`, и `ok:true, end:'interrupted', pages:0` при живой
сессии — ядро отбросило пустой проход); `LaunchFailure` плашек не трогает (KTD-6).
`toast.appended` и блок тестов AE9 M3 удалены (KTD-3: новые страницы встают на своё место).
`ScanScreen`: тег по `kind` («ДОБАВЛЯЕМ СТРАНИЦЫ» на `--color-pass-3`, без номера прохода),
счётчик по `expected`, мета досканирования `scan.resumeMetaAdded`; `EditorPassBanner`:
`titleAdded`/`textAdded` при `last.kind === 'added'`.

Решение по ходу: посадку App узнаёт по снимку, а не по ответу команды — ответ может прийти
раньше снимка (хранилище снимка дотягивает его `getSnapshot` асинхронно), а кадр `scan` может
быть пропущен. Нереализуемое из плана: тест «отказ запуска `added` → тост» перенесён в U6 —
без кнопки «+ Добавить» запуск с намерением из UI не вызвать.

**Готово:** typecheck + lint + format:check + test:all зелёные (1559 unit, 130 integration).
