Находки doc-review плана внесены до старта (2026-10-25): проба сообщает о первом HTTP-ответе —
«занят» не запускает поиск; жёсткий срок проверки ~10 с, приём кандидатов ~8 с, обрыв по сроку —
«не отвечает»; `5xx` кроме `503` — без поиска; профиль без отпечатка не ищется; «Повторить»
прерывается при закрытии; очередь кандидатов с сохранённым портом вперёд. Решение автора:
«занят» — только в модалке подключения, строка устройства остаётся «не отвечает».

## Сессия 1 — замер на железе, классификация, поиск по UUID

### U1. Замер на живом ET-3850 — ✅

Скрипт `temp/measure-m5.mjs` (вне git; полные значения — в `temp/m5-measure.json`, в выводе —
маски). Автор менял адрес сканера и перезагружал МФУ; три снимка: «до», «после», «после
перезагрузки».

- **Сертификат при смене адреса не меняется** — отпечаток, SAN и срок те же и после
  перезагрузки. В SAN остаётся старый IP: устройство SAN не обновляет. Стоп-условие плана не
  сработало; R3 (отпечаток доказывает «то же устройство») держится.
- **UUID TXT = UUID capabilities**, регистр тоже совпадает.
- **`503` на `GET` нет**: два прогона по 60 с во время печати — `ScannerCapabilities` и
  `ScannerStatus` отвечают `200`, состояние `Processing`. Ожидание «занят» в пробе остаётся
  страховкой (решение автора — строится при любом итоге замера).
- **Два поиска в одном процессе** оба видят сканер за 0,1–1,2 с — запасной вариант «модалка
  останавливает поиск проверки» не нужен.

Итог — в техбазе §8 («Проверено на ET-3850 2026-10-25»). Коммит `docs(m5): U1 …`.

### U2. Классификация исхода пробы и ожидание «занят» — ✅ зелёный

`src/core/storage/probe-outcome.ts` — чистая `classifyProbe(scanner, probed)` → `ok` / `silent` /
`foreign` / `busy` / `garbled` / `canceled` по таблице KTD1; `isSilence` удалён. Проверка
запомненного сканера пока даёт прежние слоты (`foreign` → `otherDevice`, остальное →
`unreachable`); поиск подключает U4.

`src/core/escl/connect.ts`: `probeScanner(profile, options, probe)` — третий параметр теперь
`ProbeOptions { signal?, onResponse?, waitBusy? }`. `503` на capabilities — повтор раз в 1 с до
потолка 15 с (`PROBE_BUSY_WAIT`), затем `scannerBusy`; `onResponse` — один раз, на первый
HTTP-ответ с любым кодом, до паузы; `waitBusy: false` — режим кандидата, `503` сразу
`scannerBusy`. Шов часов `ProbeClock` / `realProbeClock` по образцу `ScanJobClock`; петли
`scan-job.ts` не объединялись (KTD6). Переход на HTTP по `scannerBusy` не идёт — правило
`FALLBACK_REASONS` его и так не включало, добавлены комментарий и тест. Текст `scannerBusy` — без
«за минуту»: он общий для потолков 15 и 60 с.

Эмулятор: поле сценария `busyCapabilities` и именованный сценарий `capabilities-busy`.

**Отклонения от плана (осознанные):** классификатор — в своём модуле с тестом (план называл
`settings-store.ts`), чтобы файлы оставались малыми; `scannerNoAdf` и прочие не названные в
таблице коды — `foreign` (сохраняет прежний слот `otherDevice`). Тексты `scannerBusy` в
исторических handoff'ах M1/M2 не правились.

**Готово:** typecheck, lint, format:check, `test:all` зелёные (2145 + 203). Коммит
`feat(m5): U2 …`.

### U3. Поиск по UUID в обнаружении — ✅ зелёный

`src/core/discovery/find-by-uuid.ts`: `findByUuid({ uuid, onCandidate, windowMs?, signal?,
clock?, discovery? })` → `{ done, stop() }`. Кандидаты (`address`, `port`, `basePath`) — по мере
появления, каждый адрес с портом один раз; UUID в нижнем регистре с обеих сторон. Исход
`done` — `window` / `noNetwork` / `socket` / `canceled` / `stopped`; единственный выход через
`finish`, поиск останавливается всегда, исключение обработчика отклоняет `done` (не роняет main
из события библиотеки). Окно приёма — `UUID_SEARCH_WINDOW_MS` = 8 с; таймер окна не держит
процесс. `Discovery` получил `records()` только для ядра; `state()` и снимок не изменились.

**Отклонения:** две фейковых `Discovery` в `handlers.test.ts` получили `records: () => []` (метод
обязательный). Кандидаты берутся из слитого списка поиска с его потолком 64 записи — для домашней
сети приемлемо.

**Готово:** typecheck, lint, format:check, `test:all` зелёные (2162 + 203). Коммит
`feat(m5): U3 …`.
