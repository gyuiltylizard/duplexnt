## Сессия 1 — handoff + ядро данных

### U7. Handoff состояний M2 — ⏳ отдан автору на утверждение

`docs/design/handoffs/2026-10-m2-states.md` по шаблону и образцу M1: S1–S9 (занятость и
перезапуск на `flip`, чеклист с пунктом про входной лоток, статусная строка `merge`,
`mismatch` трёх исходов без кнопок действия, пометка непарного листа, тумблер 180° внизу
ленты, состояния кнопки сохранения, точка несохранённого), полный Copy M2 без «пачки».
Открытых вопроса автору два: порядок фокуса `editor` (отложен с M1) и слово «стопка» в
текстах разворота. Утверждение — блокер U8–U10, дедлайн — до начала сессии 4.

**Готово:** документ написан, код не трогался. Коммит `feat(m2): U7 …` (2e07202).

### U1. Журнал версии 2 и чтение версии 1 — ✅ зелёный

`JOURNAL_VERSION = 2`: `rotate180` на записи прохода, `backsDeclined` и `saved` на сессии.
Чтение v1 — отдельной v1-схемой с явным `upgradeToV2` (не дефолтами в общей схеме): v2 остаётся
строгой, а порядок «сначала текущая схема, потом v1» сохраняет правило «неизвестное поле —
несовместимость при любой версии». Методы хранилища `setRotateBacks` / `declineBacks` /
`markSaved`; роль прохода — `survivingPassesOf` / `backsPassOf` в `journal.ts` (KTD-4). Отметка
о сохранении снимается новой страницей, удалением сегмента со страницами и сменой поворота;
«обороты не нужны» её не трогает (вывод не меняется). Новая сессия флаги не наследует. Форма v2
зафиксирована амендментом ADR 0004 («форма журнала версии 2»).

**Отклонение от плана (осознанное):** затронуты файлы сверх списка U1 — `reconcile.ts`
(сверка переписывает v1-файл текущей версией: сравнение «переписывать ли» теперь учитывает
версию маркера на диске) и `src/shared/errors.ts` (+2 причины `sessionConflict`: `noBacksPass`,
`backsPresent`; строк локали у них нет намеренно — на экран не ведут, фолбэк даёт базовый текст
кода; строки добавит U3/U9, если путь появится).

**Готово:** typecheck+lint+format+test:all зелёные. Коммит `feat(m2): U1 …` (66a027a).

### U2. Сборка: `interleave`, пары, отчёт — ✅ зелёный

`src/core/scan/assembly.ts` — чистая функция `assembleSession(SessionSnapshot)`: порядок
по умолчанию + отчёт (`fronts/backs/pairs/unpairedSheets/extraBacks/backsState/backsDeclined/
mismatch`). Типы — в `src/shared/snapshot.ts`; `Snapshot.assembly` заполняет `pass-service`
(derived на каждый снимок, в журнал не пишется). Табличные тесты обязательной зоны: равные
проходы, короче/длиннее, «обороты не нужны», принят коротким, роль по позиции (№1+№3),
потерянные страницы на месте, инвариант «каждая страница ровно один раз». Защитный край сверх
плана: третий уцелевший проход (в M2 недостижим политикой U3) не собирается, но и не
выбрасывается — страницы в конце порядка.

**Готово:** typecheck+lint+format+test:all зелёные (1031 юнит + 114 интеграционных).
Коммит `feat(m2): U2 …` (5576519).

**Отклонение от плана (осознанное):** M1-тест «оставить как есть → досканировать нельзя»

### U4. Эмулятор: лотки по заданиям и двухпроходные сценарии — ✅ зелёный

порядком — физика разворота), `reloadTray` пополняет очередь без сброса сценария и списка
заданий, `DELETE` прогоняет остаток лотка задания. Сценарии `two-pass`,
`two-pass-missing-sheet`, `two-pass-jam`. Интеграционный `two-pass.emulator.test.ts` (8
тестов): AE1 — interleave сверяется побайтово с фикстурами (лист 1 получает оборот-фикстуру

AE6 («Остановить» на первом сегменте → «flip»-форма; проход №3 — оборотный: expected, флаг,
сборка), AE7 (перезапуск между проходами), AE9 (счётчик переваливает, лишний оборот в конце).
Коммит `feat(m2): U4 …` (223059d).

## Сессия 3 — PDF и сохранение

### U5. Сборка PDF в ядре — ✅ зелёный

`@cantoo/pdf-lib@2.11.1` в devDependencies (ADR 0007). `src/core/pdf/assemble.ts`: `embedJpg`
без перекодирования — тест извлекает поток из PDF и сверяет байты с фикстурой устройства,
фильтр `/DCTDecode`; поворот — только `setRotation(degrees(180))`; размер страницы — пиксели /
DPI × 72 (KTD-9); предел пикселей — `decodePixelLimit` (потолок sharp не ослабляется); коды
`pdfPageTooLarge` / `pdfPageUnreadable`. Находка: JPEG устройства идут **вообще без APP0**
(ни JFIF, ни EXIF) — ветка «плотность из JFIF» для пересобранных сессий в реальности не
сработает, рабочий путь — дефолт 300 dpi; JFIF-ветка оставлена и покрыта синтетикой.
**KTD-12 замерен** (`test/integration/pdf-worst-case.test.ts`, объём ~350 МБ = 53 × 6,8 МБ):
пик RSS сверх базы — **704 МБ** (в предсказанных 0,7–1 ГБ), максимальная пауза цикла событий —
**86 мс**, сборка 374 мс. Блокировки нет, пик допустим → **выделенный worker не нужен**;
пороги теста (2,5 ГБ / 1,5 с) — триггер пересмотра. Коммиты 26ff331 + 2df07e7/dea250e (типы).

### U6. Сохранение: мост, диалог, атомарная запись, отметка — ✅ зелёный

Команда `savePdf` (мост → схема → обработчик → preload); `CommandContext.askSavePdfPath` —
`dialog.showSaveDialog` в main (KTD-3; дефолт «Скан YYYY-MM-DD.pdf» в «Документах», перезапись
подтверждает диалог ОС). Оркестровка в службе прохода: путь → страницы в собранном порядке
(потерянная — отказ `pageUnavailable`, не молча короче) → `assemblePdf` → `writeFileAtomic`
с temp рядом с целью → `markSaved` только после успешного rename. Отказ в диалоге —
`canceled` без ошибки и без записи. `saveWriteFailed` (+ локаль), `ENOSPC` → `storageFull`.
`PageInfo.dpi` — из `origin` прохода. Тесты: AE10 через `intercept-fs` (сбой rename — старый
файл цел побайтово, сессия и журнал целы, повтор перезаписывает), AE12 на уровне службы.
Коммит `feat(m2): U6 …` (67450d2).

### U8. Экран `flip` и полные тексты `setup`/`scan` — ✅ зелёный

`screenOf` расширен формой «flip» (KTD-5: единственный уцелевший **непустой** проход —
лицевой, завершён или принят, отказа нет) и занятостью S2 (KTD-11: проход оборотов в
`busy`/`starting` без страниц и не resumed — экран остаётся `flip`; первая страница или
`scanning` — `scan`; досканирование оборотов — сразу `scan`). `FlipScreen` — по макету +
handoff S1–S3; `setup` вернул двухпроходные тексты и колонку «Как это работает»; `scan` —
тег роли по `expected` (не по чётности номера — KTD-4) и счётчик «N из M» с перевалом.
Адресат плашки отказа запуска в App теперь выводится `screenOf` (третий адресат — `flip`,
туда же приходит потолок ретрая занятости). Смоук-тест локали: `пачк|стопк` не встречается.

**Отклонение от плана (осознанное):** текст шага 4 «Как это работает» из макета («Правьте
порядок перетаскиванием») заменён на «Порядок соберётся сам — проверьте его и сохраните
документ»: перетаскивания нет до M3, а интерфейс M2 не обещает того, чего веха не делает
(принцип KTD-25 M1).

**Готово:** typecheck+lint+format+test:all зелёные (1092 юнит + 123 интеграционных).

## Сессия 5 — merge/mismatch/редактор

### U9. Экран `merge`, модалка `mismatch`, тумблер и сохранение — ✅ зелёный

`MergeScreen` — процессный, статусная строка из отчёта сборки (первой сообщает о
несовпадении); пауза 1600/1200 мс живёт в App **поверх** `screenOf` (эффект ловит переход
«scan с завершённым проходом оборотов → editor» и «flip → editor после отказа»), переживает
StrictMode и не повторяется после перезапуска (KTD-5, тесты App с фейковыми таймерами).
`MismatchModal` — три исхода Copy, без кнопок действия; показ выведен из снимка (KTD-8):
`mismatch` в отчёте + `backsState` completed/accepted + не подтверждено для этой сессии за
этот процесс — перезапуск в окне паузы не глотает модалку (AE13). Редактор: лента — порядок
сборки (`snapshot.assembly.order`, AE1), «об»-тег и `transform`-поворот на оборотах, точка
непарного листа по `unpairedSheets`, тумблер 180° внизу ленты, правая зона тулбара (точка
несохранённого + «Сохранить документ» с блокировкой на время записи, тосты 6 с, `canceled` —
тишина). Интеграционно: сценарий целиком на эмуляторе — два прохода → тумблер → `savePdf`,
`/Rotate 180` только на оборотах, исходники байт в байт (AE1/AE8).

**Отклонения от плана/handoff (осознанные):**

- **Группы «ПРОХОД N» из ленты убраны:** порядок сборки перемежает проходы (AE1), группы ему
  противоречат; ключи `editor.pass.*` удалены, предложенный handoff'ом `editor.pass.titleBacks`
  не пригодился — роль оборота в ленте несёт тег «об». Прерванность/приёмка видны плашкой S17
  и статусом `merge`/`mismatch`.
- Отказ `declineBacks` показывается своим текстом, не «Проход не начался…» (это не запуск).
- `mismatch` **не** показывается, пока проход оборотов прерван и не принят: Copy трёх исходов
  не имеет варианта «прерван», решение ведёт плашка досканирования; модалка приходит после
  «Оставить как есть» (KTD-8 читался неоднозначно — выбран этот разбор).

**Готово:** typecheck+lint+format:check+test:all зелёные (1119 юнит + 124 интеграционных).
Коммит `feat(m2): U9 …` (c32a566).

## Ревью сессий 4–5 (после закрытия сессии 5)

**Код-ревью (9 находок, все применены — 2a4bc69):** главное — тупик на `flip` (ошибки
«подключите заново» без пути в `device`; `declineBacks` при этом необратим — двусторонний
набор терялся бы) и пауза `merge`, терявшаяся при батчинге снимков (кадр `scan` между `flip`
и `editor` можно пропустить — теперь переход читает отчёт, детекция — корректировкой
состояния при рендере). Плюс: Copy «принят длинным» без битого пустого перечня, честная
диаграмма `merge`, aria-label на listbox ленты, тост при отвале IPC сохранения, мёртвая
ветка `canceled`, дубли `surviving`/`multiline` сведены.

**Simplify (4 параллельных ревью: reuse/simplification/efficiency/altitude — 6c5ad40):**
`LaunchFailureNotice` + один ключ `launch.failed` (изменение против M1: текст `scannerBusy`
на `setup` теперь без обёртки, как на `flip` — самодостаточная фраза); `assembly-outcome`
(`assemblyOutcome`/`assemblyLanded`/`mismatchDue` под юнит-тестами — классификация исхода
сборки в одном месте для `merge`, `mismatch` и App); ряд «документ» — из `assembly.order`;
`Thumb` на примитивах (memo переживает новый снимок после IPC); «ВЕРХ» в локали; фикстура
сборки тестов — одна (`state/assembly-fixture.ts`, зеркало ядра с пометкой).

**Отложено осознанно (не делаем без обсуждения, кандидаты не-горящих правок M3+):**

- перенос `assembleSession`/`survivingOf` из ядра в `src/shared` (тесты renderer зеркалят
  ядро фикстурой; честное решение — общий модуль, но это сдвиг границы слоёв);
- `PassProgress.role: 'fronts'|'backs'` из main вместо вывода роли по `expected !== null`
  (второй источник правды о роли в renderer, пока контракт задокументирован в snapshot.ts);
- `unpaired` как поле `AssembledPage` из ядра (сейчас renderer сопоставляет отчёт и порядок).

## Сессия 6 — живой прогон и закрытие

### U10. Живой прогон и смоуки — ⏳ агентская часть зелёная, ручная приёмка у автора

**Живой тест** `two-pass.live.test.ts` (a84aee7 + a87498e): 12 пронумерованных листов
(`spikes/make-twopass-pdf.mjs`), два прохода через службу, ожидание разворота пачки —
повторными запусками второго прохода, пока лоток пуст. **AE2 пройден**: порядок правильный,
PDF `temp/duplexnt-live-two-pass.pdf` сверен автором глазами.

**Находка (важная):** первая версия теста включала тумблер 180° безусловно — и перевернула
обороты вверх ногами. Живой прогон подтвердил физику техбазы («Физическое действие
пользователя»): **после разворота пачки обороты приходят в правильной ориентации, доворот в
дефолте не нужен; тумблер — аварийный** (для пачки, сканированной без разворота). Тест
исправлен: штатный PDF без /Rotate, аварийный тумблер проверяется вторым сохранением без
пересканирования (AE8/AE12 живьём — автор сверил оба PDF: штатный прямой, rotated нарочно
вверх ногами).

**CDP-смоук** (`temp/smoke-m2.mjs`, не под git): один процесс ведёт эмулятор (лотки по
заданиям), Electron и клики через CDP; изолированный `DUPLEXNT_USER_DATA`. Сценарий: setup →
подключение по адресу → лицевые → `flip` (кикер, чеклист) → обороты (тег «· ОБОРОТЫ»,
счётчик «из 3») → `merge` («совпало пар: 3») → editor (порядок FBFBFB, теги «об», тумблер
туда-обратно, точка несохранённого) → новое сканирование → недостающий лист → `mismatch`
