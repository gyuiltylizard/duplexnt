## Сессия 1 — handoff + ядро данных

### U7. Handoff состояний M2 — ⏳ отдан автору на утверждение

`docs/design/handoffs/2026-10-m2-states.md` по шаблону и образцу M1: S1–S9 (занятость и
перезапуск на `flip`, чеклист с пунктом про входной лоток, статусная строка `merge`,
`mismatch` трёх исходов без кнопок действия, пометка непарного листа, тумблер 180° внизу
ленты, состояния кнопки сохранения, точка несохранённого), полный Copy M2 без «пачки».
Открытых вопроса автору два: порядок фокуса `editor` (отложен с M1) и слово «стопка» в
текстах разворота. Утверждение — блокер U8–U10, дедлайн — до начала сессии 4.

**Готово:** документ написан, код не трогался. Коммит `feat(m2): U7 …` (2e07202).

### U1. Журнал версии 2 и чтение версии 1 — ✅ зелёный

`JOURNAL_VERSION = 2`: `rotate180` на записи прохода, `backsDeclined` и `saved` на сессии.
Чтение v1 — отдельной v1-схемой с явным `upgradeToV2` (не дефолтами в общей схеме): v2 остаётся
строгой, а порядок «сначала текущая схема, потом v1» сохраняет правило «неизвестное поле —
несовместимость при любой версии». Методы хранилища `setRotateBacks` / `declineBacks` /
`markSaved`; роль прохода — `survivingPassesOf` / `backsPassOf` в `journal.ts` (KTD-4). Отметка
о сохранении снимается новой страницей, удалением сегмента со страницами и сменой поворота;
«обороты не нужны» её не трогает (вывод не меняется). Новая сессия флаги не наследует. Форма v2
зафиксирована амендментом ADR 0004 («форма журнала версии 2»).

**Отклонение от плана (осознанное):** затронуты файлы сверх списка U1 — `reconcile.ts`
(сверка переписывает v1-файл текущей версией: сравнение «переписывать ли» теперь учитывает
версию маркера на диске) и `src/shared/errors.ts` (+2 причины `sessionConflict`: `noBacksPass`,
`backsPresent`; строк локали у них нет намеренно — на экран не ведут, фолбэк даёт базовый текст
кода; строки добавит U3/U9, если путь появится).

**Готово:** typecheck+lint+format+test:all зелёные. Коммит `feat(m2): U1 …` (66a027a).

### U2. Сборка: `interleave`, пары, отчёт — ✅ зелёный

`src/core/scan/assembly.ts` — чистая функция `assembleSession(SessionSnapshot)`: порядок
по умолчанию + отчёт (`fronts/backs/pairs/unpairedSheets/extraBacks/backsState/backsDeclined/
mismatch`). Типы — в `src/shared/snapshot.ts`; `Snapshot.assembly` заполняет `pass-service`
(derived на каждый снимок, в журнал не пишется). Табличные тесты обязательной зоны: равные
проходы, короче/длиннее, «обороты не нужны», принят коротким, роль по позиции (№1+№3),
потерянные страницы на месте, инвариант «каждая страница ровно один раз». Защитный край сверх
плана: третий уцелевший проход (в M2 недостижим политикой U3) не собирается, но и не
выбрасывается — страницы в конце порядка.

**Готово:** typecheck+lint+format+test:all зелёные (1031 юнит + 114 интеграционных).
Коммит `feat(m2): U2 …` (5576519).

## Сессия 2 — второй проход

**Решение автора по пайплайну дизайна (в начале сессии):** Claude Design до MVP не
привлекается; дизайн — из мока, дырки закрывает handoff dev-агента (U7 остаётся рабочим
артефактом); полировка с Claude Design — пост-MVP, как в Shelfory. Утверждение содержимого
handoff'а автором по-прежнему нужно до сессии 4.

### U3. Второй проход в службе прохода — ✅ зелёный

`startPass`: политика M1 «новый проход только без сессии» заменена — поверх завершённого или
принятого единственного уцелевшего прохода начинается проход оборотов (роль по позиции,
KTD-4); прерванный — только досканирование; `backsDeclined`/`backsPresent` — отказ до сети.
`PassProgress.expected` (R2) — страницы лицевого, и для досканирования оборотов тоже. Команды
`declineBacks`/`setRotateBacks` по всей цепочке (мост → схема → обработчик → preload); новая
причина `sessionConflict.backsDeclined`, строки локали для всех трёх новых причин. Юнит-тесты
политики — на посеянных на диск сессиях с подставным транспортом («дошли до сети — политика
пропустила»). Коммит `feat(m2): U3 …` (c6452fb).

**Отклонение от плана (осознанное):** M1-тест «оставить как есть → досканировать нельзя»
обновлён — в M2 поверх принятого прохода законно начинается новый проход оборотов.

### U4. Эмулятор: лотки по заданиям и двухпроходные сценарии — ✅ зелёный

`Scenario.trays` — содержимое лотка на каждое задание (номера фикстур; обороты обратным
порядком — физика разворота), `reloadTray` пополняет очередь без сброса сценария и списка
заданий, `DELETE` прогоняет остаток лотка задания. Сценарии `two-pass`,
`two-pass-missing-sheet`, `two-pass-jam`. Интеграционный `two-pass.emulator.test.ts` (8
тестов): AE1 — interleave сверяется побайтово с фикстурами (лист 1 получает оборот-фикстуру
4), AE3/AE4 (обрыв + досканирование и «оставить как есть»), AE5 (отказ от оборотов durable),
AE6 («Остановить» на первом сегменте → «flip»-форма; проход №3 — оборотный: expected, флаг,
сборка), AE7 (перезапуск между проходами), AE9 (счётчик переваливает, лишний оборот в конце).
Коммит `feat(m2): U4 …` (223059d).

### Сессия 2 — итог
