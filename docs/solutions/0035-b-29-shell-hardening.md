замороженный артефакт решений; этот файл копит **отклонения, грабли и «на чём встали»** по ходу

устройства подтверждает пользователь), [0005](../decisions/0005-bridge-validation-errors-events-images.md)

Electron 44.4.3, electron-vite 5.0.0, electron-builder 26.15.3, Node 22. Живые проверки на `out/`

## Сессия 1 — оболочка, страж, ADR 0008

### U1. Схема интерфейса — ✅ зелёный

**Спайк на `out/`** (первый шаг, до остального кода): схема `duplexnt-app` с привилегией только
`standard`, без `secure`. Итог на собранном приложении с эмулятором, два прохода, 6 страниц:

- документ — `duplexnt-app://app/index.html`, origin `duplexnt-app://app`, `isSecureContext`
  = `false`;
- модульный скрипт Vite с `crossorigin`, стили и шрифты (Golos Text, IBM Plex Mono — `woff2`
  относительными адресами `./assets/…`) загружаются; `'self'` в CSP им достаточно;
- миниатюры и полная страница с `duplexnt-page` показываются (не смешанное содержимое, потому
  что страница не на «безопасной» схеме); ошибок CSP, консоли и сети нет;
- API безопасного контекста интерфейсу не нужен — `secure` не берём (KTD-1 подтверждён);
  `corsEnabled`, `supportFetchAPI`, `codeCache` не понадобились. Привилегии `duplexnt-page` не
  менялись.

**Реализация.** `src/main/app-protocol.ts`: константы схемы, привилегии литеральным типом (как у
`page-protocol.ts`), `resolveAppFile` и `handleAppRequest` с инъекцией чтения файла. Правила:
только `GET`; хост `app`; без userinfo, порта и строки запроса; **любой `%` и `\` в пути —
отказ** (имена сборки — ASCII без спецзнаков, поэтому раскодировать нечего: `%2e%2e`, `%252e`,
`%2f`, `%00`, `%20` отклоняются одним правилом, а путь без `%` равен своему раскодированному
виду); сегмент — `[A-Za-z0-9_-]+(\.[A-Za-z0-9_-]+)*` (отсекает `.`/`..`, пустые сегменты,
хвостовую точку и пробел, `::$DATA`, букву диска); тип — по белому списку ровно того, что кладёт
сборка (`html`, `js`, `css`, `woff2`, `woff`); второй рубеж — путь строго под каталогом с
разделителем после корня. Ответ: `nosniff`, `no-store`; любой отказ и ошибка чтения — 404.
`src/main/index.ts`: обе схемы в одном `registerSchemesAsPrivileged` до `ready`, обработчик — в
начале `start()` до первого окна, `loadRenderer` вне dev-сервера зовёт `loadURL` схемы;
`loadFile` больше нет.

Грабли спайка тестов: разборщик URL нормализует путь до обработчика — `./` схлопывается,
хвостовой пробел снимается, адрес без пути под Node даёт пустой `pathname` (в Chromium — `/`).
Это принятые случаи, а не обход: проверки идут по уже нормализованному пути.

**Тест сборочного CSP (B-28)** — `test/integration/build-csp.test.ts`: сборка во временный
каталог (`electron-vite build --outDir`, ~3,5 с), мета-тег ровно равен `buildCsp({profile:
'build'})` и он единственный, профиля dev нет; плюс связка со схемой — каждый файл сборки
`resolveAppFile` умеет отдать (новый тип ассета не станет молча 404 в упакованном приложении),
а ссылки `index.html` относительные и указывают на существующие файлы.

**Готово:** typecheck, lint, format:check, `npm test` 145 / 2615, интеграционный тест сборки
зелёный; гейт живьём на `out/` — спайком (адрес на схеме, стартовый экран, шрифты, миниатюры и
страницы, консоль без ошибок), dev-сервер — `http://localhost:5173/` как раньше. Коммит
`fix(b-29): U1 …` (`142a01f`).

### U2. Оставшиеся fuses — ✅ зелёный

`electron-builder.yml`: `enableCookieEncryption: true`, `enableEmbeddedAsarIntegrityValidation:
true`, `grantFileProtocolExtraPrivileges: false` к прежним четырём. Тест
`test/tooling/electron-builder.test.ts` держит ровно полный набор (выпавший или изменённый fuse
роняет тест), `asar: true`, отсутствие `disableAsarIntegrity` и распаковку `sharp`; YAML
разбирается узко, без библиотеки — блок плоский и наш.

Гейт на настоящем exe (`npm run dist`, `release/win-unpacked/duplexnt.exe`):

- `npx @electron/fuses read` (1.8.0): все семь fuses в ожидаемых значениях; строка
  `undefined is Enabled` — слот, которого версия 1.8.0 не знает, не ошибка (план это
  предупреждал). electron-builder печатает «updating asar integrity executable resource» и
  «signing with signtool.exe» — подписи нет, строка от сборщика без сертификата безвредна;
- **`--user-data-dir=<временный каталог>` упакованное приложение честно принимает**: `data/`,
  `session`, кэши Chromium легли во временный каталог; листинг настоящего `%APPDATA%\duplexnt`
  (192 записей, размер и mtime) до и после — без изменений. Это и есть рецепт для U3 и U9;
- CDP на упакованном: адрес на схеме, шрифты и ассеты из `app.asar` читаются `fs` при включённой
  проверке целостности, два прохода на эмуляторе — миниатюры строит `sharp` из
  `app.asar.unpacked`, ошибок CSP и консоли нет;
- подменённый `app.asar`, два варианта: **пересобранный архив** с изменённым `index.html` —
  `FATAL … Integrity check failed for asar archive entry '<header>'` до окна, процесс не
  поднялся; **байты `index.html` внутри архива** при прежнем заголовке — `ASAR Integrity
Violation: got a hash mismatch` при чтении файла, выход с кодом 1, окна нет. Попутно для U3:
  в этом варианте `DevTools listening` печатается **раньше**, чем main дочитал файлы, — порт
  Chromium открывает до окна, и замер в U3 нужен именно про «до первого JS».

**Готово:** typecheck, lint, format:check, тесты зелёные. Коммит `fix(b-29): U2 …` (`9d2f413`).

### U3. Закрытие отладки в упакованном приложении — ✅ зелёный

`src/main/shell/debug-guard.ts`: `installDebugGuard(app, exit)` — первое действие main, до
каталога данных, блокировки экземпляра и `ready`; упаковано и есть `--remote-debugging-port`
(в любой форме, `=0` тоже) или `--remote-debugging-pipe` → строка в stderr и `exit(1)`.
Инъекция `app` структурно и `exit` отдельно (как `installShortcutGuard`), модуль без Electron.

**Отклонение от плана (осознанное):** выход — `process.exit(1)`, а не `app.exit`. Главный
скрипт выполняется в `PostEarlyInitialization`, обработчик DevTools Chromium поднимает позже, в
`PreMainMessageLoopRun`; `app.exit` до `ready` доехал бы до цикла сообщений и, возможно, до
порта, а немедленный выход не даёт ему открыться вовсе. Это подтвердил замер ниже.

`web-preferences.ts`: `devTools: !isPackaged` — закрытый список ключей в тесте расширен.
Шаблон смоука: консоль, DevTools и CDP — только у `out/` и dev-сервера; установленное
приложение и `win-unpacked` проверяются по поведению.

**Замер на упакованном exe** (`npm run dist`, опрос `/json/version` каждые 3 мс от `spawn` до
выхода, `ELECTRON_RUN_AS_NODE` снят, отдельный `--user-data-dir`, одного экземпляра рядом нет):

| Запуск                         | Выход                                   | Порт открывался  | «DevTools listening» |
| ------------------------------ | --------------------------------------- | ---------------- | -------------------- |
| `--remote-debugging-port=9274` | 1, 3,2 с¹                               | нет (204 опроса) | нет                  |
| `--remote-debugging-port=0`    | 1, 215 мс                               | нет (15 опросов) | нет                  |
| `--remote-debugging-pipe`      | 1, 214 мс                               | нет (15 опросов) | нет                  |
| контроль без ключа             | окно «Duplexn't» через 12 с ещё открыто | нет              | нет                  |

¹ Холодный старт exe; дальше ~215 мс. Итог: **порт не слушает всё время запуска** — риск
«Chromium открывает порт раньше кода приложения» не сработал, R6 и AE5 выполнимы в своей
формулировке. На `out/` (не упаковано) CDP работает как раньше — спайк U1 перегнан после
сборки со стражем: адрес на схеме, миниатюры, консоль чистая (R7).

**Готово:** typecheck, lint, format:check, `npm test` зелёные. Коммит `fix(b-29): U3 …`.

### U4. Страж приватности в worktree — ✅ зелёный

`scripts/privacy-guard.ts`: `GuardOptions.valuesRoot` (по умолчанию — `root`), список и сырые
снимки читаются оттуда; `resolveValuesRoot(root)` — родитель `git rev-parse --git-common-dir`
(`.git` в главном дереве, путь к `.git` главного — в worktree), вне репозитория — сам `root`.
CLI печатает «список значений — из главного дерева …», когда корни разошлись; падение `git
ls-files` вне репозитория — одна строка с причиной и код 1, а не стек. Импорты по-прежнему
только `node:*`. Тесты (B-28): настоящий временный репозиторий с `git worktree add` и
отдельным процессом Node, как зовёт hook, — находка в worktree с кодом 1; `--staged` видит
только застейдженное; чистый клон без списка — код 0 и «списка значений нет»; каталог вне git —
код 1 с вопросом «это git-репозиторий?».

**Гейт живьём:** worktree этой ветки во временном каталоге, `npm install` (531 пакет, `prepare`
→ `.husky/_`), файл с настоящим значением из списка → `git commit` остановлен хуком:
«из главного дерева», три находки `known-value`, `husky - pre-commit script failed (code 1)`.
Граница, записанная планом: **без `npm install` в worktree каталога `.husky/_` нет, и хук не
запускается** — `core.hooksPath` относительный и ищется от рабочего дерева. Worktree и ветка
сняты после проверки.

**Готово:** typecheck, lint, format:check, тесты и полный прогон `node scripts/privacy-guard.ts`
зелёные. Коммит `fix(b-29): U4 …` (`d72c398`).

### U5. Условия ADR 0008 по `sharp` — ✅ зелёный

Worst-case на текущем коде (`vitest run --project worst-case --no-file-parallelism`, 3 файла /
5 тестов зелёные, соседей нет): чанк коррекции 600 dpi цвет p50 15,1 / p95 15,8 / max 23,4 мс
(порог p95 30, max 100); паузы цикла max 54,8, p95 16,1 мс; RSS сверх базы 600 МБ (< 700);
серия из 15 страниц — пик 663 МБ, в конце 95 МБ. Ни один триггер не сработал, вынос `sharp`
не делается. ADR 0008 получил амендмент 2026-11-02 с таблицей и исправленное противоречие:
«Последствия» говорили о паузе очереди на время прохода, тогда как A/B U1 (журнал 0023) её
снял — теперь строка говорит, что очередь работает и во время прохода.

**Открыто для автора (не условие производительности):** байты JPEG от сканера — от чужого
устройства — разбираются `sharp` в main; есть предел пикселей и срок `processImage`, изоляции
нет. Амендмент записывает риск и два исхода: принять до жалоб или пункт бэклога на изоляцию
декода. Решение — на закрытии B-29 (U10).

**Готово:** worst-case зелёный, документы. Коммит `docs(b-29): U5 …`.

### U8. Интерфейс подтверждения — ✅ зелёный

- `DeviceModal.tsx` по handoff'у (вариант 1b): ответ `confirmation` открывает шаг — список и
  «Дополнительно» не рендерятся (в jsdom внешний CSS не грузится, `display: none` из handoff'а
  тест не увидел бы; поведение то же), поле адреса `disabled` с прежним вводом, карточка
  `role="alertdialog"` с `aria-describedby` (текст, «ЗАМЕНИТ», строка цены — только когда она
  есть). Цена — по флагам ядра, не по экрану: `awaitingBacks` → `costFlip`, иначе
  `interruptedPass` → `costInterrupted`. Фокус на «Отмене» при входе в шаг; «Отмена» в шаге —
  назад к вводу, `cancelConnect` гасит пробу, фокус в поле; Esc — закрытие модалки.
  Подтверждение шлёт только токен, одно на шаг (`confirming`), `aria-busy` и «Подключаемся
  к …» в статусе; отказы — `confirmStale` / `confirmBusy` своим текстом, прочие — через
  `device.connectFailed`; все возвращают к вводу. `onConnected(label, settingsSaved)` — `App`
