## Сессия 4 — история, новый репозиторий, черновик релиза

### U8. Переписывание истории и новый репозиторий — ⏳ в работе

Предусловия: `git-filter-repo` поставлен `python -m pip` в Python 3.14 (теперь системный `pip` —
его же); как git-команда не виден (Scripts не в PATH), все вызовы — `python -m git_filter_repo`.
Токен `gh` без `delete_repo` — обновление по браузерному потоку делает автор (нужно к U11).
Рабочее дерево чистое, refs — только `main`, stash пуст, тегов нет. Ключа подписи SSH в git не
настроено — тег в U10 будет просто аннотированным.

Разведка по исходной истории (скрипт проверки всех уникальных блобов и `%B` логикой стража):
3616 блобов (из них 83 бинарных — только JPEG/WOFF2/WEBP/ICO/BMP и одна версия
`src/core/escl/jpeg-markers.ts` с NUL-байтом, проверена отдельно — чистая), 599 коммитов; по
списку значений — 199 совпадений двух значений (техбаза, UUID и адрес), личный email — только в
полях автора/коммитера (1174 поля), в содержимом блобов — ни разу; пути машины — рабочий каталог
в 28 версиях техбазы, URL `/@fs/…` в 0019 и `dev-css-urls`, старый блоб плана B-40 (там же
единственное упоминание имени пользователя, в примере grep). Все `C:\Users\…` в истории —
вымышленные (макеты, handoff'ы, тест моста). Паттерновый проход без `PATTERN_SCOPE` — только
синтетические значения тестов и макетов (частные адреса из тестов стража и архивного макета,
UUID-заглушки, вымышленные имена хостов из тестов): разобраны, в список не добавлялись.

Файл замен — 149 строк из 78 значений списка (по типу → заглушка стража, три формы), email →
noreply, корневой каталог проектов автора в обеих формах слэшей → `X:\repo` / `X:/repo`,
`Users\<имя>` → `Users\author`;
mailmap — одна строка. Bundle `--all` старой истории: SHA-256
`37d5e60e074e3d22dc4cc9853a1ce158164596cf7436a587f7ac0a0a5a8d04c2`, `bundle verify` ok. N = 599,
`ls-tree -r main` — 771 строка зафиксирована.

Сухой прогон на клоне `--no-local` (~25 с) и боевой на втором таком же клоне дали **побайтно
одинаковый результат**: `main` → `139ed80`, `commit-map` совпадают. Проверки на боевом клоне:
599 коммитов; `%ae`/`%ce` — только noreply; `ls-tree -r main` совпал с зафиксированным целиком
(ни одной ложной замены на вершине); `Co-Authored-By` — 562 до и после; проход по списку
значений по всем блобам и `%B` — 0, личный email — 0, имя и пути машины — 0; паттерновый проход
— тот же синтетический набор. Хэши в сообщениях коммитов filter-repo перевёл сам
(`suboptimal-issues`: два ложных hex-токена `e3b0b198`, `20261021` оставлены как есть — это не
хэши). Первый изменённый коммит — самый первый в истории (email автора).

Правка хэшей в доках по `commit-map`: 289 токенов в 46 файлах, неоднозначных старых и новых
префиксов 0, один токен вне карты — `abc1234` из шаблона; в diff ровно 289 заменённых токенов,
234 строки, CRLF-файлов нет; prettier чист. `npm ci`, `npm test`: первый прогон сразу после
установки упал одним тестом `pass-service.straighten.test.ts` (нагрузка диска после `npm ci`),

видно. Полный страж по дереву клона со скопированным списком — «чисто (все отслеживаемые
