# Шрифты в dev: апостроф в пути проекта ломал `@font-face` (журнал)

Баг найден по ходу B-12. Плана нет: исправление в один шаг, без развилок. ADR нет.

## Симптом

Автор видел в интерфейсе «шрифт с засечками» в кикерах, заголовках разделов, модалках, на чипе
«+ Новый документ». В установщике (`release/win-unpacked`) и на странице сравнения засечек не
было, а в `npm run dev` — были.

## Причина

Замер CDP (`CSS.getPlatformFontsForNode`):

- в сборке (`out/`, `app.asar`) — вшитые IBM Plex Mono и Golos Text;
- в dev — системные **Courier New** (моно с засечками) и **Segoe UI**.

В dev у всех `@font-face` из Fontsource не было `src`. Vite под dev-сервером переписывает
`url(./files/x.woff2)` в `url(/@fs/X:/repo/Duplexn't/node_modules/…)` без кавычек, а апостроф
в имени папки проекта делает такой `url()` некорректным. Браузер выбрасывает всё объявление
`src`, файл шрифта не запрашивается, и срабатывает запасной шрифт из токенов: `monospace` в
Electron на Windows — Courier New, `system-ui` — Segoe UI. В сборке ассеты лежат в
`out/renderer/assets/` с хэшем в имени, путь без апострофа, поэтому установщик был в порядке.

Следствие: все приёмки, которые автор смотрел в `npm run dev`, шли на системных шрифтах вместо
шрифтов макета.

## Исправление

- `tooling/dev-css-urls.ts`: плагин Vite только для `serve`, `enforce: 'post'`. В CSS-модулях
  кодирует апостроф в путях `url(/@fs/…)` как `%27`, dev-сервер декодирует путь перед чтением
  файла. Подключён в `electron.vite.config.ts` рядом с CSP.
- Тест `test/tooling/dev-css-urls.test.ts`: апостроф кодируется в woff2 и woff; кавычки вне
  адреса и адреса не из `/@fs/` не трогаются.
- Проверка в dev (CDP):
  - 12 начертаний `loaded`;
  - заголовок и кнопки — Golos Text;
  - кикер и номер миниатюры — IBM Plex Mono.

## Попутно

Значок «↺» в кнопке «↺ Новое сканирование» рисуется системным Cambria Math: глифа нет в Golos
Text. Так и в сборке. Не баг этого исправления — на заметку для B-12.
