# Хвосты `window.json.*.tmp` в корне данных (журнал)

Баг из [bugs.md](../bugs.md): у автора за день 2026-11-03 в `%APPDATA%\duplexnt\data` скопилось
десять `window.json.<hex>.tmp` — два пустых, остальные с полным содержимым. Плана нет: помощник в
атомарной записи, две строки в хранилищах, выход в `main`. ADR нет. Ветка `fix/window-tmp-sweep`,
прецедент формы — журналы 0038 и 0039. Попутно — правка русской копии `setup.lead` автором.

## Причина

`trackWindowState` пишет состояние окна на событии `close` (`flush`), а `window-all-closed` тут же
зовёт `app.quit()`: процесс выходил посреди атомарной записи — после `open` (пустой хвост) или
после `fsync`, до переименования (хвост с полным содержимым). `writeAtomic` убирает свой temp
только при ошибке, а не при обрыве процесса; сверка при запуске чистит временные файлы в
`session/` и `derived/`, корень данных не обходит — хвосты копились по одному-два на запуск.

## Что сделано

1. **Выход ждёт запись окна** (`src/main/index.ts`): последняя `windowState.save` хранится в
   `windowStateSettled`; `window-all-closed` зовёт `app.quit()` после неё, но не дольше
   `WINDOW_STATE_QUIT_LIMIT_MS = 2000` — файл окна удобство, виснуть из-за него нельзя.
2. **Хранилища корня убирают свои хвосты при открытии**: `removeStaleTemps(path)` в
   `atomic-file.ts` — только имена `<файл>.<12 hex>.tmp` рядом с файлом, соседи (в том числе
   `*.unreadable-*` и хвосты других файлов) не трогаются, неудалённый хвост не ошибка. Вызов в
   `openWindowStateStore` и `openSettingsStore` до чтения файла. Тест в `window-state.test.ts`.
3. **Живая проба на `out/`** (изолированный `DUPLEXNT_USER_DATA`, крестик через `WM_CLOSE` по
   заголовку окна, четыре запуска): после фикса — выход через ~0,55 с, в каталоге только
   `window.json`, процессов не осталось. Проба «до» (та же сборка с `index.ts` из `main`): четыре
   закрытия — четыре хвоста с полным содержимым, а `window.json` не записан ни разу: старая версия
   на закрытии крестиком положение окна вообще не сохраняла, только после паузы при
   перетаскивании. В каждом раунде ровно один хвост — предыдущий убран при открытии (пункт 2).
4. **Копия `setup.lead`** (автор): «Сначала лицевые стороны листов. Потом оборотные — все разом,
   так, как они вышли из лотка. Приложение само сопоставит обороты с лицами.» Английская —
   «First the front sides of the sheets. Then the backs — all at once, just as they came out of
   the tray. The app matches the backs to the fronts on its own.» Референс перегенерирован.

Хвосты у автора: уберутся сами при первом запуске новой версии (пункт 2), руками ничего делать
не нужно.
