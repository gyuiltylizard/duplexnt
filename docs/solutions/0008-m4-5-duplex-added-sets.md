по ходу сессий. Финализируется на закрытии (`status: done`).

версии 7.

## Сессия 1 — журнал v7, политика ролей, сборка с чередованием

### U1. Shared-типы и журнал v7 — ✅ зелёный

`src/shared/snapshot.ts`: `PASS_KINDS` + `addedFronts` / `addedBacks`; `BACKS_DECISIONS`;
`PassSnapshot.pair` / `backsDecision`; `PassesByKind.addedFronts` / `addedBacks`; `AddedSet` и
`addedSetsOf(passes, hasPages)` — единственное место нумерации «ДN» (по номеру прохода лиц среди
`added` ∪ `addedFronts`; осиротевшие обороты в наборы не входят). `src/shared/bridge.ts`:
`AddedPassIntent.kind: 'added' | 'addedFronts'`.

`src/core/storage/journal.ts`: `JOURNAL_VERSION = 7`; проход v7 — `passSchema` с тремя `refine`
(якорь у `added`/`addedFronts`; `pair` ⇔ `addedBacks`; `backsDecision` ⇔ `addedFronts`); схема
журнала — `pairsHold` (оборотов набора со страницами на одни лица ≤ 1; ссылка на существующий
проход ведёт к `addedFronts`, на отсутствующий — допустима: осиротевшие). Проходы v4–v6 —
`passV6Schema` с прежними тремя ролями; `journalV6Schema` + `upgradeToV7` (дефолты `null`) в
цепочке чтения. `pendingPairOf(journal)` → `{ set, fronts, expected } | null` из фактов (лица
набора со страницами, завершённые или принятые, `none`, без оборотов со страницами);
`nextKindOf`: `fronts` → `backs` → `addedBacks` при ожидающей паре → `added`;
`addedSetsOfJournal`.

`reconcile.ts` `adopt`: очередь `addedBacks` для усыновлённого по файлам прохода заменяется на
`added` (пара без ссылки и ожидаемого числа не создаётся, R22), `pair`/`backsDecision` — `null`.
`session-store.ts`: снимок несёт новые поля; `beginPass` пишет `backsDecision: 'none'` лицам набора
(`pair` оборотов набора — U2). `App.tsx`: тип `Launch.kind` расширен до `AddedPassIntent['kind']`
(поведение — U6).

Тесты: новые `journal.v7.test.ts` (форма, согласованность полей с ролью, чтение v6, выводимое —
ожидание пары и очередь, нумерация «ДN»), `src/shared/snapshot.test.ts` (`passesByKind`,
`addedSetsOf`), `reconcile.pairs.test.ts` (v6 → v7 идемпотентно, пара и осиротевшие обороты
переживают сверку дословно, усыновление при ожидающей паре — `added`). Фикстуры v1–v5 в
`journal.test.ts` / `reconcile.test.ts` строятся от прохода v6 без полей пары; маркер «новее» —
8/9. Фикстуры проходов в тестах renderer и хранилища получили `pair: null, backsDecision: null`.

**Готово:** typecheck, lint, format:check, node + jsdom, интеграция зелёные.
Коммит `feat(m4.5): U1 …` (`9efc2d9`).

### U2. Политика проходов и команды решения набора в хранилище — ✅ зелёный

Вынос: `src/core/storage/pass-policy.ts` — `planPass`, `checkIntent`, `resumable`, `locatePass`
как чистые функции над `PolicyState { journal, incompatible }`; `PassPlan` получил `pair`
(номер прохода лиц у оборотов набора). `src/core/storage/rebase.ts` — `withRebasedEdits`
(нормализация правок) переехала из хранилища; `isVacant`, `passSnapshotsOf`, `NOTHING_LOST` —
в `journal.ts`. `session-store.ts` — 999 строк (ориентир выдержан). `modeOf` сборки
экспортирован: `checkIntent` отказывает `pairInSets` двустороннему набору в режиме раздельных
наборов.

Команды: `beginPass` оборотов набора пишет `pair` из `pendingPairOf` того же журнала;
`declineBacks()` адресуется ожидающему набору (`declined` на лицах, флаг сессии не трогает,
пустой прерванный проход оборотов набора уходит, как у основной пачки), иначе сессии;
`keepSetBacks(set)` / `rescanSetBacks(set)` — по номеру «ДN» через `addedSetsOfJournal`, отказы
`noPendingSet` / `setNotMismatched`; отброс прохода оборотов — пометки об удалении всех его
сегментов в журнале раньше файлов, затем `removeMarked` по каждому префиксу (страницы,
миниатюры, кэш оценок), правки по мёртвым ключам чистит нормализация в `commit`;
`acceptPass` прерванных оборотов набора с M ≠ F ставит `kept`; `setEdits(edits, rotate180)` —
карта «номер прохода оборотов → флаг», не названные — `false`, чужой номер / не обороты / проход
без страниц — `noBacksPass` целиком.

**Отклонение от плана (осознанное):** добавлен конфликт `pairPending` — пока набор ждёт
обороты, намерение любого нового набора отклоняется ядром (в UI недостижимо: `flip` набора
впереди редактора; без отказа две ожидающие пары дали бы два `flip` подряд). Локаль:
`errorReasons.sessionConflict.{noPendingSet,setNotMismatched,pairInSets,pairPending}`.

**Временный мост:** служба проходов до U4 переводит булев флаг команды `setEdits` в карту
`{ [backs.number]: flag }` — поведение моста M3 не меняется; U4 меняет схему и `SetEditsRequest`.

Тесты: новые `pass-policy.test.ts` (очередь пары, намерения, `pairPending`, `pairInSets`,
режим отказа, `locatePass`), `session-store.pairs.test.ts` (очередь, «Остановить» на оборотах
набора до первой страницы, отказ, «оставить», принятие коротких, «переснять» с чисткой кэша и
правок и с падением удаления файла — сверка дочищает, карта флагов). В
`session-store.flags.test.ts` флаг `setEdits` стал картой `{ 2: true }` / `{}`, ожидания
`planPass` получили `pair: null`.

**Готово:** typecheck, lint, format:check, node + jsdom, интеграция зелёные.
Коммит `feat(m4.5): U2 …` (`be049d8`).

### U3. Сборка: чередование блока, отчёт по наборам, детектор, зеркало — ✅ зелёный

`src/shared/snapshot.ts`: `pendingSetOf(passes, hasPages, stateOf)` — одно правило «набор ждёт
обороты» для журнала (`pendingPairOf` теперь над ним), сборки и renderer; `AddedSetReport` и
`AssemblyReport.sets` / `pendingSet`; `AssembledPage.sheet` у страниц набора — лист внутри набора
при чередовании, `null` в подблоках (потребители читают `addedSet` раньше `sheet`).

`src/core/scan/assembly.ts`: `BasePage.rotate180` вместо `base.rotateBacks` (угол по флагу
прохода страницы, `hasEdits` — по любому повёрнутому проходу оборотов); `placeAdded` ставит блоки
по `addedSetsOf` (нумерация «ДN» одна с журналом), блок пары — `setBlockOf`: чередование при
равном числе страниц (оборот i = `backs[F−1−i]`), иначе подблоки «лица в порядке сканирования,
обороты порядком документа»; `settled`-проекция идущих оборотов набора — всегда подблоки (R12);
`placeOrphans` — обороты набора без лиц в конец стороной «оборот» без тега; `assembledBase` —
набор целиком вне записи встаёт блоком по якорю лиц (AE13), набор, которого запись коснулась, —
по одной странице за предыдущей своего прохода; `passReport` — `sets` и `pendingSet`. Режим
сессии (`modeOf`) пары не трогают: несовпадение набора живёт в блоке. `blank-flow.ts`
`pagesToScore` и `pass-service.ts` `detectsBlank` — роли `backs` и `addedBacks`; `blankFlagOf`
без изменений (`ofBacks` по роли), в подблоках несовпавшего набора `hide` скрывает.

Зеркало `src/renderer/src/state/assembly-fixture.ts` переписано теми же правилами
(`setBlockOf`, `placeAdded` с `include`, `placeOrphans`, `setsReportOf`, угол по проходу
страницы); guard-таблица `test/guards/assembly-fixture.test.ts` — +15 сценариев без правок
(чередование, подблоки, прерванные, принятые, ожидание, отказ, повороты порознь, три набора с
якорем внутри блока пары, осиротевшие, без якоря, пустые лица, «собрано» блоком и по одной
странице, набор рядом с режимом наборов), +3 с правками, +3 с флагами пустых. Сошлось с ядром с
первого прогона. `test/support/assembly.ts`: `setFrontsOf`, `setBacksOf`.

Тесты: новый `assembly.pairs.test.ts` (AE1, AE2, AE11, AE13, ожидание, нумерация, осиротевшие,
флаг 180° порознь, `settled`, «каждая страница ровно один раз»), `assembly.blank.test.ts` —
describe про обороты набора (AE7, AE17, подблоки, пометка «не пустая», режим наборов сессии).
Литералы `AssemblyReport` в тестах renderer получили `sets: []`, `pendingSet: null`.

**Готово:** typecheck, lint, format:check, node + jsdom, интеграция зелёные.
Коммит `feat(m4.5): U3 …`.

## Сессия 2 — служба, мост, схемы; handoff

### U4. Служба проходов, мост и схемы команд — ✅ зелёный

`src/core/scan/pass-service.ts`: `setEdits(edits, rotate180)` принимает карту флагов (временный
перевод из U2 снят); `keepSetBacks(set)` / `rescanSetBacks(set)` с гардами `saving` и
`passRunning`, после отброса — `blank.prune()` (оценки отброшенных страниц уходят) и снимок;
`detectsBlank` — роли `backs` и `addedBacks` (с U3). `startPass` ничего не потребовал: роль,
`expected` и `pair` приходят из `planPass` (U2), `Run.kind` — `addedFronts` / `addedBacks`.
Мост: `SetEditsRequest.rotate180` — карта, `SetDecisionRequest { set }`, команды `keepSetBacks` /
`rescanSetBacks` в `BridgeCommands` и `BRIDGE_CHANNELS` (preload и main регистрируют по таблице);
схемы — `kind: z.enum(['added', 'addedFronts'])`, `rotate180Schema` (record с ключами-номерами
проходов, потолок `MAX_PASS_NUMBER` и `MAX_EDIT_ITEMS`), `setDecisionRequestSchema`; обработчики
через `done`. Renderer до U7: `useEditorEdits.send` переводит булев флаг истории в карту
`{ [backs]: true }` / `{}`; фикстуры `applied` / `lastSent` принимают форму моста.

**Отклонение от плана (осознанное):** в `settleSegment` условия роли нет и не было — ноль страниц
нового прохода любой роли отбрасывается общим правилом (R9), прерванные обороты набора без страниц
снимаются и набор снова ждёт; расширять нечего, тест закреплён в `pass-service.pairs.test.ts`.

Тесты: новые `pass-service.pairs.test.ts` (намерение лиц набора, обороты набора «из F» и отказ
до первой страницы, AE14 на подставном транспорте, `otherScanner` для досканирования прохода
набора, `keepSetBacks` / `rescanSetBacks` через службу и `passRunning`), `blank-flow.test.ts`
(`pagesToScore`); `handlers.test.ts` — намерение `addedFronts`, отказ `addedBacks`, схема карты
флагов (мусор), команды решения набора. Ожидания `setEdits` в тестах renderer и интеграции
переведены на карту (`{}` / `{ 2: true }`, AE6 — `{ 3: true }`).

**Готово:** typecheck, lint, format:check, node + jsdom, интеграция зелёные.
