## Сессия 1 — журнал v7, политика ролей, сборка с чередованием

### U1. Shared-типы и журнал v7 — ✅ зелёный

`src/shared/snapshot.ts`: `PASS_KINDS` + `addedFronts` / `addedBacks`; `BACKS_DECISIONS`;
`PassSnapshot.pair` / `backsDecision`; `PassesByKind.addedFronts` / `addedBacks`; `AddedSet` и
`addedSetsOf(passes, hasPages)` — единственное место нумерации «ДN» (по номеру прохода лиц среди
`added` ∪ `addedFronts`; осиротевшие обороты в наборы не входят). `src/shared/bridge.ts`:
`AddedPassIntent.kind: 'added' | 'addedFronts'`.

`src/core/storage/journal.ts`: `JOURNAL_VERSION = 7`; проход v7 — `passSchema` с тремя `refine`
(якорь у `added`/`addedFronts`; `pair` ⇔ `addedBacks`; `backsDecision` ⇔ `addedFronts`); схема
журнала — `pairsHold` (оборотов набора со страницами на одни лица ≤ 1; ссылка на существующий
проход ведёт к `addedFronts`, на отсутствующий — допустима: осиротевшие). Проходы v4–v6 —
`passV6Schema` с прежними тремя ролями; `journalV6Schema` + `upgradeToV7` (дефолты `null`) в
цепочке чтения. `pendingPairOf(journal)` → `{ set, fronts, expected } | null` из фактов (лица
набора со страницами, завершённые или принятые, `none`, без оборотов со страницами);
`nextKindOf`: `fronts` → `backs` → `addedBacks` при ожидающей паре → `added`;
`addedSetsOfJournal`.

`reconcile.ts` `adopt`: очередь `addedBacks` для усыновлённого по файлам прохода заменяется на
`added` (пара без ссылки и ожидаемого числа не создаётся, R22), `pair`/`backsDecision` — `null`.
`session-store.ts`: снимок несёт новые поля; `beginPass` пишет `backsDecision: 'none'` лицам набора
(`pair` оборотов набора — U2). `App.tsx`: тип `Launch.kind` расширен до `AddedPassIntent['kind']`
(поведение — U6).

Тесты: новые `journal.v7.test.ts` (форма, согласованность полей с ролью, чтение v6, выводимое —
ожидание пары и очередь, нумерация «ДN»), `src/shared/snapshot.test.ts` (`passesByKind`,
`addedSetsOf`), `reconcile.pairs.test.ts` (v6 → v7 идемпотентно, пара и осиротевшие обороты
переживают сверку дословно, усыновление при ожидающей паре — `added`). Фикстуры v1–v5 в
`journal.test.ts` / `reconcile.test.ts` строятся от прохода v6 без полей пары; маркер «новее» —
8/9. Фикстуры проходов в тестах renderer и хранилища получили `pair: null, backsDecision: null`.

### U2. Политика проходов и команды решения набора в хранилище — ✅ зелёный

Вынос: `src/core/storage/pass-policy.ts` — `planPass`, `checkIntent`, `resumable`, `locatePass`

**Отклонение от плана (осознанное):** добавлен конфликт `pairPending` — пока набор ждёт

`errorReasons.sessionConflict.{noPendingSet,setNotMismatched,pairInSets,pairPending}`.

**Временный мост:** служба проходов до U4 переводит булев флаг команды `setEdits` в карту

Тесты: новые `pass-policy.test.ts` (очередь пары, намерения, `pairPending`, `pairInSets`,

### Ревью сессий 1–2: simplify

Три ревьюера (reuse, quality, efficiency) по диффу U1–U4. Применено: предикаты ролей
`isBacksKind`, `isAnchoredKind`, `hasPages` и `SETTLED_STATES` в shared вместо пяти копий
(сборка, зеркало, хранилище, служба, журнал); `addedSetReportOf` — один маппинг отчёта набора для
ядра и зеркала; сборка считает `addedSetsOf` и карту проходов один раз на сборку (`SetsIndex`,
`passesOfSet`, `derivedOf`), `placeAdded` принимает уже отобранные наборы вместо `include`;
`mismatchedSetOf` — общий гард «Оставить» / «Переснять» в хранилище; `acceptPass` без вложенного
тернара; `PASS_KINDS_V4_TO_V6` / `passV4toV6Schema` по смыслу имени. Находка по поведению:
renderer до U7 слал карту флагов только для основной пачки, и любая правка обнуляла бы флаги
оборотов наборов — теперь `useEditorEdits.send` несёт текущие флаги всех проходов оборотов.
Отклонено: `busy()`-помощник в службе (общий стиль файла), `toReversed` (цель сборки не
проверялась), `pair` из `plan` в `beginPass` (меняет API хранилища), объединение зеркала с ядром
(граница слоёв, guard). Эффективность: ничего квадратичного по страницам, последовательный
`removeMarked` оставлен (как у «Остановить»). Падение `blank-backs.emulator` AE7 при полном
прогоне не воспроизвелось отдельно — тайминг эмулятора (известная нестабильность M4).

### Ревью сессий 1–2: код-ревью

Девять персон (correctness, adversarial, testing, maintainability, project-standards,
reliability, api-contract, agent-native, learnings), шесть независимых валидаций. Вердикт —
«готово с правками», правки применены:

- **Пустой прерванный проход оборотов набора + «Оставить как есть»** (три персоны, P1): ставил
  `kept` набору без оборотов — `flip` не возвращался, «переснять» отказывал. Теперь `kept` только
  у прохода со страницами; пустой принятый — набор ждёт дальше (тест в `session-store.pairs`).
- **Очередь при ожидающем наборе** (adversarial, проверено напрямую): `nextKindOf` давал обороты
  основной пачки раньше ожидающего набора, когда те не решены (достижимо после принятых коротких
  лицевых, M3.5) — набор теперь раньше очереди M2 (R11); тесты в `journal.v7` и `pass-policy`
  перевёрнуты/добавлены.
- **`settled` в режиме «собрано»** (correctness, проверено напрямую): `assembledBase` не передавал
  проекцию в блок набора — передаёт; тест в `assembly.pairs`.
- **Ориентир размера файлов** (maintainability, подтверждено как P2 — ориентир плана, не правило):
  `session-store.ts` 1003 → 927 (команды решения набора вынесены в
  `src/core/storage/set-decisions.ts` с контекстом `{ journal, commit, settleReads, removeMarked }`),
  `pass-service.ts` 1003 → 999 (`busyConflict()` — общий гард `saving` / `passRunning`).

Отклонено валидацией: повтор «Обороты не нужны» на наборе (недостижимо до U6 — U6 блокирует
кнопку в полёте или даёт команде адресата); деление `reconcile.test.ts` / `pass-service.test.ts`
(механическое касание фикстур, новые тесты ушли в новые файлы по плану). Отложено в U8: тест
приёмника «страницы оборотов набора получают оценку детектора» (сценарий плана U4; юнит-уровню
нужен транспорт со страницами — покроет эмулятор `added-pair` с режимом «Скрывать»). Остаточные
риски на U6/U7: модалка набора — только при завершённых оборотах (`keepSetBacks` принимает и
прерванный проход); «Вернуть» до U7 не сбрасывает флаги оборотов наборов. Артефакт ревью:
`/tmp/compound-engineering/ce-code-review/20261023-173757-bb79b8dc/review.json`.

## Сессия 3 — экраны потока пары, модалка набора, карточки, тумблер

### U6. Renderer: экраны потока пары, `App`, модалка набора, карточки — ✅ зелёный
