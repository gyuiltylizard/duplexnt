# Скрытый хвост перешагивал границу документа (журнал)

Остаточный риск ревью M4 («скрытый хвост через разрез при броске „после“ ложится в следующий
документ», `solutions/0007`), решение автора 2026-10-27: хвост обрывается на границе. Плана нет
— исправление в одну функцию, без развилок. ADR нет.

## Симптом

Пока пустые обороты скрыты, скрытый оборот за показанной страницей — её хвост (R12 M4): едет при
переносе, удалении, «Выделить в документ», а бросок «после» страницы встаёт за её хвостом.
Граница документов могла стоять между страницей и её скрытым оборотом — если её ставили при
показанных пустых, прямо перед пустым оборотом. Тогда бросок «после» последней видимой страницы
документа 1 вставал за хвостом, то есть уже в документе 2 — первой его страницей. Тем же путём
удаление последней страницы документа уносило скрытую первую страницу следующего.

## Исправление

- `withHiddenTails(keys, order, starts)` в `state/shown.ts`: хвост обрывается на позициях
  полной ленты, с которых начинаются документы. По умолчанию границ нет — прежнее поведение.
- `EditorScreen`: `withTails` передаёт начала документов сборки (`documentStarts`). Через эту
  обёртку идут перенос, группировка, удаление и якорь «после текущей» — правило одно на всех.
- UI_SPEC → «Скрытые хвосты (M4)» — хвост до границы.
- Тесты:
  - `shown.test.ts`: хвост до границы, граница сразу за страницей, ключ на границе;
  - `EditorScreen.blank.test.tsx`: разрез перед скрытым B3, бросок F3 «после» F1 — порядок
    `F1, F3, B1, B3, F2, B2`, документ 1 после снимка — `F1, F3`. Без исправления тест падает
    (мутационная проверка).
- Фикстура: `makeSnapshot` строит сборку без правок — для разрезов в снимке нужен
  `assemblyWithEditsOf`.
