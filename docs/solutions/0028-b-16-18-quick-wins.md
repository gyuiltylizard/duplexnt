## Сессия 1 — реализация

### U1. Склейка запросов снимка (B-16) — ✅ зелёный

`snapshot-store.ts`: `refresh()` под флагами `inFlight` / `dirty`, повтор ровно один — в
`finally` запроса, и на успех, и на отказ. Тесты переписаны под склейку: пять событий за один
запрос → два запроса всего; устаревший ответ на повтор отбрасывается; отказ с поднятым флагом
→ один повтор; StrictMode-переподписка во время полёта не даёт второго параллельного запроса —
ложится в тот же повтор (раньше тест ждал двух запросов сразу; событий между подписками повтор
не теряет). Весь jsdom-проект зелёный (54 / 830).

**Готово:** typecheck + lint + jsdom зелёные. Коммит `feat(b-16): U1 …` — `6400974`.

### U2. Замер коалесинга (B-16) — ✅

**Отклонение от плана (осознанное):** план задавал замер в `electron-vite dev` против
эмулятора с временным счётчиком в preload. CDP-харнеса в репозитории нет, прогон через GUI —
ручной и несравнимый между запусками; вместо него — временный интеграционный тест (не
закоммичен): настоящая `PassService` на эмуляторе, два прохода по 50 листов (лица, затем
обороты через `emulator.load`), поток уведомлений ядра снимается по `snapshots` обвязки
`connectService`, затем тот же поток (равномерно по времени прохода) проигрывается в старое
хранилище (запрос на каждое событие) и в новое, с заглушкой `getSnapshot` заданной стоимости.
Стоимость снимка — медиана `service.snapshot()` + `structuredClone` на сессии из 100 страниц.

| Что                                   | Значение                               |
| ------------------------------------- | -------------------------------------- |
| Событий ядра, проход лиц / оборотов   | 104 / 154 (на 50 листов каждый)        |
| Событий на страницу                   | 2,08 (лица), 3,08 (обороты: + пустота) |
| Снимок + clone, медиана, 100 страниц  | 0,35 мс (лица: 0,18 мс)                |
| Запросов, старое / новое, при 0,35 мс | 259 / 184 (−29 %)                      |
| Запросов, старое / новое, при 25 мс   | 259 / 82 (−68 %)                       |

Оговорки: эмулятор отдаёт лист за ~25 мс против ~10 с у ET-3850, то есть события в бою стоят
реже и склейка срабатывает лишь внутри «пачки» уведомлений одной страницы (приём → вердикты →
коррекция); перекос здесь — заглушка `levelWorker`, настоящее измерение ~200 мс на страницу
добавляет событие с задержкой. Дорогой снимок (25 мс) — модель сессии на сотни страниц с
миниатюрами и IPC; при дешёвом снимке выигрыш — только число IPC-кругов. Последний снимок
доезжает в обоих прогонах (`finalSeq` = число событий). Вывод: склейка безвредна и даёт
треть–две трети запросов; узкое место при дорогом снимке — сборка в main (кэш по `seq` —
кандидат в бэклог, Scope Boundaries плана).

**Готово:** числа здесь. Коммит `docs(b-16): U2 …`.

### U3. Тосты и тексты подключения и остановки (B-17: 1–3) — ✅

`App.tsx` `stopPass`: любой отказ — тост, `sessionCloseFailed` прежним текстом, остальные —
`toast.stopFailed` с причиной `errorTextInline`. `connectScanner` отвечает `ScannerInfo`
(`scannerInfoOf(storedScannerOf(connected))`, обработчик мимо `done`; `bridge.ts` — тип ответа);
`DeviceModal` отдаёт в тост имя из ответа, у безымянного — введённый адрес. Порт проверяется в
`submit` до команды — `device.address.invalidPort` в строке статуса. Грабли: фикстура `app-fixture`
и `CONNECTED` в тесте обработчиков отдавали `ok(undefined)` / без `capabilities` — обновлены.
Тест «другой отказ тоста не даёт» перевёрнут в «общий тост с причиной» (`sessionConflict`).
Коммит `9ced0fc`.

### U4. Папка сохранения не прочиталась (B-17: 4) — ✅

**Отклонение от плана (осознанное):** план ждал «отмена диалога оставляет подсказку», но ядро и
при отказе в диалоге возвращает свою папку (`canceled: true, folder`) — поле заполняется, и
подсказка снимается в обоих случаях; тест переписан под это. Состояние `folderUnknown` ставится
на отказ и на исключение `getSaveFolder`, запись не блокируется. Коммит `af8385f`.

### U5. Гарды редактора (B-17: 5–6) — ✅

Инспектор получил отдельный `notBlankLocked` (`locked || edits.busy`) — общий `locked` секции
выравнивания и «Вернуть» не тронут. `nearestShownDocument` в `shown.ts`; `unsplit` снимает все
разрезы до ближайшего видимого слева по убыванию индекса существующим `withoutCut`; `EditorRail`
показывает «✕» только при видимом слева; `EditorToolbar` считает N и M по документам с
`count > 0`. Тесты: `[F1 | B3 (скрыт) | F2 B2 F3 B1]` — «документ 2 из 2 · стр. 1 из 3», «✕»
перед третьим снимает оба разреза, имя первого, Ctrl+Z возвращает оба; первый документ из одних
скрытых — «✕» нет; кнопка «не пустая» выключена в полёте `setEdits` (`deferredSetEdits`). UI_SPEC,
раздел ленты. Коммит `3c17147`.

### U6. Оценки пустоты в `settleDerived` (B-18) — ✅

`BlankScores.abort()` / `settle()` по образцу `skew-scores`: сигнал берётся при `ensure`, в
`detect` отмена проверяется до чтения, после чтения и после детектора — до `mkdir` и записи кэша
(через функцию `aborted()`: сужение типа после `await` считало флаг неизменным — ловил lint).
`settleDerived` отменяет и ждёт оценки вместе с перекосом и очередью; `resumeDerived`
перезапускает `detectBlank` для `pagesToScore` — находка ревью плана: иначе после
`sessionCloseFailed` страницы висели бы `pending` до перезапуска. Тесты ядра
(`test/integration/blank-scores.test.ts`): отмена посреди детектора — ни кэша, ни вердикта,
следующий `ensure` оценивает заново; отмена до старта в лимитере. Эмулятор: «Новое сканирование»
при медленном детекторе — `derived/<id>` нет и через 700 мс; `closeSession` с `EPERM` на
переименовании (`interceptFs`) → `pending` возвращается к 0, PDF пишется. Коммит `3c6e1b0`.

### Ревью ветки (code-review, medium) — применено

- **Слияние через невидимый документ с split-бара и клавиши:** «✕» для первого документа из одних
  скрытых уже не показывался, но split-бар и клавиша вели в тот же `unsplit`, где запасной ход
  `docIndex − 1` сливал видимый документ с невидимым — пользователь видел бы лишь смену имени.
  Теперь без видимой цели `unsplit` ничего не делает.
- **Проверка порта в пяти местах литералом 65535** → `PORT_MAX` / `isValidPort` в
  `src/shared/bridge.ts`; схема команд, разбор адреса, схема профиля и модалка — через них.
- **`snapshot-store`:** повтор после ответа только при живой подписке (без подписчиков — некому
  показывать; переподписка перечитывает сама); тест.
- **`SaveModal`:** доменный отказ `getSaveFolder` теперь в логе, как и исключение.
- **Тест эмулятора B-18:** вместо `delay(700)` — `await service.settleDerived()`, детерминированно.

**Отклонено:** (а) собирать «видимость» документов один раз в `shownDocumentsOf`
(`shownIndex`) вместо трёх мест — верно по сути, но документов единицы, O(n²) не ощутим, а
общая функция `nearestShownDocument` уже одна; вернуться, если появится четвёртое место;
(б) брать `ScannerInfo` для ответа `connectScanner` из снимка службы — отображение
`scannerInfoOf(storedScannerOf(connected))` и так единственное (им же пользуется
`scanner-slot`), дублирования логики нет.
