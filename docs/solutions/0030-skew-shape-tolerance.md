# Графичная страница: двухуровневый порог формы детектора наклона (журнал)

Находка автора 2026-10-31: скан страницы рабочей тетради по математике (200 dpi, цвет; числовые
прямые, рамки, крупные цифры) с хорошо видимым веером — детектор отвечал «Строки на странице
есть, но их наклон не сходится в одну форму». Плана нет — правка в одной функции детектора,
критерий — таблица фикстур (прецедент — журналы 0024–0026). ADR нет. Первая смена детектора
после [solution 0029](0029-b-19-straighten-versions.md): выправленные страницы прежнего детектора
пересчитываются фоном, `derived/` руками не чистится.

## Диагноз

Скан — из `session/pages/` (по правилу «находки с живого — по JPEG, не по скриншоту»), боевым
`measureSkewJpeg`:

- полосы чистые: все валидны, уверенность 8–45, половины согласны, углы от +0,55° сверху до
  −0,57° снизу — ступень видна целиком;
- проваливается только гейт формы: остаток 0,169° при 30 мм и 0,122° при 50 мм против
  `SHAPE_RESIDUAL_MAX_DEG` 0,1° — соседние полосы прыгают на 0,1–0,2°, как у двух колонок
  (журнал 0026), но причина другая: графика (линии, рамки, крупные цифры) дразнит проекционный
  пик сильнее текста;
- запасной профиль по половинам не спасает — половины шумят так же.

Пробы порога (все откатаны до правки):

| Вариант                                         | Скан автора      | Штриховка `fan-graphic`      | Прочее                               |
| ----------------------------------------------- | ---------------- | ---------------------------- | ------------------------------------ |
| общий порог 0,15° / 0,2°                        | выправлен, ×5,29 | **выправлена ×2,31** — плохо | `text-gray-300` уходит с 50 мм на 30 |
| 0,2° только узлам по плотной опоре, прямая 0,1° | выправлен, ×5,29 | `unmeasurable` (`shape`)     | `text-gray-300` — 30 мм              |

Штриховка держится не порогом, а видом профиля: её валидные полосы — только верх (u ≤ 0,20,
≈ 0,97°) и низ (u ≥ 0,87, ≈ −0,15°), дыра опоры > `MAX_SUPPORT_GAP` → прямая по двум кучкам, и
для такой прямой 0,1° — честный порог «полосы спорят».

## Исправление

- `src/core/detect/skew.ts`: `SHAPE_RESIDUAL_DENSE_MAX_DEG` 0,2° — порог формы для профиля узлами
  по плотной опоре; `SHAPE_RESIDUAL_MAX_DEG` 0,1° остаётся для прямой при дыре опоры.
  `fitProfile` отдаёт допуск своего вида профиля (`allowed`), гейты целых полос и половин
  сравнивают с ним. `SKEW_DETECTOR_VERSION` 4 → 5 (`src/core/detect/skew-version.ts`).
- Результат по таблице: скан автора (`fan-worksheet-color-200`) — `willStraighten`, 30 мм, по
  целым полосам, ×5,29, веер 4,16 мм, профиль +0,55 → −0,58°; после коррекции — `level`, max|θ|
  0,088°, веер 0,46 мм. `text-gray-300` проходит основным проходом 30 мм вместо запасного 50 мм
  (×2,25, веер 3,94 мм; после — `level`, 0,43 мм) — закреп запасного прохода оставлен на
  `rulers-gray-200`. Штриховка — по-прежнему `unmeasurable` с причиной `shape` (остаток 0,144° при
  30 мм, прямая). Остальные сканы — без изменений исхода.
- **Синтетика:** тест «обе формы не описывают лестницу из двух ступеней» ломался — лестница по
  0,5° теперь проходит. Проба по шагам: 0,3° и 0,5° — `willStraighten`, узлы совпадают с истинным
  θ до 0,005°, контраст ×1,8–2,0 (выправление верное); 0,7° и больше — `unmeasurable` (остаток
  0,23–0,52°). Тест переписан на две части: мелкая лестница выправляется по обеим ступеням,
  крупная (по 1°) — `unmeasurable` с причинами обоих проходов.
- **Резерв места:** тест ресэмплера поймал размер выхода ×2,12 у цветного скана 200 dpi (сканер
  жмёт сильнее нашего q92 4:4:4) при `STRAIGHT_SIZE_RATIO` 2 → 2,5 (максимум с запасом).
- Фикстура `fan-worksheet-color-200` — байт в байт из `docs/input/` (baseline JPEG без
  EXIF / ICC / XMP, проверено), печатная страница без имён и личных данных; таблица ожиданий,
  тест «графичная страница с плотной опорой» (исход, 30 мм, по целым, остаток между порогами,
  штриховка — `shape`). README фикстур, техбаза (п. 4 гейтов, «Две колонки», размер файла),
  `bugs.md`.
