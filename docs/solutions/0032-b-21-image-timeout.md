## Сессия 1 — реализация

### U1. Помощник обработки картинки с двумя сроками — ✅ зелёный

`src/core/image/sharp-image.ts`: `processImage(input, work, deadlines?)` — вход JPEG с пределом
пикселей или сырые пиксели, `work` получает экземпляр `sharp` со сроком libvips
(`IMAGE_TIMEOUT_SECONDS` 30) и делает всё от заголовка до буфера; запасной срок
(`IMAGE_DEADLINE_MS` 35 000) — `Promise.race` с таймером. Любой признак срока приводится к
`ImageTimeoutError` (`isImageTimeout`): своя ошибка запасного срока, текст
`timeout: N% complete` где угодно в сообщении, любой отказ не раньше срока по часам. Подмена
сроков — только целые секунды 1…3600 (`RangeError` иначе: 0 выключил бы защиту). Проигравшая
гонку обработка получает пустой обработчик отказа — без него поздний отказ был бы unhandled.

**Замер нагрузки для теста (2026-11-01).** Размытие σ 60 и медиана 41 на 4000×4000 идут за
0,2–0,4 с — libvips их сильно ускоряет, срок в 1 с не успевает сработать. Годится
несепарабельная свёртка: ядро 121 на 3000×3000 — без срока ~3,9 с, со сроком 1 с — отказ за
~1,1 с с текстом `timeout: 27% complete\nVipsImage: killed for image "temp-42"`. Срок работает
на всех трёх формах ядра: серый `resize` в сырой буфер, JPEG в сырой одноканальный, сырой вход в
JPEG. Серая форма с уменьшением при ядре 61 шла 0,5 с и без срока: `sharp` уменьшает до свёртки.

Тест `test/integration/sharp-image.test.ts` (10): срок libvips в трёх формах (причина — текст
libvips, 0,9–3 с), запасной срок на незавершающейся обработке, текст срока не первой строкой,
отказ без текста после срока по часам, битый JPEG — не срок, посторонние значения — не срок,
`RangeError` на 0 / 1,5 / −1 / 3601, скан ET-3850 со сроками по умолчанию.

**Готово:** typecheck, lint, тест помощника зелёные. Коммит `fix(b-21): U1 …`.

### U2. Все вызовы `sharp` ядра — через помощника; страж — ✅ зелёный

- `detect/gray.ts` (`decodeWorkingGray`): обработка — через `processImage`; срок пробрасывается
  исключением, прочие сбои — по-прежнему `null` (KTD-5). Комментарии `blankRatio` и
  `measureSkewJpeg` — про исключение срока.
- `image/straighten.ts`: декод и кодирование — через помощника, срок и там и там — `null`
  (очередь откладывает страницу со сбоем в памяти, как раньше). Тип результата декода несёт
  `channels: 1 | 3` — кодированию нужен литерал, `RawImage.channels` — просто число.
- `storage/thumbnails.ts` (`render`): через помощника, срок — `thumbnailFailed` / `decode`, не
  кэшируется.
- Страж `test/guards/sharp-entry.test.ts` по образцу `straight-paths.test.ts`: импорт `sharp` в
  `src/` вне тестов — только у помощника и `imaging-probe.ts`; синтетика ловит статический,
  именованный, `import()`, `require()` и импорт ради побочного эффекта, не путает `sharp-extra`
  и тестовые файлы.

**Готово:** typecheck, lint, `npm test` 144 / 2567, `test:integration` 33 / 292 (4 live
пропущены), worst-case 3 / 5 — ожидания прежних наборов не правились. Коммит `fix(b-21): U2 …`.

### U3. Оценки пустоты и наклона: «не успели» — в памяти, без кэша — ✅ зелёный

- `blank-scores`: `ratioOf` отдаёт `{ ratio, cacheable }`; срок — `ratio: null`,
  `cacheable: false`, кэш пишется только при `cacheable` (сбой чтения страницы — тоже
  `cacheable: false`, как раньше).
- `skew-scores`: в `catch` вокруг измерителя срок даёт `UNMEASURABLE` в памяти и выход до записи
  кэша — тот же исход, что у сбоя чтения; прочие исключения — запись «не померить» с причиной.
- Тесты: `blank-scores.test.ts` (+2: срок — в памяти, кэша нет, повторное открытие оценивает
  заново; не-срок — `null` в кэше), `skew-scores.test.ts` (+1: срок — в памяти, повторное
  открытие выправляет). Новый `image-timeout-paths.test.ts` (3) с подменой помощника — пути из
  U2 на настоящем коде: декод детекторов пробрасывает срок исключением, прочий сбой — `null`;
  выпрямление — `null` при сроке на декоде и на кодировании; миниатюра — `thumbnailFailed` /
  `decode` без кэша, следующий запрос строит заново. Эмулятор `blank-backs.emulator.test.ts`
  (+1): оба детектора отвечают сроком — ожиданий нет, ничего не скрыто, кэшей нет, PDF из всех 24.

**Грабли гейта.** Полный `test:integration` один раз уронил
`added-pair-mismatch.emulator` («гарды команд решения набора… `saving`»); отдельно и в четырёх
полных прогонах подряд — зелёный, текст падения не снят. Разбор по коду: запись PDF стартует без
ожидания оценок; под нагрузкой (новый тест помощника греет все потоки libvips свёрткой)
недоделанная оценка пустых даёт «Сохранить» отказ `blankPending` до флага записи, и гард `saving`
не проверяется. Исправлено ожиданием оценок перед записью (`untilScored`), как в соседних тестах
файла; `bugs.md` — закрытый пункт. Продуктовый код не меняется.

**Готово:** typecheck, lint, format:check, `npm test`, `test:integration` зелёные. Коммит
`fix(b-21): U3 …`.
