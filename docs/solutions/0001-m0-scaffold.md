## Окружение (выверено в начале сессии 1)

Node 24.17, npm 11.13, git 2.52, Windows 11. `core.autocrlf=true` глобально — перекрыт
`.gitattributes`. Remote не задан. `ELECTRON_RUN_AS_NODE=1` унаследована терминалом редактора на
уровне процесса: Electron из такого терминала стартует как Node.

**Связка версий (факт реестра на 2026-09-19).** Ведёт `electron-vite` 5.0.0, и это сразу дало два
ограничения против «просто latest»:

- `electron-vite` 5 принимает Vite `^5 || ^6 || ^7`, а `latest` у Vite уже 8 → **Vite 7.3**;
  отсюда `@vitejs/plugin-react` **5.2** (6-я ветка требует Vite 8).
- `typescript-eslint` 8.70 принимает TypeScript `<6.1.0`, а `latest` у TypeScript уже 7.0 →
  **TypeScript 6.0**. Пересмотр — когда typescript-eslint поддержит 7-ю.

## Сессия 1 — тулчейн

### U1. Гигиена репозитория и форматер — ✅ зелёный

`package.json` без поля `type` (KTD-31), `engines.node >= 22.12` — минимум, общий для
`electron-vite`, vitest и Electron 44. `.gitattributes`: общее правило LF первым, бинарные типы,
`test/fixtures/** -text`. Prettier: `singleQuote`, `printWidth: 100`, `endOfLine: lf` — под то, как
доки уже были набраны. Hook — husky 9 + lint-staged, форматирует застейдженное и больше ничего;
страж приватности добавит U15.

Проверено: `git check-attr` даёт `eol: lf` на markdown и `text: unset` под `test/fixtures/`; hook
отрабатывает на пути проекта с апострофом; застейдженный файл с CRLF и кривым форматированием
выходит из lint-staged отформатированным и с LF.

Первый прогон форматера — отдельный коммит-база: 7 файлов доков, только выравнивание таблиц,
`*курсив*` → `_курсив_` и развёрнутый блок `:root` в дизайн-системе. Смысл не тронут.

**Грабли:** `husky init` кладёт в hook `npm test` — заменено на `npx lint-staged`.

**Готово:** `format:check` зелёный. Коммиты `chore(m0): U1 …`, `style(m0): U1 …`.

### U2. Проекты TypeScript, electron-vite, окно — ✅ зелёный

Пять проектов TypeScript по KTD-5, корень solution-style. Закрыт отложенный вопрос плана про
`typecheck`: **`tsc -b` с `noEmit` и `incremental`, без `composite`** — TypeScript 6 принимает
ссылки на такие проекты из корня с `files: []`; `tsBuildInfoFile` уведён в `node_modules/.tmp/`.
В TypeScript 6 `types` по умолчанию пуст, и это работает на изоляцию: `shared` собирается без
Node и DOM, `core` — с Node, но без DOM. Проверено подставными файлами: `document` в ядре и
`node:fs` в `shared` роняют `typecheck`.

Таблица алиасов — `tooling/aliases.ts` (`@shared`, `@core`, `@locales`), корень берётся от
`process.cwd()`: конфиги бандлятся загрузчиками в разные форматы, где `__dirname` и `import.meta`
ведут себя по-разному. Входы и выходы `electron-vite` — по умолчанию; preload вышел одним
CJS-файлом.

Закрыт отложенный вопрос про `ELECTRON_RUN_AS_NODE`: **`electron.vite.config.ts` сам удаляет
переменную из `process.env`** — конфиг грузится в процессе `electron-vite` до запуска Electron, и
дочерний процесс наследует уже чистое окружение. Проверено: `npm run dev` с нарочно выставленной
`ELECTRON_RUN_AS_NODE=1` открывает окно. Это лечит `dev`; запуск `electron.exe` напрямую и
установленного приложения из терминала редактора по-прежнему требует снять переменную руками.

Проверено: `build` кладёт выход в `out/`, собранное приложение открывает окно с заголовком
приложения, события `preload-error` нет — preload грузится под sandbox и вне `dev`.

**Грабли:**

- Electron 44 убрал postinstall: бинарник качается лениво, при первом запуске. После чистой
  установки — `npx install-electron --no`, иначе первый `dev` молча ждёт загрузку.
- `electron-vite` по умолчанию не минифицирует ни один из трёх выходов — бандл renderer с React
  весит около 640 КБ. Это продакшен-сборка React, не dev; при загрузке с диска размер не важен.
- **Процессы Electron закрывать только по PID своего дерева** (`taskkill /PID <id> /T /F`), никогда
  по имени: `Stop-Process` по имени `electron` закрывает и чужие приложения на Electron,
  запущенные из `node_modules` соседних проектов. В этой сессии агент так закрыл dev-экземпляр
  Shelfory автора.

**Не проверено агентом:** отсутствие ложных ошибок JSX в открытом `.tsx` в редакторе — проверка
глазами автора.

**Готово:** `typecheck`, `format:check` зелёные. Коммит `feat(m0): U2 …`.

### U3. Харнес vitest — ✅ зелёный

Один `vitest.config.ts`, три проекта: `node`, `jsdom`, `integration`; алиасы — из общей таблицы.
`test` называет первые два поимённо. Проверено ловушкой: заведомо падающий тест под
`test/integration/` не попадает в `test` и попадает в `test:integration`. До U5 у
`test:integration` стоит `--passWithNoTests`; U5 его снимает.

Глобалы выключены, поэтому авто-очистка testing-library сама не срабатывает — `afterEach(cleanup)`
стоит в тесте явно. Когда jsdom-тестов станет больше одного файла (U7), это уезжает в setup-файл
проекта `jsdom`.

**Отклонение от плана (осознанное):** добавлены `@testing-library/react` и `@testing-library/dom` —
план их не называл, но сценарии U7 ищут текст в разметке, и писать это на голом `react-dom`
дороже.

**Готово:** `typecheck`, `format:check`, `test:all` зелёные. Коммит `test(m0): U3 …`.
