# Гейт половин детектора наклона терял полосы без строк в одной половине (журнал)

Находка приёмки M6 (2026-10-29, [solution 0023](0023-m6-straighten.md)): автор принёс три
наблюдения с живого ET-3850 — две колонки «не по чему мерить» при заметном перекосе, оборот
листа 1 двухпроходного набора не выровнен при выровненном лице, калибровочный лист 3 с
линейками «выровнен», но лишь чуть повёрнут, веер остался. Плана нет — правка в одной функции
детектора с таблицей фикстур как критерием. ADR нет.

## Диагноз

Скриншоты не годятся — нужны исходные сканы (`session/pages/`, 200 dpi серый). Прогон боевым
`measureSkewJpeg` (не спайком — прототип всем четырём отказал):

| Скан            | Было                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------- |
| две колонки     | `unmeasurable`: все 10 полос валидны, ступень видна, но остаток формы 0,176° / 0,130° > 0,1  |
| лист 1 лицо     | `willStraighten` 50 мм ×1,34: ровно 3 полосы из 10 (шапка, «TOP», блок строк), прямая        |
| лист 1 оборот   | `unmeasurable`: 2 полосы из 10 — блок строк рядом с чёрной плашкой отброшен (половины 0,60°) |
| калибровочный 3 | `willStraighten` 50 мм ×2,47, веер 0,31 мм: узлы только до u 0,52, низ с линейками отброшен  |

Механика. Гейт половин (`halvesGap > HALVES_TOLERANCE_DEG`) не смотрел на уверенность самих
половин. У половины с одной плашкой (кромки прямоугольника) или миллиметровыми рисками
(гребёнка) пик резкости плоский, угол — шум, и он накладывал вето на уверенную целую полосу
(оборот: целая 30,5, −0,65°, как у лица −0,73°; линейки: целые −0,95 / −0,90° — верный низ
ступени). За последним узлом профиль идёт константой, поэтому низ калибровочного листа
повернулся на −0,3° вместо −0,9°; метрика «не хуже» это пропускает — весь контраст даёт текст
сверху (×2,47). Две колонки — известный предел метода (шум между соседними полосами
0,1–0,2°), не этот дефект.

Инструментирование половин по всем сканам (26 фикстур + 4 приёмки):

- уверенность половины (max/min в окне ±0,6°): плашка и линейки 1,1–1,3, текст 1,6–2,1 —
  делит, но зазор тонкий и величина не про то;
- **отношение возражения** r = пик половины / счёт половины при угле целой: плоские половины
  1,00–1,12; настоящие возражения — колонки с другой фазой (до 1,65), штриховка (1,18–1,22),
  мусорные полосы цифры «1» на лице (1,28–1,98). Порог 1,2.

## Исправление

- `src/core/detect/skew.ts`: `halfOf(half, …, wholeAngle)` — угол половины в окрестности угла
  целой и флаг `objects` (пик ≥ `HALF_OBJECTION_MIN` 1,2 × счёт при угле целой; `angleOf`
  отдаёт `score` пика). Вето `halves-disagree` — только если возражает хотя бы одна половина;
  среднее половин вместо целой — только когда обе возражают и согласны между собой. Пустая
  половина не голосует.
- Порог `MIN_INK_FRACTION` 0,002 → 0,005: с ожившим гейтом на обороте ожила полоса пустой
  бумаги (0,32 % чернил — просвечивание лица, уверенность 3,5, угол −0,25° ниоткуда) и ломала
  форму (0,26° при 50 мм). По всем сканам минимум валидных полос — 1,47 % (бедный лист),
  печатная страница 2,0 %, одна строка текста 2,75 %; кромочные полосы чистых листов
  (0,9–1,2 %, u ≈ 0) остаются и исходов не меняют.
- Все валидные полосы ниже `LEVEL_DEG` → `level` без гейта формы: страж `straighten.test.ts`
  («после коррекции профиль читается») поймал лицо листа 1 — после коррекции три полосы
  −0,08 / +0,10 / −0,08°, остаток формы 0,105° против 0,1 → `unmeasurable`. Когда коррекции не
  будет, вопрос доверия форме не стоит; профиль узлами, константа за крайними держит его под
  порогом. Слабость существовала и до правки — просто такого листа в фикстурах не было.
- `SKEW_DETECTOR_VERSION` 1 → 2: записи измерений v1 не читаются, страницы перемеряются при
  открытии. Версию геометрии не трогал — `.v1` держат литералом ~10 тестов, а пересчёт уже
  выправленных файлов нужен лишь текущей сессии автора (`derived/` удалить). Пробел «запись
  коррекции не знает версии детектора» — в бэклог.

После: лицо ×1,33 (как было), оборот `willStraighten` 30 мм ×3,35, веер 4,20 мм (3 полосы,
прямая +0,41° → −0,85°), калибровочный ×3,19, веер 2,45 мм, узлы 0,77:−0,95 и 0,82:−0,90 —
ступень найдена; две колонки — как было. **Таблица 26 фикстур не изменилась ни исходом, ни
профилем.**

- Фикстуры: `sheet-front-gray-200`, `sheet-back-gray-200`, `rulers-gray-200` (сканы приёмки,
  страж метаданных зелёный); таблицы ожиданий в `skew-detector.test.ts` (оба `sheet-*` и
  `rulers` — `willStraighten`, лицо и линейки — запасным проходом 50 мм), классы
  `blank-detector.test.ts`, README фикстур.
- Тест-мутация в `skew-detector.test.ts`: у линеек узел ниже u 0,7 и веер > 2 мм, оборот —
  `willStraighten` с тремя валидными полосами. Без правила возражения падает.
- Техбаза → «Детектор перекоса»: п. 3 валидности, строки таблицы, «Доработка после приёмки»,
  «Предел метода» (две колонки — ход для бэклога, «строки сверху, рисунок снизу» — M6.5).
- `docs/bugs.md` → «Закрытые»; бэклог → «Входящие»: две колонки по отдельности; версия
  детектора в записи коррекции.
