# Bugs — Duplexn't

Реестр известных дефектов. Пайплайн: пользователь описывает баг в «Входящих» → по команде
«обработать входящие» баг анализируется и переносится в «Открытые» → после исправления
переезжает в «Закрытые» одной строкой. Критичные кандидаты могут идти сразу в `docs/plans/`.

Серьёзность: **crit** (риск данных пользователя) · **high** (ломает сценарий) · **low**
(косметика, мелкое неудобство). Дефекты с риском для данных пользователя — всегда **crit**,
в приоритете над фичами.

Формат записи:

```
### [crit|high|low] Краткий заголовок
- **Где:** компонент / файл
- **Повтор:** шаги воспроизведения
- **Ожидание / факт:** что должно быть / что есть
- **Статус:** open | in-progress (→ plans/...) | fixed (→ solutions/...)
```

## Входящие

Сырые описания багов от пользователя, без оформления — свободным текстом. По команде
«обработать входящие» каждый пункт анализируется (повтор, серьёзность, где сломано),
оформляется по формату выше и переносится в «Открытые», а отсюда удаляется. Этот
заголовок остаётся всегда, даже когда пусто.

- Эмуляторные тесты с дедлайнами нестабильны под нагрузкой (2026-10-29, `test:all` при
  работающем рядом приложении, CPU ~34 %): утром — `two-pass` AE6 по таймауту 5 с (укреплён,
  `52c67b0`); вечером в `npm run test:integration` дважды подряд разные падения —
  `pass.emulator` AE5 «обрыв на 18-м листе, досканирование», `blank-backs` AE3 «бледный
  карандаш в лотке оборотов», `pass.emulator` «прерывание возвращается не позже срока, даже если
  DELETE молчит» (`expected 'running' to be 'interrupted'` после `interrupt(100)`); третий
  прогон зелёный; позже тем же вечером — `blank-backs` AE4 и `added-pair-mismatch` AE3, повтор
  файла зелёный. Кандидаты: тесты, где ожидание фиксировано временем, а не условием
  (`interrupt(100)` + проверка состояния сразу), и дефолтный таймаут 5 с без своего у тестов с
  подачей. Пройтись по интеграционным тестам: условие вместо паузы, таймауты как у соседей.
