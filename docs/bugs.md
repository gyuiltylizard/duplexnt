# Bugs — Duplexn't

Реестр известных дефектов. Пайплайн: пользователь описывает баг в «Входящих» → по команде
«обработать входящие» баг анализируется и переносится в «Открытые» → после исправления
переезжает в «Закрытые» одной строкой. Критичные кандидаты могут идти сразу в `docs/plans/`.

Серьёзность: **crit** (риск данных пользователя) · **high** (ломает сценарий) · **low**
(косметика, мелкое неудобство). Дефекты с риском для данных пользователя — всегда **crit**,
в приоритете над фичами.

Формат записи:

```
### [crit|high|low] Краткий заголовок
- **Где:** компонент / файл
- **Повтор:** шаги воспроизведения
- **Ожидание / факт:** что должно быть / что есть
- **Статус:** open | in-progress (→ plans/...) | fixed (→ solutions/...)
```

## Входящие

Сырые описания багов от пользователя, без оформления — свободным текстом. По команде
«обработать входящие» каждый пункт анализируется (повтор, серьёзность, где сломано),
оформляется по формату выше и переносится в «Открытые», а отсюда удаляется. Этот
заголовок остаётся всегда, даже когда пусто.
