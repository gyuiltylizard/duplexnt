# Duplexn't — двустороннее сканирование на сканере без дуплекса

Десктопное приложение для Windows, которое сканирует двусторонние документы на сканере **с
автоподачей, но без автоматического дуплекса** (целевое устройство — Epson EcoTank ET-3850).
Сценарий — два прохода: лицевые стороны, разворот пачки, обороты; приложение само собирает
документ в правильном порядке, даёт проверить и поправить результат, разметить границы
документов и сохранить. Сознательно **не является** универсальной сканирующей утилитой:
нет автоподачи — устройство не подходит; есть дуплекс — приложение не нужно.

> **Стадия: M0 реализована — каркас заведён, продуктового поведения ещё нет.** Оставшаяся пометка
> `<не определено: …>` — библиотека PDF (ADR при планировании M2).
> Найти хвосты: поиск по `<не определено`.

**Техническая база** — [`duplexnt-tech.md`](duplexnt-tech.md): протокол eSCL, возможности
ET-3850, логика двух проходов, решения макета — всё, что проверено экспериментально. Спека
на неё ссылается и факты оттуда не дублирует; при расхождении по фактам протокола и железа
права техбаза, по скоупу и правилам — спека.

---

## Концепция

- **Платформа:** Windows, десктоп (макет — 1280×800).
- **Основной домен:** сетевое сканирование по **eSCL** (AirScan / Mopria, HTTP + XML) с
  автоподачи; сборка двух проходов в документ; результат — PDF.
- **Философия:** узкий инструмент под один сценарий — «двусторонняя пачка на сканере без
  дуплекса». Планшет — вспомогательная утилита внутри главного экрана, не режим. Внятный
  статус устройства прямо в интерфейсе вместо модалки с кодом ошибки — половина ценности
  продукта. Тяжёлое (разбор XML, обработка изображений, сборка PDF) отдаётся готовым
  библиотекам.

**На будущее:** подпись кода и автообновление; сборка под мак (код её не ломает намеренно, но
она не делается и не тестируется); вторая локаль; OpenCV или его WASM-сборка под
выравнивание перекоса и вычитание просвечивания — через спайк.

**Что стек обязан уметь** (исходный список из техбазы; чем закрыто):

- HTTPS к устройству с самоподписанным сертификатом — main-процесс; проверка ослабляется
  только для соединения со сканером. Pinning отпечатка — пост-MVP;
- mDNS-обнаружение (`_uscan._tcp` / `_uscans._tcp`, TXT-записи) — чистый JS, `bonjour-service`;
  спайк M0 пройден при остановленной службе Bonjour;
- обработка изображений: бинаризация и доля непустых пикселей, миниатюры — `sharp`;
  автообрезка, deskew, вычитание просвечивания — пост-MVP, перед ними спайк;
- сборка PDF — JPEG от устройства вкладывается без перекодирования, поворот на 90° —
  свойством страницы;
- десктопный UI по макету: перетаскивание, множественное выделение, анимированная
  инструкция — веб-стек, макет служит референсом напрямую;
- поставка одним установщиком для Windows — NSIS.

## Архитектура

Четыре слоя ([ADR 0003](decisions/0003-shell-build-delivery.md)):

| Слой      | Где живёт                                    | Назначение                                                                                                                                                                     |
| --------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Ядро      | `src/core/` — Node, без импортов Electron    | Клиент сканера (сессия, `capabilities`, `status`, `scan`, пересчёт координат, занятость и ретраи); сборка проходов, пустые обороты, разбиение на документы; постобработка; PDF |
| Main      | `src/main/` — main-процесс                   | Тонкая обвязка: окно, усиление оболочки (`shell/`), регистрация моста, файловые диалоги. Логики сканирования здесь нет                                                         |
| Мост      | `src/preload/` — один CJS-файл под sandbox   | Узкий объявленный набор каналов; вход валидируется на стороне ядра                                                                                                             |
| Интерфейс | `src/renderer/` — React, без Node и Electron | Экраны по `design/UI_SPEC.md`                                                                                                                                                  |

**`src/shared/` — контракт, а не пятый слой.** Типы и константы, общие для всех процессов: карта
каналов моста, типы запросов и ответов. В нём нет ни Node, ни DOM, ни Electron, и он не
импортирует ни один слой — поэтому его может импортировать каждый. Вне `src/` лежат `locales/`
(строки интерфейса), `tooling/` (общее для конфигов сборки: алиасы, билдер CSP) и `scripts/`
(страж приватности, синхронизация токенов).

**Границы слоёв — правила линтера, а не договорённость:** импорт Electron в слое ядра роняет
`lint`, как и любой другой импорт поперёк таблицы — статический, динамический `import()` или
`require()`. Поэтому ядро тестируется без окна, а сеть и устройство заменяются эмулятором сканера,
который говорит по настоящему протоколу на тех же фикстурах, что и юнит-тесты
([ADR 0001](decisions/0001-test-framework.md)).

Отдельного процесса или воркера для ядра нет: `sharp` асинхронный, JPEG вкладывается в PDF
почти побайтовым копированием. Появится число, которое требует воркера, — пересматривается.

**Ключевой принцип компактности:** одно ядро и один путь исполнения. Настоящий сканер, эмулятор
и тесты ходят через один и тот же клиент; в приложении нет ни демо-режима, ни второго способа
получить страницы.

## Модель данных

Решено [ADR 0004](decisions/0004-data-model.md) по брейншторму
`brainstorms/2026-10-02-data-model-requirements.md`. Базы данных нет
([ADR 0003](decisions/0003-shell-build-delivery.md)): сессия — папка обычных файлов и журнал.
Сущности:

- **Профиль сканера** — UUID, SerialNumber, последний адрес (схема / порт / путь),
  отпечаток сертификата. Идентичность устройства — UUID, не IP.
- **Параметры сканирования** — источник, DPI, цветовой режим, регион, режим пустых оборотов;
  допустимые значения берутся из capabilities устройства.
- **Сессия сканирования** — проходы и полученные с устройства страницы. Одна за раз; живёт на
  диске, переживает перезапуск и удаляется только явным действием пользователя.
- **Проход** — единица сканирования и единица удаления; завершён или прерван.
- **Страница** — исходное изображение, проход и позиция в нём, сторона (лицо / оборот),
  пометки и правки (поворот, скрыта как пустая, удалена).
- **Документ** — имя и упорядоченный набор страниц; из одной пачки может выйти несколько.
- **Сохранённые файлы** — результат в папке пользователя.

**Принцип:** источник правды — исходные изображения страниц (байт в байт как отдал сканер,
после записи не меняются), журнал сессии (проходы, страницы, правки, границы документов) и
профиль с настройками. Правки — записи в журнале поверх исходников. Миниатюры, оценки детектора
пустых страниц и порядок сборки по умолчанию — производное: перестраиваются из источника
правды и в него не пишут. Сохранённый PDF — результат, сессия из него не восстанавливается.
Страница записывается на диск в момент получения. Схема хранилища и любой записываемый формат
версионируются с первого дня.

`dev`-запуск и установленное приложение используют разные каталоги данных; приложение работает
в одном экземпляре.

## Локализация

`i18next` с привязкой к React. Строки интерфейса — через `t("ключ")` с первого экрана, локали
в файлах, плюрализация по правилам локали (в интерфейсе есть счётчики страниц и листов: лист /
листа / листов), даты по локали; данные пользователя (имена документов и файлов) не
переводятся.

**Первая локаль — русская, и она задаёт раскладку.** Русские слова длиннее: раскладка,
выдержавшая русский, выдержит английский, обратное неверно. В MVP локаль одна; каркас под
вторую есть с M0, перевода нет. Локали лежат в `locales/<язык>/<пространство>.json` — сейчас это
`locales/ru/common.json`; renderer импортирует их по алиасу `@locales`, ядру и preload импорт
локалей запрещён линтером. Ключи типизированы: опечатка в `t("ключ")` роняет `typecheck`.

## Возможности — MVP

> Черновик: деление «MVP / позже» предложено при бутстрапе по техбазе и ждёт подтверждения
> автора.

### Подключение сканера

- Обнаружение по mDNS и ручной ввод адреса; схема / порт / путь — под «Дополнительно»,
  значения из TXT-записи, не хардкод.
- Валидация: нет `AdfSimplexInputCaps` — устройство не подходит, так и сообщаем.
- Профиль с UUID: адрес сменился по DHCP — находим устройство заново молча.
- Занятость устройства (`503`) переживается вежливым ретраем, а не падением. Остальной
  словарь состояний — пост-MVP.

### Сканирование в два прохода

- Параметры строятся из capabilities (набор DPI меняется с источником).
- Проход 1 → инструкция разворота картинкой с анимацией, явное «не переворачивайте
  листы» → **переход по нажатию** → проход 2. Автоперехода нет намеренно: пачку кладёт
  человек, и подтверждение готовности — его.
- Прогресс прохода — счётчик полученных страниц. **Общего числа листов в первом проходе
  приложение не знает**: сканер их не считает, страницы приходят по одной до `404`. Во
  втором проходе ожидаемое число известно — оно равно числу листов первого.
- Сборка: обороты идут в обратном порядке (`interleave`, техбаза, раздел 5).
- Несовпадение числа страниц: документ собирается по совпавшим парам, приложение сообщает,
  какой лист остался без оборота; досканирование — обычным «Добавить» (один лист, после
  текущей страницы). Первый проход не теряется.
- Отмена прохода пользователем отбрасывает полученные страницы — это её смысл: в лоток
  могли лечь не те документы.
- Аварийный переключатель «повернуть обороты на 180°».

### Пустые обороты

- Детект по доле непустых пикселей; три режима: скрывать / помечать / оставлять. Никогда
  не выбрасываем молча.

### Редактор и сохранение

- Миниатюры с перетаскиванием, множественное выделение, поворот, удаление, крупное превью;
  плашка «Порядок изменён» с возвратом к автосортировке.
- Границы документов на миниатюрах, имена блоков, «один файл / отдельные файлы».
- Сводка перед сохранением; сохранение в PDF — атомарно, перезапись только с подтверждением.
- «Новое сканирование» предупреждает о несохранённых страницах.

## Возможности — Доработка позже

- Добавление скана к документу (двусторонняя пачка / односторонние листы / один лист) и
  планшет как утилита «досканировать помятый лист».
- Пересканирование отдельной страницы.
- Постобработка: «Авто»-размер (автообрезка по контуру), deskew.
- Подавление просвечивания: мягкое (точка белого, гамма) и агрессивное (вычитание парного
  изображения, с превью «до/после»).
- **Словарь состояний устройства по ходу работы:** занят другим сеансом, ушёл в сон, потеря
  сети, замятие, лоток опустел посреди пачки — с внятным текстом прямо в интерфейсе. Сюда же
  опрос `ScannerStatus` и подсветка кнопки второго прохода по `AdfState` как подсказка
  готовности лотка.
- Pinning сертификата устройства.
- Мастер калибровки первого запуска (4 пронумерованных листа).
- Форматы сохранения помимо PDF (конвертацией на своей стороне).

## Сознательно вне рамок

- **Сканеры без автоподачи** — сценарий приложения не имеет смысла; устройство в списке
  приглушено и не выбирается.
- **Поддержка дуплекса** — не проверяем и не используем: приложение существует ради его
  отсутствия.
- **WIA / TWAIN** — транспорт только сетевой, по eSCL.
- **Планшет как самостоятельный режим** — только подчинённая утилита.
- **Автоматическое выбрасывание страниц** — пустые обороты и лишние листы только
  предлагаются к скрытию; бледный карандаш легко принять за пустоту.

## Ключевые принципы реализации

Факты и обоснования — в техбазе; здесь то, что нельзя нарушать.

- **Регион сканирования — всегда в 1/300 дюйма**, независимо от DPI. Пересчёт «пиксели
  превью → 1/300 дюйма» — одна функция, закрытая тестом. Самое хрупкое место интеграции.
- **Capabilities определяют UI**: списки DPI, режимов, форматов строятся из ответа
  устройства. Через автоподачу потолок 600 dpi — кнопка 1200 там врёт.
- **Порт, схему и путь не хардкодить** — брать из mDNS TXT; нормализацию `Location`
  оставить как страховку.
- **`DELETE` задания в конце обязателен**; `503` на `POST /ScanJobs` — занятость, ретрай с
  таймаутом, не падение.
- **Сборка проходов не молчит**: несовпадение числа страниц — явное решение пользователя, а
  не сдвиг.
- **Исходные сканы не теряются от сбоя**: ошибка, потеря связи или замятие не уничтожают уже
  полученные страницы. Явная отмена прохода пользователем — исключение: она их отбрасывает,
  и в этом её смысл (в лоток могли лечь не те документы). Разница в том, чьё это было
  решение.
- **«Авто»-размер — это постобработка**, а не параметр запроса: устройство не умеет
  определять размер листа.

## Правила и конвенции разработки

Операционные правила работы над проектом. `CLAUDE.md` держит из них только критичный
минимум и ссылается сюда; перед архитектурными изменениями этот раздел читается целиком.
Внешний источник правил — dev-playbook (`PLAYBOOK.md`); здесь — его проекция на проект.

### Безопасность данных (приоритет над всем)

- Запись в пользовательские файлы — **только атомарно**: временный файл → `fsync` →
  `rename` поверх оригинала. Никогда не модифицировать «на месте».
- Валидация структуры до и после записи; при ошибке — откат, оригинал цел.
- Деструктивные операции (удаление, перезапись оригинала, пакетные изменения) — только с
  явного подтверждения пользователя.
- Необратимые операции — явным действием, по копии, с тестом на границу обратимости.
- Уже отсканированное не теряется от сбоя: ошибка второго прохода или ошибка сохранения не
  уничтожают полученные страницы. Явная отмена прохода пользователем их отбрасывает —
  намеренно.
- Страницы не выбрасываются молча: пустые обороты и лишние листы — только по решению
  пользователя.
- Сохранение поверх существующего файла — только с явного подтверждения.

### Источник правды

- **Источник правды — исходники страниц, журнал сессии, профиль и настройки; миниатюры, оценки
  детекторов и порядок сборки по умолчанию — производное**
  ([ADR 0004](decisions/0004-data-model.md)). Ничего невосстановимого в производном;
  производное не пишет в источник правды.
- Исходник страницы после записи не меняется; правки — записями в журнале поверх него.
- Сессию удаляет только явное действие пользователя; единица удаления при отмене — проход.
- Восстановление **идемпотентно**: матчинг по устойчивому ключу, без дублей при повторе.
  Прерванный проход сохраняет полученные страницы.
- Идентичность сканера — UUID / SerialNumber, не IP-адрес.
- Схема хранилища версионируется с первого дня (миграции).

### Слои и стек

- Интерфейс не обращается к сети, файлам и ядру напрямую — только через `preload`-мост; вход
  моста валидируется на стороне ядра.
- Слой ядра не импортирует Electron. Нарушение ловит `lint`, а не ревью.
- Сканирование, постобработка и сборка PDF не блокируют интерфейс.
- Проверка TLS-сертификата ослабляется только для соединения со сканером. Глобально — никогда.
- Один путь исполнения: настоящий сканер, эмулятор и тесты ходят через один клиент. Демо-режима
  в приложении нет.
- Конфиги Shelfory не копируются — тулчейн тот же, но заводится заново.

**Правила моста** (контракт — `src/shared/bridge.ts`, действуют для каждого нового канала):

- одна функция на команду: preload отдаёт в окно именованные функции, а не `ipcRenderer` и не
  универсальный `invoke(канал)`;
- имя канала, тип запроса и тип ответа объявляются в одной карте в `shared`; main регистрирует
  обработчики по этой карте;
- main проверяет отправителя: запрос принимается только от главного фрейма своего окна;
- вход валидируется в ядре, до любой работы; мусор отклоняется ошибкой, а не приводится к типу;
- в контракте только типы из ES-библиотеки, переживающие structured clone: `Uint8Array` и
  `ArrayBuffer` можно, `Buffer`, `Blob` и потоки нельзя. События main → renderer, транспорт
  доменных ошибок и библиотека валидации входа — решения M1, своим ADR.

**Подводные камни стека** (подробности и репро —
[журнал M0](solutions/0001-m0-scaffold.md)):

- **`ELECTRON_RUN_AS_NODE=1` в терминале редактора.** VS Code передаёт её дочерним процессам, и
  Electron стартует как Node: окна нет, ошибки тоже. `dev` снимает её сам (в
  `electron.vite.config.ts`); в установленном приложении её игнорирует выключенный fuse
  `runAsNode`. Свой скрипт, запускающий Electron, обязан снять её сам.
- **Связку версий ведёт `electron-vite`, а не `latest`.** Он ограничивает Vite, Vite —
  `@vitejs/plugin-react`; `typescript-eslint` ограничивает TypeScript. Обновление — от них, а не
  по одному пакету.
- **В `package.json` нет поля `type`.** Под sandbox preload обязан быть одним CJS-файлом; ESM
  включён только в `scripts/` своим `package.json`. Node запускает `.ts` напрямую с 22.18 — на
  этом стоят hook и скрипты.
- **У Electron 44 нет postinstall.** Бинарник качается лениво, при первом запуске; после чистой
  установки первый `dev` молча ждёт загрузку. Скачать заранее — `npx install-electron --no`.
- **`electron-builder` пакует весь каталог проекта и не читает `.gitignore`.** Состав
  установщика — белый список в `electron-builder.yml`; без него в установщик уезжают `docs/` и
  сырые данные устройства.
- **`sharp` не грузится из asar.** Пакет стоит в `dependencies` и распаковывается явными
  паттернами `asarUnpack`; пересборка под Electron не нужна (`npmRebuild: false`).
- **Flat config ESLint не сливает опции правила.** Блок ниже по файлу перезаписывает
  `no-restricted-imports` целиком, поэтому каждый слой несёт полный набор запретов. В селекторах
  `no-restricted-syntax` слэш внутри `/…/` недопустим даже экранированным — пишется hex-кодом.
- **mDNS на Windows.** Порт 5353 делят служба Bonjour, DNS-клиент системы и сторонние
  приложения — `reuseAddr` обязателен; обнаружение идёт перебором внешних IPv4-интерфейсов
  (амендмент [ADR 0003](decisions/0003-shell-build-delivery.md)).
- **Коды ошибок TLS различаются между Node и Electron** (OpenSSL против BoringSSL). Код клиента
  не ветвится по конкретному коду отказа сертификата.
- **Файрвол Windows создаёт правило в момент показа запроса — блокирующим**, и меняет его на
  разрешающее по нажатию «Разрешить». Правило привязано к пути exe, переживает деинсталляцию и
  достаётся следующей установке в тот же путь. На машине автора блокирующее правило обнаружение
  не сломало, причина не установлена — полагаться на это нельзя; текст для пустого обнаружения —
  задача M1.

### Код и зависимости

- Ошибки не глотать (`catch {}` запрещён): логировать с контекстом или показывать
  пользователю понятным сообщением.
- Новые зависимости — только с обоснованием. Не реимплементировать то, что делает
  выбранная библиотека.
- Предпочитать правку существующих файлов созданию новых. Крупные рефакторинги и смена
  архитектуры — только после обсуждения.
- Язык и строгость — по ADR 0002; точечные отключения правил — только с обоснованием в коде.
- Прежде чем добавлять механизм «на всякий случай» — назвать число или сценарий, который
  его требует.

### Definition of Done

1. typecheck + lint + format:check + тесты (`test:all`) — зелёные.
2. Ручной смоук затронутого сценария.
3. Решение задокументировано в `docs/solutions/` (+ ADR, если была развилка).
4. Изменения закоммичены, тема коммита несёт id.

### Тестовые фикстуры

Набор заводится поэтапно. С M0 — канонические ответы устройства (`ScannerCapabilities` и
`ScannerStatus` ET-3850) и конвенция каталога. С первым кодом, который их читает: страницы
двух проходов с известным порядком (пронумерованные листы), пустой оборот и оборот с
бледным карандашом, пара «лицо + оборот» с просвечиванием, capabilities устройства без
автоподачи, ответы `503` / `404`. Каталог — `test/fixtures/<протокол>/<устройство>/`, сейчас
`test/fixtures/escl/et-3850/`; имя файла равно имени ресурса протокола, содержимое лежит байт в
байт. Конвенция целиком — [`test/fixtures/README.md`](../test/fixtures/README.md). Эмулятор
сканера и юнит-тесты читают один набор фикстур. Все операции чтения и записи тестируются против
них; реальные сканы пользователя — в `local-test-data/`, вне git.

**Приватность данных устройства.** Репозиторий публичный, утечка в историю git необратима.
Сырое, снятое с устройства, лежит только в `local-test-data/device/`; в репозиторий идёт
зачищенная копия с плейсхолдерами. Первым шагом после любого снятия данных пополняется список
настоящих значений `local-test-data/privacy-values.txt` — до первой строки журнала. Правило
держит страж `scripts/privacy-guard.ts`: тест в `npm test` и pre-commit hook. Hook обходится
флагом `--no-verify`, поэтому полный прогон `node scripts/privacy-guard.ts` — условие закрытия
вехи и первого push в публичный remote. Что страж ловит и чего не видит —
`test/fixtures/README.md`.

### Тестирование

Политика по приоритету риска, не по проценту покрытия.

**Обязательно покрывается:** компонент записи (round-trip, целостность, атомарность,
инварианты формата); табличная логика и эвристики (краевые случаи из спеки); идемпотентность
восстановления; детекторы; инвариант «derived ↛ durable».

**Для этого проекта обязательно:** пересчёт региона в 1/300 дюйма; `interleave` и сборка
при несовпадении числа страниц; детектор пустых оборотов (срабатывает где надо, молчит на
бледном тексте); разбор capabilities / status и нормализация `Location`; атомарность
сохранения PDF.

**Достаточно смоука:** обработчики на границе слоёв (валидация входа отклоняет мусор); UI.

**Принципы:** все тесты против фикстур; необратимые операции — по копии; без догмы про
процент; e2e — только когда появится сквозной сценарий, который смоук не ловит.

_Инструмент — ADR 0001._ Нативный / тяжёлый слой — отдельным прогоном
(`test:integration`); `test:all` — гейт вехи.

### Команды

Имена зафиксированы брейнштормом по стеку (R15), заведены в M0. Держать актуальными: смена
команды — правка здесь в той же вехе. Нужен Node 22.18 или новее.

```
npm run dev               # запуск в разработке; ELECTRON_RUN_AS_NODE снимает сам
npm run build             # сборка в out/
npm run dist              # build + установщик NSIS в release/ (вне git, не публикуется)
npm run typecheck         # tsc -b по пяти проектам: shared, core, node, web, test
npm run lint              # eslint, включая границы слоёв и запрет глобального ослабления TLS
npm run format            # prettier --write   (format:check — только проверка; pre-commit
                          #   hook форматирует застейдженные файлы сам)
npm run test              # чистая логика, интерфейс, страж приватности: без сети и окна
npm run test:integration  # sharp; с M1 — ядро против эмулятора сканера по настоящему HTTP
npm run test:all          # оба зелёные = DoD вехи
npm run tokens:sync       # перегенерировать tokens.css из docs/design/DESIGN_SYSTEM.md
node scripts/privacy-guard.ts   # полный прогон стража; --staged — то, что делает hook
```

После чистой установки бинарник Electron качается лениво, при первом запуске, и `dev` в это
время молча ждёт; скачать заранее — `npx install-electron --no`. Значения токенов правятся в `DESIGN_SYSTEM.md`, а не в
`tokens.css`: расхождение роняет `test`.

Тесты против живого сканера — opt-in по переменной окружения с его адресом; без неё
пропускаются с предупреждением. Запуск эмулятора — своей командой, заводится в M1.

### Git

- Перед переключением ветки — WIP-коммит. Не использовать `git stash` для переноса работы
  между ветками. Никогда `git stash drop`, не убедившись, что всё восстановлено.
- **Коммит шага вехи несёт U-ID в теме** (`feat(m4): U5 …`): `git log` однозначно
  показывает, какой юнит закрыт.
- Ветки `feat/<веха-или-B-N>`, `fix/…`, `chore/…` от `main`; история линейная.

### Процесс

- Планы — в `docs/plans/`; статус во frontmatter `status:` (`в работе` → `done`;
  `заморожен` — готов, не начат). Завершённый план **не удаляется**.
- Бэклог `docs/backlog.md`: «Входящие» → по команде «обработать входящие» каждый пункт
  оформляется, получает сквозной `B-N` (один раз и навсегда) и раскладывается по секциям
  Quick wins / Средние / Крупные. Ссылаться — по id.
- Пайплайн: `backlog.md` → (брейншторм, если развилки) → `docs/plans/` → выполнить →
  `docs/solutions/` → строка в «Завершённом».
- **Формат доков — шаблоны в `docs/templates/`.** Открывать шаблон при создании нового.
- **Сессионная нарезка крупного плана.** При заморозке плана — прикинуть, влезает ли
  реализация в одно контекстное окно. Если нет — секция `## План по сессиям` (каждая
  сессия кончается зелёным атомарным коммитом на границе юнита). Возобновление: позиция —
  `git log` (U-ID); мягкое состояние — журнал в `docs/solutions/`, заведённый с первой
  сессии (`## На чём встали` обновляется в конце каждой). В начале сессии — сориентировать
  пользователя на стадию; в конце — дописать журнал и сказать, на чём встали.
- **Завершение пункта.** Реализованный пункт → `## Завершённое` бэклога одной строкой (id,
  название, чем закрыто, ссылка, дата); полный текст удаляется; пункт вычёркивается из
  «Кластеров и порядка».
- **ADR — в момент принятия.** Развилка (стек / язык / библиотека / схема / протокол) →
  `docs/decisions/` сразу, по `docs/templates/adr.md`, сквозной нумерацией.

### Закрытие вехи

Порядок строгий:

1. **DoD зелёный** (`test:all`).
2. **Доки-хвосты долиты в ту же ветку до влития:** ADR, журнал (`status: done`), спека и
   «Команды», роадмап помечен.
3. **Остановка на точке приёмки.** Пользователю явно сообщается, что из DoD требует ручного
   действия, и запрашивается добро.
4. **Merge — только после явного ОК пользователя.** Влитие в `main` по собственной
   инициативе не допускается, даже при зелёных автотестах.
5. **База ветвления — `main`; история линейная.** Ветка удаляется после влития.

  производителей; сейчас проверено только на ET-3850.
