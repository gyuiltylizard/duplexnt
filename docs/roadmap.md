# Duplexn't — роадмап MVP

Верхнеуровневая нарезка MVP на вехи. Это **не пере-скоуп**: скоуп и границы заданы в
`duplexnt.md`, здесь — только порядок. Каждая веха — вертикальный срез через все слои, а
не горизонтальный слой.

**Как пользоваться:** роадмап задаёт последовательность. Детальный план разворачивается на
**одну** веху — ту, что делается прямо сейчас, — не вперёд. Выводы по завершённой вехе идут
в `docs/solutions/` и кормят планирование следующей. Планы накапливаются, а не пишутся
заранее и гниют.

**Принцип порядка:** хребет «фундамент → данные → чтение → отображение → **самая
рискованная запись** → надстройка». Самый рискованный и самый зависимый кусок идёт рано и
сразу с тест-политикой. UI-соблазн начать с богатой дизайн-системы игнорируем: оболочка без
ядра пуста.

> **Черновик.** Нарезка сделана при бутстрапе и уточнена после выбора стека (ADR 0001–0003);
> состав вех ждёт подтверждения автора. Блокеров у M0 нет.

---

## Сквозные нити (не вехи — действуют на каждой)

- **Безопасность данных** — отсканированное не теряется; сохранение атомарно; ничего не
  выбрасывается молча.
- **Тесты против фикстур** — каждый рискованный кусок покрывается по тест-политике; ядро
  тестируется без железа. Эмулятор сканера и юнит-тесты читают один набор фикстур; сценарии
  ошибок добавляются в эмулятор той же вехой, что их обработка.
- **Capabilities определяют UI** — никаких захардкоженных списков DPI, режимов, форматов.
- **Внятный статус вместо кода ошибки** — каждое новое состояние устройства получает
  человеческий текст в интерфейсе.
- **Локализация** — строки через `t()` с первого экрана.
- **Дизайн-токены** — UI собирается из токенов, без хардкода.
- **Документирование решения** — в `docs/solutions/` по завершении вехи.

## M0 — Каркас и фундамент

> Входы: требования к стеку —
> [brainstorms/2026-09-17-stack-requirements.md](brainstorms/2026-09-17-stack-requirements.md);
> решения — ADR [0001](decisions/0001-test-framework.md),
> [0002](decisions/0002-language.md), [0003](decisions/0003-shell-build-delivery.md).

Проект собирается и запускается пустым окном; заведены команды качества и pre-commit hook;
канонические фикстуры (`ScannerCapabilities` и `ScannerStatus` ET-3850) и конвенция
каталога; каркас локализации (`i18next`, русская локаль) и токенов из `DESIGN_SYSTEM.md`;
шрифты макета в поставке; правило линтера на границу слоя ядра; журнал
`docs/solutions/0001-m0-scaffold.md`. **Спайк из ADR 0003** на живом ET-3850: mDNS без
Bonjour, HTTPS с самоподписанным сертификатом, установщик с `sharp` на чистой машине.

**Выход:** `test:all` зелёный на пустом каркасе, спайк пройден или его провал оформлен
амендментом, команды записаны в спеку → «Команды».

## M1 — Подключение и один проход

Клиент сканера: ручной адрес и mDNS-обнаружение, `capabilities` → валидация наличия
автоподачи → параметры сканирования из capabilities; `status`; задание с автоподачи:
`POST` → `NextDocument` до 404 → `DELETE`; пересчёт региона в 1/300 дюйма под тестом; `503` →
ретрай. Экраны `setup` и `scan` со счётчиком, модалка `device`. Страницы прохода видны в
интерфейсе и лежат там, где не потеряются. **Эмулятор сканера** на фикстурах M0 со сценарием
занятости. Перед стартом — брейншторм и ADR по модели данных.

**Выход:** пачка отсканирована в один проход и с эмулятора, и с живого ET-3850; страницы видны
в приложении.

---

## M2 — Два прохода и сборка _(хребет риска)_

Экран `flip` с анимированной инструкцией и переходом по нажатию; второй проход;
`interleave`; несовпадение числа страниц (модалка `mismatch`, сборка по совпавшим парам,
первый проход цел); переключатель «повернуть обороты на 180°»; экран `merge`. Минимальное
сохранение в один PDF — атомарно. Самая рискованная логика идёт рано и сразу с
тест-политикой.

**Выход:** двусторонняя пачка с живого сканера сохранена в PDF в правильном порядке;
сценарий замятия не теряет первый проход.

---

## M3 — Редактор и сохранение

Экран `editor`: миниатюры, перетаскивание, множественное выделение, поворот, удаление,
крупное превью, плашка «Порядок изменён»; границы документов и имена; модалка `save`
(«один файл / отдельные файлы»), сводка перед сохранением; модалка `newscan`.

**Выход:** из одной пачки размечено и сохранено несколько документов с ручной правкой
порядка.

---

## M4 — Пустые обороты

Детектор по доле непустых пикселей; три режима (скрывать / помечать / оставлять);
переключатель показа скрытых и счётчик в редакторе; учёт в сводке перед сохранением.

**Выход:** пачка со смешанными одно- и двусторонними листами собирается без ручной чистки;
бледный текст не принимается за пустоту молча.

---

## M5 — Устойчивость подключения

Профиль сканера с UUID / SerialNumber; старт «сохранённый адрес → mDNS по UUID → молча
обновить адрес». Словарь состояний устройства (сон, потеря сети, замятие, опустевший лоток)
вынесен в пост-MVP; здесь остаётся только занятость — `503` переживается ретраем.

**Выход:** смена адреса по DHCP не требует ручных действий, занятый сканер не роняет
операцию.

---

## Вне этого роадмапа (пост-MVP)

Берутся отдельным решением; источник — спека → «Возможности — Доработка позже»:

- добавление скана к документу и планшет как утилита; пересканирование страницы;
- постобработка: «Авто»-размер, deskew;
- подавление просвечивания (мягкое и агрессивное);
- pinning сертификата; мастер калибровки; форматы помимо PDF.

---

## Граф зависимостей (кратко)

```
ADR по стеку → M0 → M1 → M2 → M3 → M4
                     └────────→ M5
```

До старта вехи под её заголовком может стоять цитата «Входы» — брейншторм и ADR, из которых
она вырастет. Статус вехи при закрытии: заголовок дополняется `✅ (реализовано YYYY-MM-DD)`, а
цитата заменяется ссылками на план, журнал и ADR.
