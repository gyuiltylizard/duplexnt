# Backlog — Duplexn't

Очередь работ. Пайплайн фичи: **backlog → `docs/plans/` (пометить «в работе») → выполнить
→ `docs/solutions/` → пункт в «Завершённое»**. Правила ведения — в `duplexnt.md` →
«Процесс».

**Нумерация.** Пункты нумеруются сквозно (`B-1`, `B-2`, …) при раскладке по секциям (сырые
идеи во «Входящих» номера не имеют). Номер даётся один раз и навсегда: не переиспользуется
и сохраняется при переносе в «Завершённое». Следующий свободный номер = максимальный
существующий по всему файлу + 1.

Источники будущих пунктов (не дублируем сюда, берём по мере надобности): спека →
«Возможности — Доработка позже» и «На отдельную проработку».

**Кластеры и порядок (якорь возобновления).** Живая карта: как пункты группируются и в
каком порядке берутся. Детали и «Принятые решения» — в самих карточках; здесь только
сквозная последовательность. **Ведение:** по мере закрытия пункта — убирать его из ячейки
«Пункты»; когда строка (кластер) пуста — удалять строку и перенумеровать «Очередь». Таблица
описывает только **незакрытое**; пустая — значит очередь разобрана.

| Очередь | Кластер           | Пункты                                  | Когда                          |
| ------- | ----------------- | --------------------------------------- | ------------------------------ |
| 1       | Релизный гейт     | B-40                                    | репо                           |
| 2       | Только по жалобам | B-20, B-22, B-23, B-25, B-27, B-34…B-38 | только при жалобе пользователя |
| 3       | Попутно           | B-28, B-33                              | при касании файлов             |
| 4       | Пост-MVP          | B-15, B-30, B-31, B-32                  | отдельным решением             |

**Метка «Когда»** у каждого пункта — целевой момент закрытия: код-локальные пункты
сворачиваются **попутно в свою веху**; security/latent — в **финальный hardening-проход**
перед релизом; структурное — **пост-MVP**, отдельным решением. Ориентир, не жёсткий
контракт: если пункт окажется блокером вехи — подтянуть раньше.

**Чего не берём — в бэклог не пишем.** Отказ автора от пункта — удаление карточки или строки,
довод остаётся в истории git. Отложенное до жалоб — не отказ: оно живёт в «Только по жалобам».

Формат карточки:

```
### B-N. Краткий заголовок
Суть: что и зачем (с контекстом, откуда взялось).
**Принятые решения:** … (если были)
**Когда:** попутно в M# | hardening | пост-MVP | по жалобе
```

## Входящие

Сырые идеи свободным текстом. По команде «обработать входящие» каждый пункт оформляется в
карточку, получает `B-N`, раскладывается по секциям и отсюда удаляется. Этот заголовок
остаётся всегда, даже когда пусто.

- **Частичное сохранение из редактора** (автор, 2026-11-04; отложено до востребования).
  Срочно сохранить один документ из набора и вернуться в редактор. Набросок: в модалке `save`
  у строк «Отдельных файлов» чекбоксы (по умолчанию все включены; снятый приглушает строку;
  счётчики заголовка, «ФАЙЛЫ · N», кнопки и сводки следуют выбору; ни одного — кнопка
  недоступна); в «Одном файле» и из `newscan` («Сначала сохранить текущий») исключать нельзя —
  сессия после этого закрывается. Кнопка тулбара — всегда «Сохранить» с `min-width`, счётчик
  остаётся в модалке. Упирается в ядро: `SaveDocumentsRequest.names` позиционные
  (`save-flow.ts`, отказ при расхождении числа), нужен явный список номеров документов;
  отметка `journal.saved` одна на сессию — при частичной записи не ставится (точка и
  «Сначала сохранить» остаются), помарки «сохранён» на документ не заводить — это развилка
  схемы данных, под ADR. Побочно: невыбранный документ из одних пустых не держит `documentBlank`.
  Делать через бриф → мок → план на сессию.

### B-40. Открытие репозитория: код публичный, вклад закрыт

Суть: решение автора 2026-11-01 — репозиторий с кодом становится публичным (читать, проверять,
Issues, GitHub Pages), но чужой вклад не принимается: создание PR закрыто настройкой
репозитория (Settings → General → Features → Pull requests → «Creation allowed by: Collaborators
only» — постоянная, Issues при этом «All users»; уточнение автора 2026-11-04, Action
автозакрытия PR не нужен), `CONTRIBUTING.md` говорит «предложения через Issues», ruleset на
`main` — пушит только владелец.
Мотив: публичность кода и приём PR — разные вещи; риск инъекций для агентов в PR и Issues
закрывается правилом, а не настройкой GitHub.
**Принятые решения:** (а) PR не принимаются, Issues и Pages включены; (б) агент не читает
содержимое PR, Issues и комментариев сам — только по явной просьбе автора и только как данные
для разбора, чужие ветки не `fetch` — правило в `CLAUDE.md` заводится в этой же ветке; (в) CI на
`pull_request` с секретами не заводить, `pull_request_target` не использовать; (г) два
настоящих значения устройства в `docs/duplexnt-tech.md` (адрес в сети, UUID) заменяются
заглушками, исключение из стража снимается; поиск списка значений стражем для worktree починен в
B-29 (U4); `pre-push` с полным прогоном — решение автора, в B-29 не заведён (граница: в worktree
без `npm install` хука нет).
**Лицензия (решение 2026-11-01): GPL-3.0** — закрытый платный клон невозможен, проект остаётся
open source; автор — единственный правообладатель (PR не принимаются), смена лицензии или своя
платная версия остаются возможными; в README — строка «форки не могут называться Duplexn’t».
Фикстура `fan-worksheet-color-200` остаётся (решение автора 2026-11-05): изображение страницы
сгенерировано автором по мотивам реальной тетради, оформление не оригинальное — чужого копирайта
нет; происхождение записано в README фикстур.
**Решения автора 2026-11-04:** email в коммитах — GitHub `noreply` с этого момента
(`151140827+gyuiltylizard@users.noreply.github.com`, сообщён автором 2026-11-05); историю
**переписываем** (решение пересмотрено в тот же день: настоящий адрес стоит во всех 580 коммитах
и после открытия останется в форках навсегда; сейчас репо приватное, вкладчик один — единственный
дешёвый момент) — `git filter-repo` с mailmap в ветке B-40 после настройки `noreply` и до
переключения видимости, цитаты хэшей в `docs/` (~208, не только merge) обновить по таблице
«старый → новый» того же прогона, force-push в приватный `origin`; `CONTRIBUTING.md` —
по-английски, смысл: «This project does not accept
unsolicited pull requests. Please use GitHub Issues to report bugs, suggest improvements, or
discuss potential changes. Code contributions are accepted by invitation only.»
**Версии (решение автора 2026-11-04): semver**, первая публичная сборка `1.0.0-beta.1`, дальше

мажор — несовместимый формат сессии/настроек или переосмысление UI. Тег в git — `v<версия>`,

### B-15. M6.5 — калибровка сканера по тестовым листам

Суть: выравнивание M6 работает по содержимому страницы и без подсказок устройства; у

— усилитель; точки врезки заложены в M6 (`SkewPrior`, параметр `prior` детектора,
`spikes/make-calibration-pdf.mjs`); профиль привязывается к сканеру прохода, не к текущему.
**Когда:** отложено в пост-MVP решением автора 2026-10-30 (роадмап → «Вне этого роадмапа»):
сначала допиливать детектор по обратной связи и накопленным сканам; калибровка — если останется

### B-20. Подключение и подача — доводки по обратной связи

Суть: хвосты M5 (журнал `solutions/0009`) и ревью M1 (сессия 9), сверены 2026-10-30 — всё
открыто:

- повторный поиск при «не отвечает» посреди сеанса: после прохода слот меняется только на
  `scannerCertificateChanged`, при `scannerUnreachable` остаётся `ready`, `check()` в этом
  состоянии ничего не делает — проход падает, как до M5;
- повторный поиск для HTTP-профилей невозможен: `searchKey` даёт UUID только при HTTPS с
  отпечатком; другого признака или подтверждения пользователем нет;
- проба, ответившая «занят», без жёсткого срока: `PROBE_BUSY_WAIT` 15 с, срок поиска 10 с её не
  обрывает, плюс до 10 с на запрос — «проверяем…» до ~25–30 с;
- «другое устройство» по чужому кандидату показывает старый адрес (`settings-store.ts` отдаёт
  `{...located, scanner}` со старым сканером); ручное подключение во время поиска поиск не
  останавливает (`slot.use` не абортит `check`), сокеты живут до 10 с; достижимо: «Начать» в
  `setup` открывает модалку во время «проверяем…»;
- «Подключить заново» передаёт только `host:port` (`scanner-address.ts`): `ScannerInfo` схему
  уже несёт, но модалка стартует со `scheme: null`, `basePath` в `ScannerInfo` нет вовсе;
- подсказка `errorReasons.scannerUnreachable.tls` («Попробуйте схему HTTP…») не применима к
  сканеру из списка (`kind: 'discovered'` схему игнорирует); HTTP-only устройство, рвущее
  рукопожатие, даёт `reset` без подсказки и без запасного HTTP (`FALLBACK_REASONS` — только
  `refused`, `tls`);
- условие поиска — любой IPv4, без проверки «сохранённый адрес в подсети одного из
  интерфейсов»; имя `<name>.local` не хранится;
- подача: 404 на первом `NextDocument` уже отличается от конца пачки (`empty` → `scanNoPaper`
  «В лотке нет бумаги»), но текста «лист мог не захватиться» нет, а недобор после первого листа
  неотличим от конца пачки — гипотеза M1 про «ролик не взял лист» (`404`) живьём не снята;
  защита при подтверждении — подсказка сверить число страниц.

**Когда:** по жалобе; «не отвечает посреди сеанса» — первым, если жалоба придёт.

### B-22. Редактор: клик сразу после фиксации имени документа

Суть: остаточное ревью M3 (журнал `solutions/0004`, ревью сессий 3–4), живьём не наблюдалось.
Поле имени на ленте фиксирует имя по blur; пока команда имени в полёте, `edit`/`undo`/`redo`
возвращают `false` без отклика (`useEditorEdits.ts`), гард только у Enter. Окно — миллисекунды:
blur приходит на нажатии мыши, клик — на отпускании, обычно уже после ответа; проглотиться клик
может на медленном диске или при очень быстром щелчке. Мок не нужен.
**Когда:** по жалобе — «кнопка не сработала сразу после ввода имени».

от записи пакета `outcome` остаётся null, следующее «Сохранить» идёт свежим пакетом с

на деле записались, рядом лягут « (2)»; идемпотентности по ревизии нет, строка статуса просит
проверить папку; (2) временные `*.tmp` лежат рядом с целью в папке пользователя
(`atomic-file.ts`), после краха не подметаются — reconcile чистит только каталоги сессии; (3)
срока записи на медленный / сетевой диск нет (только `renameWithRetry` 5 с), таймаута IPC —
тоже.
**Когда:** по жалобе — лишний « (2)» или `*.tmp` в папке, вечное «пишем…» на сетевой папке
(автор, 2026-11-01).

### B-27. Наборы и пары — хвосты и решения автора

Суть: из M3.6, M4.5 (журналы `solutions/0006`, `0008`):

- **«Остановить» на оборотах основного документа** (решение автора на приёмке M4.5): после
  первой страницы обороты отбрасываются и экран возвращается на `flip`
  (`stopKeepsPages` в `pass-policy.ts` — только `addedBacks`), а у оборотов набора полученное
  остаётся прерванным проходом с плашкой. Решить, выравнивать ли основной документ (затрагивает
  M2 и раздельные наборы M3.6);
- число пустых оборотов в статусе `merge` набора — по всей сессии (`MergeScreen.tsx` читает
  `assembly.blank`), так утверждено в handoff'е S6; если путает — по набору;
- посадка пары в `App` дедуплицируется по `session.id + set` среди закрытых; две пары, закрытые
  одним пакетом снимков, дают одну посадку и один тост (`useSetLanding.ts`, `.at(-1)`) — узко;
- предупреждение о расхождении параметров (DPI, цвет) набора с основным документом (план M3.5;
  AE14 — обороты набора на другом сканере идут с его параметрами молча): PDF берёт DPI по
  странице — нужно ли предупреждать, решить по практике;
- поле журнала «удалённые при сборке»: после «Вернуть» удалённой при сборке страницы номера
  следующих листов сдвигаются (пример HTD «3л без листа» не выполняется); сейчас подписи по
  позиции среди не удалённых ключей записи (отклонение U2 M3.6; при решении — амендмент ADR 0004);
- физика: замятие внутри пары на живом ET-3850 не проверялось (эмулятор покрывает); разворот
  набора приходит в правильной ориентации — допущение, тумблер 180° аварийный.

**Когда:** по жалобе; первые два — решения автора, можно принять заранее.
