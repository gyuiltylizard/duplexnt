# Backlog — Duplexn't

Очередь работ. Пайплайн фичи: **backlog → `docs/plans/` (пометить «в работе») → выполнить
→ `docs/solutions/` → пункт в «Завершённое»**. Правила ведения — в `duplexnt.md` →
«Процесс».

**Нумерация.** Пункты нумеруются сквозно (`B-1`, `B-2`, …) при раскладке по секциям (сырые
идеи во «Входящих» номера не имеют). Номер даётся один раз и навсегда: не переиспользуется
и сохраняется при переносе в «Завершённое». Следующий свободный номер = максимальный
существующий по всему файлу + 1.

Источники будущих пунктов (не дублируем сюда, берём по мере надобности): спека →
«Возможности — Доработка позже» и «На отдельную проработку».

**Кластеры и порядок (якорь возобновления).** Живая карта: как пункты группируются и в
каком порядке берутся. Детали и «Принятые решения» — в самих карточках; здесь только
сквозная последовательность. **Ведение:** по мере закрытия пункта — убирать его из ячейки
«Пункты»; когда строка (кластер) пуста — удалять строку и перенумеровать «Очередь». Таблица
описывает только **незакрытое**; пустая — значит очередь разобрана.

_(пусто — очередь разобрана: B-14 закрыт 2026-10-28, см. «Завершённое»)_

**Метка «Когда»** у каждого пункта — целевой момент закрытия: код-локальные пункты
сворачиваются **попутно в свою веху**; security/latent — в **финальный hardening-проход**
перед релизом; структурное — **пост-MVP**, отдельным решением. Ориентир, не жёсткий
контракт: если пункт окажется блокером вехи — подтянуть раньше.

Формат карточки:

```
### B-N. Краткий заголовок
Суть: что и зачем (с контекстом, откуда взялось).
**Принятые решения:** … (если были)
**Когда:** попутно в M# | hardening | пост-MVP
```

## Входящие

Сырые идеи свободным текстом. По команде «обработать входящие» каждый пункт оформляется в
карточку, получает `B-N`, раскладывается по секциям и отсюда удаляется. Этот заголовок
остаётся всегда, даже когда пусто.

- **Коалесинг уведомлений о снимке (M6, код-ревью сессий 3–4):** на одну страницу прохода
  приходится 3–5 `notify()` (приём, вердикт пустоты, вердикт перекоса, исход коррекции), каждое
  — полный `assembleSession` в main и `getSnapshot` с structured clone по IPC. Склеить: в
  renderer `refresh` с флагом «запрос в полёте / dirty» и одним повтором, либо в main один
  `send` на макрозадачу с последним `seq`. Мерить на проходе 50 листов.

- **Подсказка склейки пустого оборота при показанных «Пустых» (B-13, отложено):** оборот
  подсвечивается вместе с выделенным лицом или несёт «скрепку» на миниатюре; сводка `add` —
  «после листа N» вместо «после стр. N». Нужен мок Claude Design. Сейчас — обычный курсор и
  `title` на обороте.
- **Хвосты M5 (устойчивость подключения)** — из плана и ревью вехи (журнал
  `solutions/0009`):
  - повторный поиск для HTTP-профилей — нечем доказать устройство (UUID открыт); нужен другой
    признак или явное подтверждение пользователем;
  - повторный поиск при «не отвечает» посреди сеанса (сканер уже был «готов», адрес сменился во
    время работы) — сейчас проход падает с «не отвечает», как до M5;
  - привязка к чужому устройству одним кликом остаётся там, где поиск не помогает: «Подключить
    заново» подставляет старый адрес и запоминает то, что там отвечает; плашка прерванного
    прохода подставляет адрес из журнала. Укрепление — предупреждение о смене отпечатка;
  - условие поиска «сохранённый адрес в подсети одного из интерфейсов» — сейчас ищем при любом
    IPv4; хранение имени `<name>.local` вместо IP как альтернатива поиску;
  - «другое устройство» по чужому кандидату поиска показывает строку со старым адресом, а
    «Подключить заново» подставляет старый адрес, хотя чужой ответил на другом; ручное
    подключение во время поиска не останавливает поиск — сокеты живут до срока 10 с;
  - проба, ответившая «занят», не обрывается жёстким сроком — «проверяем…» может идти до ~15 с
    (до ~30 с, если повтор после `503` повиснет на соединении).

    (`blank-backs`, `scan-job`, `two-pass`, `added-pass`); по отдельности зелёные, на `main`
    тоже — разобрать причину (пределы транспорта в тестах под нагрузкой CPU) или ограничить
    параллелизм интеграции. Повторилось 2026-10-26 на `main` после merge B-7: два прогона
    из четырёх, `separate-sets` AE7 и `blank-backs` («Остановить» на оборотах), тот же симптом. И 2026-10-27 после merge B-10: `added-pass` (набор после лица 2), после merge fix/dev-fonts: `two-pass` AE6 — оба раза два повтора зелёные.

  релизе работать не должны); проверить на установщике в смоуке U25. Декодирование изображений страниц в отдельном процессе: с M1 `sharp` разбирает в main-процессе
  байты, пришедшие от сканера (план M1, KTD-37 оставляет ему только JPEG, но не изолирует).
  Решено для тяжёлых циклов M6 — [ADR 0008](decisions/0008-image-worker.md): прямой
  исполнитель чанками в main по замеру, поток `worker_threads` — по триггерам пересмотра
  (паузы цикла, память), интерфейс исполнителя уже в ядре.
- **Сканер по USB** (вопрос автора 2026-10-22). Сейчас транспорт — только eSCL по сети, и
  МФУ, воткнутое в USB без сети, приложение не увидит; с сетью USB-шнур не мешает. Если
  поддержка USB когда-нибудь понадобится — второй транспорт под тем же клиентом, отдельная веха
  размером с M1–M2 и новый ADR (интерфейс клиента вытащить из eSCL). **Принятое решение
  (автор, 2026-10-22): делать через WIA, не TWAIN** — COM без нативного аддона (можно
  отдельным процессом-помощником), тогда как TWAIN требует C++ аддон поверх `TWAINDSM.dll`,
  цикл сообщений и нативную сборку под каждую версию Electron. Эмулятор сканера для такого
  транспорта бесполезен — нужен свой подставной источник. **Когда:** пост-MVP, отдельным
  решением; до него правило спеки «WIA/TWAIN не добавлять» в силе.
- Деинсталлятор не спрашивает про данные: каталог данных остаётся, и сканы последней сессии
  переживают удаление приложения (ADR 0004). Решить к первому публичному релизу: спрашивать ли
  «удалить и данные?» при деинсталляции. Удаление без вопроса исключено правилом «данные
  священны».
- Страж приватности в отдельном git worktree работает без списка значений и без hook'а: списка
  нет (каталог `local-test-data/` вне git), `.husky/_` генерируется при установке. Предложение
  код-ревью M0: искать список через общий каталог git (`git rev-parse --git-common-dir`) и
  добавить `pre-push` с полным прогоном. Меняет процесс — нужно решение автора.
- Пробелы в тестах из код-ревью M0, оставшиеся после M1 (U5): путь `--staged` и код выхода CLI
  стража проверены только вручную; нет теста, что собранная страница несёт сборочный профиль CSP.
- Чёрно-белый режим. ET-3850 перечисляет `BlackAndWhite1` в capabilities, но задание с ним и
  `image/jpeg` отклоняет (`409`) — снято в M1, U1 (`docs/solutions/0002`). В M1 режим из списка
  исключён. Вернуть можно порогом на своей стороне: сканировать в сером и бинаризовать при
  сборке. Решить вместе с постобработкой.
- Автообрезка страницы. Доворот (deskew) закрыт вехой M6: веер подачи и постоянный наклон
  выпрямляются по содержимому страницы (техбаза «Детектор перекоса», «Ресэмплер»). Остаётся
  обрезка: лист в автоподаче ET-3850 гуляет на ±1,5 мм (M1, U1), регион размером с лист
  срезает до 2,6 мм бумаги с одной стороны; целиком лист даёт только скан на всю ширину поля с
  обрезкой по контуру у себя — постобработка за кнопкой «Авто».
- Сбой «ролик не взял лист» по сети не снят (M1, U1): воспроизведение придержанным листом
  оставило устройство в ошибке автоподачи до перезагрузки. Гипотеза — обычный `404`, как при
  конце пачки. Если подтвердится на практике, защита — подсказка сверить число страниц.

## Крупные

### B-15. M6.5 — калибровка сканера по тестовым листам

Суть: выравнивание M6 работает по содержимому страницы и без подсказок устройства; у
конкретного сканера остановка подачи повторяется в одном месте, и калибровка по напечатанным
тестовым листам даст детектору подсказку формы (ступень: `u0`, ширина, угол низа) — увереннее
на бедных страницах и быстрее. Брейншторм
[2026-10-28-local-skew-correction-requirements.md](brainstorms/2026-10-28-local-skew-correction-requirements.md)
(origin R15–R21, AE4–AE5, F3), роадмап — M6.5 с «Входами».
**Принятые решения:** вынесено из M6 автором 2026-10-28 — база работает из коробки, калибровка
— усилитель; точки врезки заложены в M6 (`SkewPrior`, параметр `prior` детектора,
`spikes/make-calibration-pdf.mjs`); профиль привязывается к сканеру прохода, не к текущему.
**Когда:** отдельная веха после приёмки M6.
