# Handoff — состояния интерфейса M1, которых нет в макете

Один handoff на всё, чего в макете `mock/Сканер ADF.dc.html` нет, а веха M1 показывает: прерванный
проход, потерянная страница, состояния запомненного сканера, ожидание занятости, пустой лоток,
пустое и сломанное обнаружение, ход подключения, подтверждение «Новое сканирование», экран несовместимых
данных, счётчик при досканировании, тексты одного прохода и каркас `editor`, состояния миниатюр,
уведомления запуска, «Останавливаем…», пометка схемы, смена сертификата. Закрывает юнит U19 плана
`docs/plans/2026-10-02-001-feat-m1-connect-single-pass-plan.md` (R16, R23; KTD-25). Экраны:
`setup`, `scan`, `editor`, модалка `device`, новая модалка `newscan`, новый экран `incompatible`.

**Мока нет** — по решению автора (план M1, KTD-2) состояния собираются из готовых рецептов
`../DESIGN_SYSTEM.md`; новых токенов и компонентов здесь нет, а единственное место, где без
нового, возможно, не обойтись (кольцо фокуса), вынесено в «Открыто». Экраны из макета делаются по макету и `../UI_SPEC.md` и здесь не
повторяются. **Статус: утверждён автором** (сессия 6 M1, 2026-10-03) — по предложениям агента во всех шести
развилках, с одной поправкой: слово «пачка» заменено на «листы» / «страницы», действие — «Новое
сканирование».

**Как читать.** Состояния пронумерованы `S1`…`S22` и сгруппированы по экранам; в каждом
разделе шаблона состояние ищется по номеру. Классы — предложение для U20 в стиле уже принятого в
renderer БЭМ (`.shell__header`, `.status--pending`); значения — только токены `tokens.css`.
Фикстурный сканер в примерах — вымышленный «ScanPro 200» по адресу `192.0.2.10` (документационный
диапазон), 24 листа, обрыв после 17-го.

| S2  | Запомненный сканер: проверяется                               | `setup`, строка устройства (первая строка группы параметров)                                               |
| S3  | Запомненный сканер: не отвечает                               | там же                                                                                                     |
| S4  | Запомненный сканер: по адресу другое устройство               | там же                                                                                                     |

| S12 | Тексты `scan` для одного прохода                              | `scan`: тег прохода, счётчик                                                                               |
| S13 | Ожидание занятости                                            | `scan`: блок иллюстрации и счётчика; «Остановить» остаётся                                                 |
| S14 | Счётчик и лента при досканировании                            | `scan`: счётчик, подпись под ним, лента                                                                    |
| S15 | «Останавливаем…»                                              | `scan`: кнопка «Остановить»                                                                                |

| S21 | Подтверждение «Новое сканирование»; не удалось закрыть сессию | модалка `newscan` над `editor`; отказ — в её статусной строке и тостом над `editor`                        |
| S22 | Экран несовместимых данных                                    | отдельный экран `incompatible` вместо любого другого; модалок и тостов над ним нет                         |

Что меняется в существующем:

- **`setup`.** Сетка `grid-template-columns: 1fr var(--size-aside)` становится одной колонкой:
  левая колонка центрируется по окну, правой нет (S1). Строки параметров — три (цвет, разрешение,
  размер листа), без «Пустые обороты»; значения — из capabilities, без «Авто» (KTD-25). Под
  кнопкой запуска появляется слот плашки S6.
- **`scan`.** Между иллюстрацией и счётчиком ничего не добавляется; состояния S13–S15 меняют
  содержимое уже существующих мест.
- **`editor`.** Сетка тулбара и тела — `var(--size-rail) minmax(0, 1fr)` вместо трёх колонок.
  Из макета остаются: левая группа тулбара с одной кнопкой, лента, превью, статус-бар с «←»,
  счётчиком и «→». Всё остальное из макета в разметке отсутствует (KTD-25).
- **`device`.** Поле «Схема» в «Дополнительно» становится сегментированным выбором из двух
  сегментов `HTTPS` / `HTTP` (техбаза → «Что в макете нужно поправить»); дефолты HTTPS · 443 ·
  `/eSCL`. Остальные изменения — состояния S7–S11.
- **Тост.** Без изменений рецепта; новые тексты — в Copy.

## Anatomy

Разметка с фикстурным текстом; `t()`-ключи — в Copy. Повторяющиеся примитивы: `.btn`
(`--primary` / `--secondary` / `--ghost`, размер `--large` / `--compact`), `.kicker`, `.dot`
(точка статуса), `.notice` (информационная плашка), `.skeleton`.

## Behaviour

- **Открытие / закрытие.**
  - S6 показывается сразу по отказу `startPass`; снимается следующим нажатием кнопки запуска,
    открытием `device` и уходом с экрана. Другого «закрыть» у неё нет.
  - S7 включается таймером экрана через 10 с после открытия `device` (ядро поиск не
    останавливает); S8 — сразу по снимку обнаружения. Закрытие модалки останавливает поиск и
    отменяет идущее подключение (U21).
  - S17 живёт, пока последний проход в состоянии «прерван»; уходит по «Оставить как есть», по
    успешному досканированию (проход «завершён») и по «Новому сканированию».
  - S20 — плашка исчезает по «Понятно»; без нажатия живёт до перезапуска. Уведомление показывается
    один раз за запуск: закрытие не пишется на диск, снимок уведомлений читается без сброса.
  - S21 закрывается «Отмена», успехом или `Esc`-эквивалентом — по `UI_SPEC.md` 7 закрытия по Esc
    и клику вне окна нет; здесь так же.
  - S22 не закрывается: из него только «Открыть папку с данными» (окно остаётся) и «Выйти».
- **Указатель.**
  - Ghost-кнопки строки устройства: hover — `text-decoration: underline` (как «Сменить» в
    макете). «Повторить» и «Подключить заново» — те же правила.
  - `.notice` и `.pass-banner` не кликабельны целиком — только их кнопки.
  - Миниатюры S18 и S19 выбираются кликом, как обычные: превью показывает соответствующее
    состояние. `cursor: pointer`, не `grab` (перетаскивания в M1 нет).
  - Бейдж `HTTP` (S5) — не кнопка; `title` показывает пояснение.
  - Скелетон (S19) и область «Сканер занят» (S13) событий не принимают.
- **Клавиатура.**
  - Порядок фокуса на `setup`: плашки уведомлений (их «Понятно») → строка устройства (кнопки
    слева направо) → сегменты параметров → «Сбросить параметры» → кнопка запуска → кнопка в
    плашке S6, если есть.
  - `device`: ловушка фокуса в модалке; Tab идёт список → поле адреса → «Дополнительно» →
    сегменты схемы / порт / путь → «Отмена» → «Подключить». В S10 «Подключить» выпадает из обхода
    (`disabled`), фокус переносится на «Отмена». После закрытия фокус возвращается на кнопку,
    которая открыла модалку («Сменить», «+ Добавить сканер», «Повторить», «Подключить заново»).
  - `scan`: единственный фокусируемый элемент — «Остановить»; в S15 он `disabled`, фокус уходит
    на контейнер экрана (`tabindex="-1"`), чтобы не потеряться.
  - `editor`: «Новое сканирование» → плашки S20 → кнопки S17 слева направо → лента (listbox: стрелки
    ←/→ переключают выбранную страницу, Home/End — первая/последняя) → «←» / «→» статус-бара.
    `Enter`/`Space` на миниатюре — выбор. `Delete` ничего не делает (удаления в M1 нет).
  - S21: начальный фокус на «Отмена» (U24); Tab — «Отмена» ↔ «Удалить и начать заново»; `Enter`
    на «Отмена» — закрыть.
  - S22: фокус при открытии на «Открыть папку с данными».
  - Живые регионы: счётчик `scan` и текст занятости — `role="status" aria-live="polite"
aria-atomic="true"`; отказы (S6, S8, S11, статусы S17 и S21) — `role="alert"`; плашки S20 —
    `role="status"`.
- **Гейтинг.**
  - Ряды параметров недоступны, пока сканер не подтверждён (S2, S3, S4, «не подключён»); при
    этом они показывают запомненные значения, а не пустоту. Доступны — только при «готов».
  - Кнопка запуска доступна всегда (как в макете): без подтверждённого сканера она открывает
    `device`, а не проход.
  - «Досканировать остаток» есть только при `canResume === true` (параметры прохода известны
    и подключён тот же сканер — KTD-27); иначе кнопки нет, причина названа текстом плашки
    (KTD-25: неработающих элементов нет). Ядро всё равно может отказать по клику — например,
    `sessionConflict.paramsUnknown`, если снимок устарел; текст — строкой под действиями.
  - «Оставить как есть» и «Новое сканирование» недоступны, пока идёт сегмент (ядро отклоняет —
    KTD-33); на экране `scan` этих кнопок и нет, в `editor` они не появляются до конца прохода.
  - «Подключить» в `device` при пустом поле и без выбора — не запрос, а подсказка в статусной
    строке (как в макете). В S8 список выбрать нельзя, ручной адрес — можно.
  - В S22 нет ни прохода, ни «Нового сканирования»: экран других действий не содержит.
- **Движение.**
  - `pulse` `--duration-loop` `--ease-loop` на скелетонах (S19), точке «проверяем…» (S2) и трёх
    скелетонах поиска (макет); соседние скелетоны ленты — сдвиг `--delay-stagger`.
  - В S13 цикл `feed` и `pulse` полосы прогресса останавливаются (`animation: none`), полоса
    приглушается `--opacity-disabled`; возврат в S12 — анимация включается снова, без перехода.
  - Появление плашек, модалки `newscan`, экрана `incompatible` — без анимации (как у всех
    модалок и тостов макета).
  - Под `prefers-reduced-motion: reduce` — все циклы `feed` и `pulse` выключены; скелетон стоит
    статичным, приглушённым.

## Decisions and open questions

- **Решено: состояния собираются из рецептов, мока нет** — решение автора (план M1, KTD-2).
  Отклонён мок на все 22 состояния: экраны-носители уже утверждены в макете, а состояния —
  подстановки в их существующие места.
- **Решено: отказ запуска прохода — плашка на `setup` под кнопкой, не тост и не модалка.**
  Тост гаснет через 2,6 с, а «нет бумаги» нужно прочитать и исправить; модалка — лишний клик
  на событие, которое повторяется каждый раз, когда забыли положить листы. Один слот на все
  причины: двух отказов одновременно не бывает.
- **Решено: причина обрыва в плашке S17 не называется.** Четыре состояния устройства M1 —
  занят, не отвечает, нет бумаги, прерван — без выяснения причин (решение автора); после
  перезапуска причина и так неизвестна, журнал версии 1 её не хранит. Заголовок несёт номер
  последней страницы — это и есть действие: «положите листы с 18-го». (Отклонено показывать
  причину, пока она в памяти: два разных текста для одного состояния в зависимости от того, был
  ли перезапуск.)
- **Решено: «Досканировать остаток» при неизвестных параметрах не рисуется, причина — в тексте
  плашки.** По KTD-25 неработающих элементов нет; `disabled` с `title` — отклонено, потому что
  подсказка в `title` недоступна с клавиатуры, а текст плашки виден всем.
- **Решено: уведомления запуска — полоса плашек с «Понятно», не тост.** Их может быть несколько
  сразу (`journalRebuilt` + `pagesLost` + `settingsIncompatible`), и каждое важнее 2,6 с.
  Отклонена модалка: ни одно из них не требует решения.
- **Решено: потерянная страница и несобранная миниатюра различаются формой, а не только
  текстом:** пунктир + «ФАЙЛ ПОТЕРЯН» против сплошной рамки + «НЕТ МИНИАТЮРЫ». Первое —
  утрата данных, второе — косметика; превью во втором случае показывает саму страницу.
- **Решено: «Новое сканирование» — единое имя действия** в тулбаре, в плашке S17 и в заголовке
  модалки; «Новый скан» из макета уходит (правка `UI_SPEC.md`). Слово «пачка» — рабочий термин
  спеки и плана, в тексты интерфейса оно не идёт (решение автора): про бумагу в лотке — «листы»,
  про отсканированное — «страницы». Модалка M1 без
  карточки «Сначала сохранить» (сохранения нет до M2) — обычный диалог подтверждения с
  начальным фокусом на «Отмена».
- **Решено: порт найденного сканера показывается всегда**, даже 443: адрес и порт — единственная
  защита от поддельного объявления (ревью сессии 4), а скрывать «обычный» порт — значит
  скрывать разницу между двумя записями одного устройства.
- **Решено: `setup` в одну колонку.** Правая колонка «Как это работает» описывает два прохода и
  разворот; без неё окно с одной левой колонкой перекошено, поэтому колонка центрируется.
  Отклонено оставить пустую правую подложку: пустая панель выглядит недоделкой.
- **Решено (автор, сессия 6): кольцо фокуса — без нового токена.** В дизайн-системе
  `:focus-visible` не задан (открытый вопрос 6 DS); берётся `outline: var(--space-1) solid
var(--color-border-focus); outline-offset: var(--space-1)`. Отклонён токен `--focus-ring-width`:
  одно значение в одном месте не стоит записи в системе.
- **Решено (автор, сессия 6): заголовок `setup` — «Сканируем листы из автоподатчика», кнопка —
  «Сканировать листы».** Отклонено «Сканируем листы в один проход» / «Начать проход»: слово
  «проход» до первого запуска ничего не значит.
- **Решено (автор, сессия 6): текст пустого обнаружения — новый, с запросом брандмауэра Windows,**
  без слов AirPrint / Bonjour: пользователю ET-3850 они ничего не говорят.
- **Решено (автор, сессия 6): `storage.unsaved` в M1 на экране не показывается.** Данные не
  теряются, сверка вернёт страницу по ключу, флаг живёт секунды. Подпись в тулбаре отклонена.
- **Решено (автор, сессия 6): прошедшее время в ожидании занятости не показывается** — «ждём до
  минуты» достаточно; живой счётчик озвучивался бы каждую секунду.
- **Решено (автор, сессия 6): у не отвечающего сканера — отдельная ghost-кнопка «Повторить»**
  рядом со «Сменить»; для неё в U21 заводится команда моста `recheckScanner`. Отклонено «только
  «Сменить»»: короче, но прячет способ не ходить в модалку.
