# Handoff — состояния интерфейса M2, которых нет в макете

Один handoff на всё, чего в макете `../archive/Сканер ADF.dc.html` нет, а веха M2 показывает:
занятость сканера на `flip`, возврат на `flip` после перезапуска, дополненный чеклист разворота,
варианты статусной строки `merge`, модалка `mismatch` без кнопок действия и с тремя исходами,
пометка непарного листа в ленте, тумблер «повернуть обороты на 180°», состояния кнопки
«Сохранить документ», индикация несохранённого — и Copy всех текстов M2 без слова «пачка».
Закрывает юнит U7 плана `../../plans/2026-10-04-001-feat-m2-two-passes-merge-plan.md`
(R9 UI-часть, R14; KTD-2, 8, 11). Экраны: `flip`, `merge`, `scan` (тексты второго прохода),
`editor`, новая модалка `mismatch`.

**Мока нет** — как в M1 (`2026-10-m1-states.md`): экраны `flip` и `merge` и каркас `mismatch`
есть в макете и делаются по макету и `../UI_SPEC.md` §4–5, 7.5; здесь — только дырки и
подстановки из готовых рецептов `../DESIGN_SYSTEM.md`. Новых токенов нет.
**Статус: утверждён автором 2026-10-04** (гейт U7 закрыт; оба открытых вопроса решены — см.
«Decisions and open questions»: порядок фокуса `editor` — естественный, слова «стопка» в Copy
нет — «все листы разом» / «не меняя порядок листов»).

**Как читать.** Состояния пронумерованы `S1`…`S9` и сгруппированы по экранам. Классы — в стиле
принятого в renderer БЭМ; значения — только токены `tokens.css`. Фикстура в примерах: 12 листов
лицевого прохода; варианты второго прохода — 11 страниц (без оборота остаётся лист №1 — обороты
приходят в обратном порядке и считаются от последнего листа), 13 страниц (лишний оборот в конце
набора), остановлен и принят на 7 (без оборота листы №1–5).

**Номер прохода — не роль.** Везде ниже «проход оборотов» — второй **уцелевший** проход сессии
(план M2, KTD-4): после «Остановить» и перезапуска он получает номер 3, но тег, счётчик, тумблер
и сборка ведут себя как у оборотного.

## Placement

| №   | Состояние                                                  | Где живёт                                                                              |
| --- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| S1  | Тексты `flip`: кикер с числом листов, чеклист из 4 пунктов | `flip`: все тексты экрана; чеклист получает новый первый пункт про входной лоток       |
| S2  | `flip`: сканер занят после запуска оборотов                | `flip`: первичная кнопка и строка статуса под кнопками; по потолку — плашка `.notice`  |
| S3  | `flip` после перезапуска между проходами                   | `flip` целиком — та же раскладка, данные из журнала                                    |
| S4  | Статусная строка `merge` — фактический результат           | `merge`: строка под диаграммой (в макете — константа) и строка-формула над ней         |
| S5  | Модалка `mismatch`: сообщает, три исхода                   | новая модалка над `editor`; кнопок действия из макета нет — одно «Понятно»             |
| S6  | Пометка непарного листа                                    | `editor`: футер миниатюры лицевой страницы без пары; живёт после закрытия `mismatch`   |
| S7  | Тумблер «повернуть обороты на 180°»                        | `editor`: низ ленты (слот переключателя пустых оборотов из макета — тот появится в M4) |
| S8  | Кнопка «Сохранить документ»: rest / идёт / ошибка          | `editor`: правая зона тулбара (новая); ошибка — тост по анатомии UI_SPEC §8            |
| S9  | Индикация несохранённого                                   | `editor`: янтарная точка слева от кнопки сохранения                                    |

Что меняется в существующем:

- **`setup` и `scan`.** Возвращаются полные тексты макета (двухпроходный сценарий, колонка
  «Как это работает», тег «ПРОХОД N · ОБОРОТЫ», счётчик «Отсканировано N из M») — это макет,
  не handoff; здесь только их Copy без «пачки». Параметр «Пустые обороты» не показывается (M4).
- **`editor`.** Тулбар получает правую зону: сетка `var(--size-rail) minmax(0, 1fr)` →
  `var(--size-rail) minmax(0, 1fr) auto`; в ней S9 + S8. Лента: у оборотов тег «об» в футере
  миниатюры (макет, UI_SPEC §6.2), у непарных лиц — S6; внизу ленты — S7. Остальной каркас —
  без изменений (KTD-25 M1 продолжает действовать: инспектора, правок страниц, «Добавить» нет).
- **`merge`.** Заголовок — «Сопоставляем проходы» (мы-форма, как все тексты M1; в макете
  «Сопоставляю»); при «Обороты не нужны» ряд оборотов не рендерится. Статусная строка — S4.
- **`mismatch`.** Каркас модалки из макета, но три кнопки действия удаляются (UI_SPEC §7.5 —
  решено при разборе), Copy — без отсылки к «Добавить» (его нет до M3).

## Anatomy

Разметка с фикстурным текстом; `t()`-ключи — в Copy. Примитивы `.btn`, `.kicker`, `.dot`,
`.modal`, `.notice`, `.toggle` — рецепты дизайн-системы.

### `flip` — S1–S3

Экран по макету; ниже — зона действий со строкой статуса (S2) и слотом плашки.

```html
<div class="flip-screen__actions">
  <!-- rest -->
  <button type="button" class="btn btn--primary btn--large">
    Листы в лотке — сканировать обороты
  </button>
  <button type="button" class="btn btn--link">Обороты не нужны</button>

  <!-- S2: занятость — кнопки заменяются на время ожидания -->
  <button type="button" class="btn btn--primary btn--large" disabled aria-busy="true">
    Ждём, пока сканер освободится…
  </button>
  <p class="flip-screen__status" role="status" aria-live="polite">
    Сканер заканчивает прошлый проход и выпускает оставшиеся листы в выходной лоток. Заберите их,
    чтобы набор оборотов был полным, — сканирование начнётся само.
  </p>

  <!-- S2: не освободился за потолок — плашка, кнопки снова доступны -->
  <div class="notice notice--danger" role="alert">
    <p class="notice__text">
      Сканер занят и не освободился за минуту. Дождитесь, пока он закончит, и запустите ещё раз.
    </p>
  </div>
</div>
```

## Behaviour

- **Открытие / закрытие.**
  - S2 наступает сразу по нажатию «Листы в лотке — сканировать обороты» при занятом устройстве;
    выходы два: страницы пошли (→ `scan`) или потолок ретрая (→ `flip` rest + плашка). Плашка
    снимается следующим нажатием и уходом с экрана. Занятость **посреди** прохода — не здесь:
    это S13 M1 на `scan`.
  - S5 показывается при первом входе в `editor` за процесс, пока несовпадение не подтверждено;
    «Понятно» закрывает и подтверждает до конца процесса. После перезапуска с неподтверждённым
    несовпадением — показывается снова: падение в окне паузы `merge` не глотает её (KTD-8).
    Esc и клика вне окна нет — как у всех модалок (UI_SPEC §7).
  - S6 живёт независимо от модалки: пока у листа нет пары. Приёмка прерванного прохода оборотов
    пересчитывает отчёт — пометки следуют за фактическими парами.
  - `merge` — пауза 1600 мс (1200 мс после «Обороты не нужны»), уходит сам, органов управления
    нет; после перезапуска пауза не повторяется (KTD-5).
- **Указатель.**
  - Точка S6 и точка S9 — не кнопки; пояснение в `title`.
  - Вся строка `.toggle-row` кликабельна (label), hover не меняет фон — переключение видно по
    самому тумблеру.
  - «Сохраняем…» и «Ждём…» события не принимают (`disabled`).
- **Клавиатура.**
  - `flip`: обход — «Листы в лотке — сканировать обороты» → «Обороты не нужны». В S2 обе
    недоступны, фокус уходит на контейнер экрана (`tabindex="-1"`), как S15 M1.
  - `merge`: фокусируемых элементов нет; фокус на контейнере экрана.
  - `mismatch`: ловушка фокуса; начальный фокус и единственный стоп — «Понятно»; `Enter` —
    закрыть. После закрытия фокус — на контейнер `editor`.
  - `editor`: тумблер — `Space` переключает; кнопка сохранения — `Enter`/`Space`. Порядок
    обхода — естественный (решение автора, 2026-10-04): тулбар (правая зона в конце) →
    уведомления → лента (тумблер в конце) → превью.
  - Живые регионы: строка статуса S2 и статусная строка `merge` — `role="status"`; плашка
    потолка S2 и тост ошибки сохранения — `role="alert"`.
- **Гейтинг.**
  - «Сохранить документ» недоступна: при пустом наборе, во время идущего прохода/сегмента и на
    время своей же работы (S8). Причина не пишется — состояния очевидны из экрана.
  - Тумблер доступен всегда, когда есть проход оборотов, в том числе у прерванно-принятого.
  - «Обороты не нужны» недоступна только в S2 (проход уже запущен).
- **Движение.**
  - `turn180` — цикл 3800 мс из макета; под `prefers-reduced-motion: reduce` — статичный
    развёрнутый кадр, подпись остаётся.
  - Поворот миниатюр/превью при S7 — `transform` за `--duration-fast`; под reduced-motion — без
    перехода.
  - Пульс ряда оборотов на диаграмме `merge` — `pulse` из макета; под reduced-motion выключен.
  - Появление модалки, плашек, тостов — без анимации (конвенция макета).

## Decisions and open questions

- **Решено: занятость — на `flip`, не на `scan`** (план M2, KTD-11). Ожидание после «Остановить»
  — это момент, когда листы физически доезжают в выходной лоток: напоминание забрать их осмысленно
  только на экране разворота. Правило: чётный проход в фазе `busy`/`starting` без единой страницы
  → экран остаётся `flip` (S2); первая страница или фаза `scanning` → `scan`. Занятость посреди
  прохода — S13 M1 без изменений. (Отклонено уходить на `scan` сразу по нажатию: «Сканер занят»
  без контекста разворота читается как поломка.)
- **Решено: возврат после перезапуска — та же раскладка `flip`, без плашки** (R6). Кикер «ЛИЦА
  ГОТОВЫ: N листов» уже говорит всё, что сказала бы плашка. (Отклонена плашка «вы вернулись»:
  дублирует кикер.)
- **Решено: тумблер 180° — внизу ленты,** в слоте, где в макете живёт переключатель пустых
  оборотов (M4): оба — режимы показа ленты, пусть живут в одном месте. (Отклонён тулбар: правая
  зона занята сохранением, а тумблер — не действие над документом, а режим отображения прохода.)
- **Решено: индикация несохранённого — точка у кнопки сохранения,** по образцу янтарной точки
  кикера `newscan` (UI_SPEC §7.4). Решение M1 «unsaved не показывается» пересмотрено ровно в
  объёме M2: появился PDF, которому индикация и служит. (Отклонена подпись текстом: шум в
  тулбаре; отклонён бейдж на кнопке: первичная кнопка с янтарной точкой внутри спорит с её фоном.)
- **Решено: пометка непарного листа — янтарная точка в футере миниатюры,** не метка на «бумаге»:
  метки на бумаге (`ФАЙЛ ПОТЕРЯН`, `ПУСТО` в M4) означают состояние самой страницы, а здесь
  страница в порядке — не хватает пары. Точка и `title` этого достаточно; полный блок
  «Проверка» — M3.
- **Решено: `mismatch` без кнопок действия** — закреплено ещё в UI_SPEC §7.5; Copy переписан без
  отсылки к «Добавить» (ловушка плана U7: «Добавить» нет до M3). Три исхода — три пары
  заголовок+текст, кнопка одна.
- **Решено: чеклист `flip` — новый пункт про входной лоток первым.** «Ролик не взял лист» в
  первом проходе неотличим от конца пачки, оба прохода дают равное число и `mismatch` молчит;
  единственная защита — глаза человека, опора — кикер с фактическим числом листов.
- **Решено: заголовок `merge` — «Сопоставляем проходы»** (в макете «Сопоставляю»): все тексты
  приложения с M1 — в мы-форме.
- **Решено (автор, 2026-10-04): порядок фокуса `editor` — естественный.** Обход «тулбар →
  уведомления → лента (тумблер в конце) → превью»: DOM совпадает с видимым порядком, плашки
  запуска озвучиваются живыми регионами (`role="alert"`/`"status"`) независимо от места в
  обходе. Правило M1 «уведомления первыми» снято. (Отклонено: рендерить плашки перед тулбаром —
  разметка расходится с экраном.)
- **Решено (автор, 2026-10-04): «стопки» в текстах нет** — как и «пачки». Про разворот
  целиком — «все листы разом» (`flip.title`, `flip.lead`, `flip.illustration`, `setup.lead`,
  `setup.how.step2`), про сохранение порядка — «не меняя порядок листов»
  (`flip.check.keepOrder`), «набор оборотов» в `flip.busy.text`. Copy выше уже переписан.
