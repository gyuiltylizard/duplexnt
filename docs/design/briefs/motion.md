# Brief — движение в интерфейсе

Интерфейс Duplexn't ощущается резким: экраны сменяются скачком, новые страницы на экране
сканирования появляются рывком, миниатюра поворачивается мгновенно, модалка при смене
содержимого прыгает по высоте. Это замечания автора со смоук-приёмок M2 (2026-10-05) и M3
(2026-10-06), карточка **B-4** бэклога. Нужен единый язык движения — тихий, короткий,
обратимый, в духе принципа 5 `DESIGN_SYSTEM.md` («Тихое движение»), — и применение его к пяти
местам ниже. Это один бриф, а не пять: движение должно читаться как одна система, а не как
набор отдельных эффектов. Брейншторма не было — продуктовые вопросы ниже помечены как
допущения.

Сцены референса: `scan-fronts`, `scan-backs`, `flip`, `merge`, `editor`, `save` и остальные
(`reference/index.html#<сцена>`). Граф переходов между экранами — `UI_SPEC.md` §1, тайминги —
§9.

## Что спроектировать

1. **Смена экранов.** Экраны `setup` → `scan` → `flip` → `scan` → `merge` → `editor` (и
   обратные пути: «Остановить» возвращает на экран запуска, «+ Добавить» ведёт из `editor` в
   `scan`) сейчас подменяются мгновенно. Переход должен сказать «процесс идёт дальше», не
   задерживая человека: `scan` и `merge` — процессные экраны, уходят сами; `setup`, `flip`,
   `editor` ждут человека. Переход не должен растягивать паузы, которые уже есть (пауза после
   последней страницы прохода, пауза `merge` — `UI_SPEC.md` §9).
2. **Лента последних страниц на `scan`** (`.strip`, пять карточек, затухание к краю
   1 → 0,32). Новая страница появляется рывком, очередь сдвигается скачком. Нужно: появление
   новой карточки и сдвиг остальных, когда шестая выталкивает первую. Страницы приходят
   примерно раз в 300 мс — движение должно успевать и не накапливать очередь анимаций.
   Миниатюра сначала скелетон, потом картинка (`strip__card--loading`) — это тоже часть
   появления.
3. **Поворот миниатюры и превью в `editor`** (кнопки ↺ ↻ под превью — текущая страница или всё
   выделение; тумблер «Повернуть обороты на 180°» в подвале ленты). Сейчас без анимации — её сняли сознательно в M3: угол
   хранится по модулю 360, и переход 270° → 0° анимировался бы назад, на три четверти
   оборота (`handoffs/2026-10-m3-states.md`, «Движение»). Нужна схема, при которой поворот
   всегда идёт в сторону команды на 90° (а тумблер — на 180°), и миниатюра с превью вращаются
   согласованно.
4. **Высота модалки при смене содержимого** (`.modal`). Пример — `save`: после записи модалка
   может остаться в состоянии **ИТОГ** (фактические имена файлов, ✓/✕ по каждому, статус
   «Записано N из M.»), и высота меняется скачком. Состояния ИТОГ в референсе нет — состав
   описан в `UI_SPEC.md` §7.3 («Запись и итог»); в моке его стоит собрать. Сюда же — открытие
   и закрытие модалок и тост: сейчас без анимации по конвенции исходного макета, решение —
   за тобой, в той же системе.
5. **Подсказка про Ctrl/Shift** в инспекторе `editor`, блок «ДОКУМЕНТЫ В НАБОРЕ» — строка под
   списком документов о том, как поставить границы (split-бар или выделение: Shift — диапазон,
   Ctrl — по одной). Автор хочет, чтобы при первом запуске она несколько раз мигнула и её
   заметили. Нужна форма «обратить внимание», которая не превращается в тревогу и не
   повторяется бесконечно.

## Какое поведение сделать рабочим в моке

- Панель сценариев: «пройти весь путь» — `setup` → `scan` (страницы приходят по таймеру) →
  `flip` → `scan` оборотов → `merge` → `editor`, с кнопкой «Остановить» на `scan`.
- На `scan` страницы реально приходят раз в ~300 мс, лента живёт: появление, сдвиг,
  затухание, выталкивание шестой.
- В `editor` кнопки ↺ ↻ и тумблер 180° поворачивают текущую миниатюру и превью; несколько
  нажатий подряд, включая проход через 270° → 0°, — всегда в сторону команды.
- Модалка `save`: «Сохранить» → короткое «пишем…» → ИТОГ (с переименованным файлом и одним
  ✕) — высота меняется плавно; закрытие, повторное открытие.
- Переключатель «первый запуск» — подсказка про Ctrl/Shift мигает; повторное открытие
  `editor` — уже нет.
- Переключатель `prefers-reduced-motion` (или эмуляция) — всё движение сводится к мгновенной
  смене или короткому fade, ничего не крутится и не мигает.

## Стадии

Для поворота (п. 3) и смены экранов (п. 1) форма неясна — сначала отдельная страница с 2–3
действительно разными вариантами каждого (например, смена экранов: перекрёстное
растворение / короткий сдвиг по направлению процесса / смена только содержимого при
неподвижном каркасе), без контекста. Ждать выбора автора. Потом — выбранное в контексте всех
сцен. Пп. 2, 4, 5 — сразу в контексте.

## Вне скоупа

- Редизайн экрана `merge` — отдельный бриф (`briefs/merge.md`, B-5). Здесь `merge` участвует
  только как экран в цепочке переходов.
- Циклические иллюстрации `feed`, `turn180`, `pulse` уже есть и не пересматриваются; их темп
  (1,2 и 3,8 с) — опора для нового движения.
- Перетаскивание страниц в ленте `editor`, маркер вставки, split-бар (проявляется за
  `--duration-fast`) — работают и не меняются.
- Состав экранов, тексты и раскладка — не меняются; бриф только про движение.
- Анимация «сортировки» листов — это B-5.

## Открытые вопросы / допущения

- **Допущение:** «первый запуск» для подсказки — первый раз, когда человек видит в `editor`
  блок «ДОКУМЕНТЫ В НАБОРЕ» с подсказкой, один раз на установку (запоминается в настройках).
  Сколько миганий — предложи; автор говорил «несколько раз».
- **Допущение:** движение не задерживает работу: человек может нажать кнопку, не дожидаясь
  конца анимации, и действие выполняется сразу.
- Если сочтёшь, что какому-то из пяти мест движение не нужно или нужно иначе, чем просил
  автор, — предложи в handoff'е с доводом.
