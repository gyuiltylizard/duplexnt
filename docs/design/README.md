# docs/design — пакет для дизайн-агента

Ты работаешь над **Duplexn't** — десктопным приложением для Windows (Electron), которое
сканирует двусторонние документы на МФУ с односторонним автоподатчиком (Epson ET-3850) по
сети. Сканирование идёт в два прохода: сначала лицевые стороны пачки, потом человек
разворачивает пачку на 180° и сканирует обороты, а приложение само сводит лица и обороты в
листы. Дальше — редактор: порядок, повороты, пустые обороты, разбивка на документы, сохранение
в PDF. Интерфейс на двух языках — русском и английском (B-41); русский задаёт раскладку
(он длиннее), английский обязан в неё укладываться. В референсе каждая сцена снята на обоих
языках — переключатель `RU | EN` рядом с вкладками сцен.

Эта папка даёт тебе приложение **таким, какое оно есть сейчас**, и просит построить поверх
него **интерактивный мок**. Новый интерфейс проектируется и утверждается в моке; каждый
утверждённый компонент превращается в компактный **handoff**, который агент-разработчик
внедряет в приложение. Папку можно получить целиком отдельно — или вместе со всем
репозиторием; во втором случае прочитай раздел «Если подключён репозиторий».

## Что в папке

| Путь                    | Что это                                                                                                                                                                                                                                                                |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reference/`            | **Генерируется, руками не править.** Настоящие экраны и модалки приложения, отрендеренные из боевых React-компонентов с боевыми стилями на фикстурных данных: `index.html` — сцены вкладками (сцена открывается и по адресу, `index.html#editor`), кадр окна 1280×800. |
| `reference/app.css`     | Все стили приложения одним файлом: токены (`:root`), базовые стили, стили экранов и модалок. Источник правды по реализованным рецептам. **Генерируется.**                                                                                                              |
| `reference/fonts/`      | Шрифты приложения файлами: Golos Text и IBM Plex Mono, 400/500/600, `fonts.css`. **Генерируется.**                                                                                                                                                                     |
| `reference/pages/`      | Картинки страниц для миниатюр и превью — тестовые листы с крупным номером. **Генерируется.**                                                                                                                                                                           |
| `reference/wrapper.css` | Оформление страницы референса: вкладки, кадр окна. Не стили приложения.                                                                                                                                                                                                |
| `DESIGN_SYSTEM.md`      | Дизайн-система: принципы, токены, типографика, рецепты компонентов.                                                                                                                                                                                                    |
| `UI_SPEC.md`            | Поэкранный контракт: раскладка, состояния, поведение, тайминги, граф переходов между экранами.                                                                                                                                                                         |
| `handoffs/`             | Handoff'ы. `2026-10-m*-states.md` — исторические: их писал агент-разработчик по ходу вех, они объясняют состояния, которых не было в исходном макете (наборы, пары, пустые обороты, плашки). Твои новые handoff'ы ложатся сюда же.                                     |
| `briefs/`               | Брифы — по одному на компонент: что спроектировать и зачем.                                                                                                                                                                                                            |
| `handoff-template.md`   | Форма, которую обязан иметь каждый handoff. **Генерируется** из шаблонов репозитория.                                                                                                                                                                                  |
| `archive/`              | Исходный макет M0 (`Сканер ADF.dc.html` + рантайм `support.js`) и его протокол нормализации токенов. **Устарел**: приложение с тех пор сильно выросло. Только для истории.                                                                                             |
| `mock/`                 | **Твой мок** (создаёшь ты).                                                                                                                                                                                                                                            |

Сцены референса: `setup`, модалка `device`, `scan` (лица и обороты), `flip`, `merge`,
`editor`, модалки `save`, `add`, `newscan`, `editor` в режиме раздельных наборов с модалкой
`mismatch`. Над каждым кадром — строка, что за сцена и что в ней важно. Анимации CSS (подача
листа, разворот пачки, пульс) в референсе живые.

## Если подключён репозиторий

С репозиторием видно то, на что отрендеренный референс только намекает, — пользуйся.

- **Имена классов и анатомия компонентов** — из исходников, а не из разметки:
  `src/renderer/src/screens/` (экраны), `src/renderer/src/modals/` (модалки),
  `src/renderer/src/components/` (общие), `src/renderer/src/styles/tokens.css` (токены;
  `reference/app.css` начинается с его копии). Тексты интерфейса — `locales/ru/common.json`.
- **Обоснования** — `docs/brainstorms/` (требования), `docs/decisions/` (архитектурные
  решения), `docs/solutions/` (журналы реализации), `docs/duplexnt.md` (спека продукта).
- `npm run design:snapshot` генерирует `reference/` (файл `test/design-snapshot/reference.test.tsx`).

Что репозиторий **не** меняет:

1. **Чтение кода — не разрешение его менять.** Дизайн живёт в моке, результат — handoff. Ничего
   не править в `src/` и не открывать pull request — handoff внедряет агент-разработчик.
2. `reference/` и `handoff-template.md` остаются сгенерированными: ручная правка теряется при
   следующей перегенерации.
3. `archive/` остаётся архивом: возможность его прочитать — не повод возвращать его решения.
4. Запустить приложение ты всё равно не можешь — это Electron и сетевой сканер. Референс —
   ближайшее к живому приложению, а поведение судится по моку.

## Мок

Мок — работающая замена приложения: сцены референса, оживлённые небольшим JavaScript, плюс
новый компонент. Пользователь утверждает дизайн, **пользуясь** моком, а не разглядывая
скриншоты.

Правила:

1. Начни с копии `reference/index.html` в `mock/index.html` (одна страница — нормально;
   дели, только если так понятнее). Подключи `../reference/fonts/fonts.css`,
   `../reference/app.css` и `../reference/wrapper.css` без изменений; все добавления и
   переопределения — в `mock/mock.css` (новые токены — блоком `:root { … }`), поведение — в
   `mock/mock.js`. Простые HTML, CSS и vanilla JS — без фреймворка, без рантайма шаблонов, без
   сборки. Картинки страниц — из `../reference/pages/`. Классы приложения сохраняй; новые —
   в том же стиле `block__element--modifier`.
2. Оживи затронутые сцены: кнопка открывает модалку, лента прокручивается, экран сменяет
   экран, если бриф про переходы. Небольшая **панель сценариев** (в углу, вне кадра окна),
   переключающая фикстурные ситуации — «идёт проход», «не сошлось», «есть пустые обороты», —
   приветствуется: так пользователь доходит до каждого состояния без перезагрузки.
3. Проектируй в контексте. Не заводи вкладку на каждое состояние; состояния достижимы через
   поведение и для протокола один раз показаны в handoff'е.
4. Держись принципов `DESIGN_SYSTEM.md` («Принципы»): плотный десктоп (кегль 12.5–13 px,
   шаг 2 px), тёплая бумага вместо белого, один почти ахроматический акцент, два голоса
   типографики (Golos Text — читаемое, IBM Plex Mono — считаемое и метки), тихое движение
   (микропереходы 150–200 мс, циклические иллюстрации 1,2 и 3,8 с). Всё движение — с
   выключением под `prefers-reduced-motion`.
5. Строй на том, что есть. Не перерисовывай незатронутые экраны «заодно» и не меняй
   поведение, которое бриф не называет. Правила продукта из `UI_SPEC.md` — данные
   пользователя не теряются молча, страницы не выбрасываются без его решения, удаление сессии
   — только через модалку — в силе и для мока.
6. Тексты — на обоих языках, в тоне приложения (`locales/ru/common.json` и
   `locales/en/common.json`, если репозиторий подключён); в handoff'е секция `## Copy` несёт
   колонки `ru | en`. В интерфейсе не говорим «пачка», «стопка», «проход N»: листы, страницы,
   «лицевые стороны», «обороты» — по-английски sheets, pages, front sides, backs.

## Утверждение и handoff

1. Пользователь трогает мок; замечания — новыми итерациями мока, а не статичными картинками.
2. Когда форма неясна — сначала отдельная страница с 2–3 действительно разными вариантами
   затрагиваемого элемента, без контекста; после выбора — выбранный вариант в контексте.
3. После утверждения — handoff в `handoffs/<компонент>.md` по `handoff-template.md`:
   placement, разметка и CSS с настоящими классами и токенами, таблица новых токенов,
   состояния, поведение словами (не JS мока), тексты, решения и открытые вопросы. Движение —
   длительности в мс, кривые, что происходит под `prefers-reduced-motion`.
4. Handoff — **единственный вход в реализацию**; мок не шиппится. Расхождения handoff'а с
   `DESIGN_SYSTEM.md` агент-разработчик решает в пользу дизайн-системы или фиксирует в ней
   явно; новые токены заносятся в дизайн-систему.

## Для агента-разработчика

- Процесс: **референс → бриф → мок → утверждение → handoff → реализация**. Бриф пишется по
  карточке бэклога (`../templates/brief.md`), один компонент на бриф, в `briefs/`.
- `npm run design:snapshot` перегенерирует `reference/` и `handoff-template.md` — после
  каждой вехи или пункта, менявших UI, и перед отдачей папки дизайн-агенту. В `test:all` не
  входит. Сцены и фикстуры — `test/design-snapshot/reference.test.tsx`: новый экран или
  модалка — новая сцена там же.
- Папка отдаётся дизайн-агенту целиком (или репозиторий); `mock/` и новые `handoffs/` от
  него коммитятся как есть (`mock/` prettier не трогает).
