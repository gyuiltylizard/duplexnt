# docs/design — дизайн-модуль (опционально)

Подключается, если у проекта есть интерфейс. Иначе — удалить папку целиком и пункт про
дизайн-систему из `CLAUDE.md`.

## Что здесь

| Путь                 | Что это                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `DESIGN_SYSTEM.md`   | Источник правды по токенам: цвета, типографика, радиусы, тени, рецепты компонентов.          |
| `UI_SPEC.md`         | Поэкранный контракт: раскладка, состояния, семантика взаимодействий.                         |
| `reference/`         | **Генерируемый** референс реальных экранов из боевых компонентов и стилей. Руками не править. |
| `briefs/`            | Один бриф на компонент (`../templates/brief.md`). Пишет агент-разработчик.                   |
| `mock/`              | Интерактивный мок дизайн-агента: копия референса + свои `mock.css` / `mock.js`.              |
| `handoffs/`          | Утверждённые handoff'ы (`../templates/handoff.md`). Единственный вход в реализацию.          |

## Процесс: референс → бриф → мок → утверждение → handoff → реализация

1. **Референс** генерируется командой `<design:snapshot>` из реальных компонентов на
   фикстурных данных; перегенерируется после каждой вехи, менявшей UI.
2. **Бриф** — один компонент; что спроектировать, какое поведение сделать рабочим, что вне
   скоупа, открытые вопросы. При неясной форме — сначала страница вариантов, размещение в
   контексте после выбора.
3. **Мок** — дизайн-агент строит из копии референса; свои правки только в своих файлах;
   без фреймворка и сборки; состояния достижимы через поведение, не через отдельные экраны.
4. **Утверждение** — пользователь трогает мок; замечания — новыми итерациями мока.
5. **Handoff** — placement, разметка и CSS с реальными классами и токенами, таблица
   токенов, состояния, поведение словами, копи по языкам, решения и открытые вопросы.
6. **Реализация** — обычным пайплайном по handoff'у. Расхождения с `DESIGN_SYSTEM.md`
   решаются в пользу дизайн-системы или фиксируются в ней явно; новые токены — в токены и
   в `DESIGN_SYSTEM.md`.

## Правила для дизайн-агента (контракт)

- Чтение кода — не разрешение его менять: результат — handoff, не PR.
- Референс и стили приложения остаются сгенерированными; ручная правка теряется.
- Старые прототипы — референс only: не шиппить, не импортировать, не расширять.
- Скоуп мокапа ≠ скоуп MVP: богатый мок скоуп не расширяет.
- Токены — один раз: компоненты тянут переменные, хардкод значений запрещён.
