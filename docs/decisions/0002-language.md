# 0002 — Язык: TypeScript (strict) во всех процессах

## Контекст

В техбазе стоял Python: `requests`, `lxml`, Pillow / OpenCV. В брейншторме по стеку
(`docs/brainstorms/2026-09-17-stack-requirements.md`) выяснилось, что это первое, что подошло
под «протокол — HTTP с XML», а не решение. К моменту выбора появились два факта: макет
интерфейса — HTML с токенами в CSS-переменных, то есть интерфейс будет на веб-стеке; и у
автора есть рабочий проект на Electron и TypeScript по тому же playbook'у, в котором ничего
не мешало. Развилки:

1. **Язык ядра** — Python-ядро при веб-интерфейсе или один язык на всё.
2. **Строгость** — strict TypeScript, JS с JSDoc или чистый JS.
3. **Линтер, форматер, pre-commit hook.**

До M0: кода нет.

## Решение

### Один язык — TypeScript

Ядро (клиент eSCL, сборка проходов, PDF) и интерфейс пишутся на TypeScript. Ключевой довод:
Python-ядро при веб-интерфейсе — это два языка, два набора инструментов качества и
межпроцессный мост; числа, которое оправдывает эту сложность, нет. Протокол — HTTP с XML,
его умеет любой язык.

### Строгий режим

`strict: true` во всех процессах — `main`, `preload`, `renderer`. Мост между интерфейсом и
ядром типизируется общей картой «канал ↔ тип», чтобы обработчик, мост и вызывающая сторона
не могли разойтись по построению. JS с JSDoc отклонён: типы слабее именно на мосте и на
разборе ответов устройства, а обвязка нужна всё равно.

### Линтер, форматер, hook

`eslint` (typescript-eslint) + `prettier`; `husky` + `lint-staged` правят застейдженное на
pre-commit. Граница слоёв — правило линтера: импорт Electron в слое ядра роняет `lint`
(см. [[0003-shell-build-delivery]]). Правила не ослабляются точечными отключениями без
обоснования в коде.

## Альтернативы

- **Python-ядро + веб-оболочка** — отклонён: см. выше. Его настоящий козырь — OpenCV, но
  функции, которым он нужен, в пост-MVP.
- **JavaScript + JSDoc / чистый JS** — отклонены: нет статической проверки на слое, который
  разбирает чужой XML и собирает документ пользователя.
- **Rust-ядро (Tauri)** — отклонён: языка в проекте нет, выигрыш в размере установщика его не
  окупает.

## Последствия

- Гейт «готово» включает `tsc --noEmit` по всем процессам.
- **Нет OpenCV под рукой.** Выравнивание перекоса и вычитание просвечивания — открытый риск.
  Перед этими пост-MVP функциями нужен спайк: хватает ли `sharp`, нужна ли WASM-сборка OpenCV
  или отдельный процесс. MVP риск не задевает: миниатюры и детектор пустых оборотов OpenCV не
  требуют.
- Конфиги Shelfory не копируются (playbook, BOOTSTRAP §6): tsconfig, eslint и hook заводятся в
  M0 заново.
