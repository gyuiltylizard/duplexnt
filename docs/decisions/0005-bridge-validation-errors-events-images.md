# 0005 — Мост M1: валидация входа, доменные ошибки, события, изображения страниц

## Контекст

M0 построил мост из одной команды-пробы и отложил четыре решения до первой вехи с настоящими
данными (план M0, KTD-10, KTD-29, KTD-30; `docs/duplexnt.md` → «Правила моста»). M1 добавляет
подключение сканера, проход и сессию на диске, и все четыре нужны сразу. Решено при планировании
M1 (`docs/plans/2026-10-02-001-feat-m1-connect-single-pass-plan.md`), развилки:

1. **Чем проверять вход моста** — рукописные проверки или библиотека схем.
2. **Как доменная ошибка доходит до интерфейса** — отказом `invoke` или значением.
3. **Как main сообщает о ходе работы** — прогресс прохода, результаты обнаружения.
4. **Как интерфейс получает изображения страниц** — байты через мост, `file://` или своя схема.

До M1: одна команда `probe` с рукописным валидатором; отказ `invoke` доходит до renderer строкой
без класса ошибки; событий нет; `img-src 'self'`, renderer загружен с `file://`.

## Решение

### Валидация — `zod`

Схемы `zod` описывают вход каждой команды, журнал сессии и файл настроек; типы выводятся из схем,
второго описания формы нет. Ключевой довод — тот же, что у `vitest` в [[0001-test-framework]]:
схемы пишет агент, и распространённый API даёт меньше кривых схем. Схемы живут в ядре: `shared`
несёт только типы, вход проверяется в ядре до любой работы. Пакет чистый JS — `devDependencies`,
бандлится в main.

Рукописные валидаторы отклонены: при десятке команд и двух файловых форматах они дают расхождение
типа и проверки и разные по форме сообщения. `valibot` отклонён: выигрыш в размере бандла в main
ничего не стоит.

### Доменные ошибки — значением, а не отказом

Команда возвращает результат-конверт: успех со значением или отказ с **кодом** доменной ошибки и
необязательными деталями. Коды объявлены в `shared` одним перечислением; текст для пользователя
живёт в локали renderer и выбирается по коду — ядро отдаёт данные, не текст. Отказ `invoke`
остаётся только для ошибок программы: нарушение контракта, чужой отправитель, баг.

Отказ `invoke` как транспорт отклонён: Electron передаёт через границу только сообщение, класс и
поля ошибки теряются, и renderer пришлось бы разбирать строку.

### События — подписка на именованное событие, состояние — запросом

События объявляются в `shared` отдельной картой рядом с картой команд. Preload отдаёт по одной
функции на событие; функция принимает обработчик и возвращает отписку. Объект события Electron и
`ipcRenderer` наружу не выходят, универсального `on(канал)` нет.

**Событие — подсказка, а не источник правды.** Состояние сессии и устройства интерфейс получает
командой-запросом снимка; событие несёт номер по порядку и сообщает, что снимок изменился.
Порядок события относительно ответа `invoke` не гарантирован, поэтому renderer берёт позднейшее
по номеру, а после перезагрузки окна заново подписывается и запрашивает снимок.

### Изображения страниц — собственная схема с непрозрачным ключом

Main регистрирует привилегированную схему до `ready` и обработчик после. Адрес изображения несёт
вид (миниатюра или полная страница) и **ключ страницы** — не путь. Обработчик проверяет форму
ключа, получает путь у ядра и отдаёт файл; неизвестный ключ — 404. CSP получает узкую дельту:
схема добавляется только в `img-src`. Renderer остаётся без `connect-src`, читать пиксели через
`fetch` он не может и не должен.

Схема получает минимум привилегий: обход CSP, доступ через `fetch` и CORS выключены, иначе узкая
дельта CSP теряет смысл, а скрипт страницы смог бы прочитать пиксели. Адрес несёт идентификатор
сессии: ключ страницы повторяется от сессии к сессии, и без него окно показало бы изображение
прошлой пачки. Ответ не кэшируется и всегда объявлен как JPEG. Адрес схемы не может стать целью
навигации окна.

Команды не принимают от интерфейса путей. Открытие каталога данных не имеет аргументов; снимок
состояния не несёт абсолютных путей. Адрес сканера приходит от интерфейса только при ручном
вводе и проверяется строгой схемой; найденное устройство передаётся непрозрачным
идентификатором, выданным ядром.

Байты через мост отклонены: сотня страниц по несколько мегабайт легла бы в кучу renderer и
копировалась бы дважды. `file://` отклонён: интерфейсу пришлось бы знать настоящие пути, а CSP —
открыть файловую систему.

## Альтернативы

- **Библиотека-обёртка типизированного IPC** — отклонена: мост уже типизирован картой в `shared`,
  обёртка добавила бы зависимость и скрыла бы проверку отправителя.
- **Одно событие «состояние изменилось» с полным снимком внутри** — отклонено: снимок со списком
  страниц пересылался бы на каждую страницу прохода; событие остаётся лёгким.
- **Перевести и сам renderer на собственную схему вместо `file://`** — не сейчас: это пункт
  hardening оболочки в бэклоге, со своей проверкой установщика.

## Последствия

- `docs/duplexnt.md` → «Правила моста» дополняется правилами конверта, событий и схемы изображений.
- Каждая новая команда — запись в карте, схема входа в ядре, строка в preload, обработчик в main;
  каждая доменная ошибка — код в `shared` и строка в локали.
- CSP меняется узкой дельтой под тестом; схема изображений — новая поверхность main, закрытая
  тестами на обход каталога и неизвестный ключ.
- Проба `probe` остаётся диагностическим каналом и переезжает на конверт вместе с остальными.
- Риск: `zod` — первая библиотека в ядре, бандлящаяся в main; проверяется сборкой установщика на
  закрытии вехи.
