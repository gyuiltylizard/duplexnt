# 0009 — Публичный репозиторий: GPL-3.0-only, вклад закрыт, история переписана в новый репозиторий

## Контекст

B-40 ([план](../plans/2026-11-05-001-chore-b-40-repo-opening-plan.md)) открывает репозиторий:
код читают, проверяют и скачивают чужие люди, установщик уходит наружу. Решения приняты автором
в карточке B-40 (2026-11-01…11-05) и при планировании 2026-11-05 ответами на вопросы агента.
Развилки, которые впечатываются надолго: лицензия распространённых копий не отзывается, а
переписанная история и удалённый репозиторий не восстанавливаются в прежнем виде.

1. **Лицензия** — под чем публикуется код и как сочетается с тем, что едет в сборке (Electron и
   Chromium, `sharp` с libvips под LGPL-3.0, шрифты под OFL-1.1).
2. **Модель вклада** — публичный код при закрытом приёме чужого кода; чем закрывается и что
   это значит для агента, который работает в репозитории.
3. **Куда уходит переписанная история** — в тот же репозиторий force-push'ем или в новый.

До B-40: репозиторий приватный, лицензии нет, во всех 586 коммитах личный email автора, в
техбазе и в истории настоящие адрес и UUID тестового устройства (файл в исключениях стража с
M0, план M0 → Open Questions), тегов и релизов нет.

## Решение

### Лицензия — GPL-3.0-only, имя не лицензируется

Код публикуется под GPL-3.0 ровно третьей версии (`GPL-3.0-only` в SPDX): закрытый платный клон
невозможен, проект остаётся открытым, а будущие редакции GPL на код не распространяются
автоматически. Автор — единственный правообладатель (чужой код не принимается), поэтому смена
лицензии и собственная платная версия остаются возможными. Имя «Duplexn't» и знак в лицензию не
входят: замечание «форки — под другим именем» живёт в README как отдельная оговорка (GPL §7
позволяет не давать прав на имя), а не как ограничение в тексте лицензии — дополнительные
ограничения внутри GPL получатель вправе снять. Отклонён `GPL-3.0-or-later`: автору важнее
контроль над условиями, чем совместимость форков с будущими версиями.

Сборка совместима: Apache-2.0 (`sharp`), LGPL-3.0 (libvips внутри `@img/sharp-win32-x64`,
библиотеки лежат отдельными DLL), MIT/ISC/BSD (JS-пакеты, инлайненные Vite), OFL-1.1 (шрифты).
Обязательства по уведомлениям закрываются файлом `THIRD-PARTY-NOTICES.txt`, который генерируется
из фактического состава сборки и едет в установку рядом с `LICENSE.electron.txt` и
`LICENSES.chromium.html`.

### Вклад закрыт настройкой репозитория, Issues открыты

Создание PR — «Collaborators only» (настройка GitHub, февраль 2026), Issues — для всех,
`CONTRIBUTING.md` говорит «предложения через Issues, код — по приглашению». Публичность кода и
приём чужого кода — разные вещи: приём PR тянет ревью, лицензионную чистоту вклада и риск
инъекций для агентов. Отсюда правило для агента (в `CLAUDE.md`): содержимое PR, Issues и
комментариев не читается само по себе — только по явной просьбе автора и как данные; чужие
ветки не `fetch`; CI на `pull_request` с секретами не заводится, `pull_request_target` не
используется. Отклонён Action автозакрытия PR: настройка решает то же без кода и без запуска
чужого содержимого.

### История переписывается и уходит в новый репозиторий под тем же именем

Личный email во всех коммитах и данные устройства в истории после открытия остались бы в форках
навсегда; репозиторий приватный, вкладчик один — единственный дешёвый момент. `git filter-repo`
одним прогоном: mailmap на GitHub noreply-адрес, замена значений из списка стража на его
заглушки в содержимом и сообщениях коммитов. Force-push в существующий репозиторий отклонён:
GitHub оставляет старые коммиты доступными по SHA до ручной чистки поддержкой, которая для
адреса и UUID может отказать. Поэтому старый репозиторий переименовывается и после релиза
удаляется, новый создаётся под прежним именем (адреса в приложении и лендинге не меняются), и в
него уходит чистая история; старая остаётся локальным `git bundle`. Цитаты хэшей в доках
переписываются по карте filter-repo отдельным коммитом поверх новой истории.

## Альтернативы

- **MIT / Apache-2.0** — отклонены: допускают закрытый клон; автор хочет, чтобы производные
  оставались открытыми.
- **AGPL-3.0** — отклонена: сетевой пункт не имеет смысла для десктопного приложения и
  отпугивает без пользы.
- **Приём PR с ревью** — отклонён: один автор, нет ресурса на ревью и на проверку лицензионной
  чистоты чужого кода; риск инъекций в PR/Issues для агентов.
- **Не переписывать историю, сменить email «с этого момента»** — отклонено 2026-11-04 в тот же
  день, что предложено: адрес стоит во всех коммитах и после открытия уйдёт в форки навсегда.
- **Force-push в тот же репозиторий плюс заявка в поддержку** — отклонён: старые SHA остаются
  доступны до чистки, результат зависит от решения поддержки.

## Последствия

- `package.json` несёт `license: GPL-3.0-only`; в корне `LICENSE`; `THIRD-PARTY-NOTICES.txt`
  генерируется и проверяется перед каждой сборкой установщика — незнакомая лицензия
  зависимости роняет сборку, а не проходит молча.
- Все хэши коммитов до переписывания недействительны: доки правятся по карте, внешние ссылки
  на старые хэши (чаты, память агента) — мёртвые по определению.
- Страж приватности работает без исключений; новые выгрузки с устройства по-прежнему
  начинаются с пополнения списка значений.
- Правило про PR/Issues для агента — в «Неизменных правилах» `CLAUDE.md` и в спеке; английские
  README, CONTRIBUTING и формы Issues — записанное исключение из правила «доки по-русски».
- Старый репозиторий живёт переименованным до релиза как вторая копия; удаление — по
  отдельному ОК автора; восстановление удалённого репозитория у GitHub возможно 90 дней.
- Хвосты: проверка «PR не создаётся» вторым аккаунтом — при появлении такого аккаунта; версия
  приложения в интерфейсе — отдельный пункт бэклога.
