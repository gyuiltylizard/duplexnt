# 0006 — Разбор ответов устройства: `saxes` и правила недоверенного входа

## Контекст

Клиент eSCL разбирает два XML-ответа сканера — `ScannerCapabilities` и `ScannerStatus` — и
собирает один XML-запрос `ScanSettings`. Сканер — единственный недоверенный удалённый вход
приложения, и разбирается он в main-процессе без sandbox (план M0 → «Deferred to Follow-Up Work»
требовал записать правила разбора отдельным ADR). Решено при планировании M1
(`docs/plans/2026-10-02-001-feat-m1-connect-single-pass-plan.md`), развилки:

1. **Библиотека разбора XML.**
2. **Правила обращения с ответом устройства.**
3. **Чем собирать `ScanSettings`.**

До M1: фикстуры ET-3850 лежат минифицированным XML; тесты M0 работают с ними как с текстом;
разборщика в проекте нет.

## Решение

### Разбор — `saxes` с разрешением пространств имён

Потоковый SAX-разборщик `saxes` и небольшой собственный сборщик дерева поверх него. Ключевой
довод: элементы сопоставляются по **URI пространства имён**, а не по префиксу — чужая прошивка
может назвать `scan:` и `pwg:` иначе, и разбор по префиксам на ней молча соврёт. Пакет уже едет в
проекте зависимостью `jsdom`. Чистый JS — `devDependencies`, бандлится в main.

`fast-xml-parser` отклонён: удобнее, но префиксы он только отрезает, а обзор при планировании
нашёл у него серию advisories 2026 года вокруг DOCTYPE и сущностей. `@xmldom/xmldom` с `xpath`
отклонён: корректен по пространствам имён, но это DOM и вторая библиотека ради двух маленьких
документов, и у него тоже свежие advisories разбора. `xml2js` не поддерживается.

Цена выбора: `saxes` давно не выпускался. Он стабилен и мал; если понадобится замена, она
локализована в одном модуле разбора.

### Правила недоверенного входа

- Ответ с `<!DOCTYPE` или `<!ENTITY` отклоняется до разбора и на событии DOCTYPE самого
  разборщика: устройству незачем их слать. Текст расшифровывается как строгий UTF-8.
- Размер XML-ответа ограничен сверху; превышение — ошибка, а не усечение. У сборщика дерева есть
  потолки глубины и числа узлов; имена элементов устройства не становятся ключами обычных
  объектов.
- Страница принимается потоком в файл с потолком размера и общим сроком приёма; у задания есть
  потолок числа страниц. Страница принята, когда тело дочитано по своему обрамлению и является
  JPEG по маркерам начала и конца.
- `sharp` получает только JPEG: маркеры проверяются перед декодированием, предел пикселей
  выводится из capabilities и не ослабляется. libvips выбирает загрузчик по содержимому, и без
  проверки под видом страницы в main-процесс попал бы любой его формат.
- Разобранный ответ приводится к типизированной форме с проверкой каждого значения: неизвестный
  цветовой режим или формат пропускается, а не попадает в интерфейс строкой.
- `Location` из ответа на создание задания — данные: берётся только путь, он перебазируется на
  origin профиля и обязан лежать под базовым путём eSCL. Автоматических переходов по 3xx нет.
- Ослабленная проверка сертификата привязана к профилю, который подтвердил пользователь, а не к
  любому устройству, ответившему по mDNS: capabilities запрашиваются только у выбранного.

### `ScanSettings` — шаблонной строкой

Запрос собирается шаблоном с экранированием; каждое значение перед подстановкой проверяется по
перечислению из capabilities. Набор полей маленький и фиксированный, библиотека-сборщик дала бы
зависимость без выигрыша.

## Альтернативы

- **Регулярные выражения по тексту** — отклонены: пространства имён и вложенность на чужом
  устройстве сломают их молча.
- **Разбор в отдельном процессе** — отклонён: два документа по несколько килобайт с потолком
  размера и без DTD не дают числа, которое требует изоляции процесса.

## Последствия

- Разбор живёт в одном модуле ядра; остальной клиент получает типизированные структуры.
- Тесты разбора идут против фикстур: ET-3850, устройство без автоподачи, ответ с DOCTYPE, ответ
  с другими префиксами тех же пространств имён, ответ больше потолка.
- Правило про `Location` уточняет KTD-20 плана M0: чужой хост в `Location` не роняет задание — он
  отбрасывается вместе со схемой и портом, проверяется только путь.
- Состояние advisories и версии сверяются при установке пакетов: обзор — вторичный источник.
