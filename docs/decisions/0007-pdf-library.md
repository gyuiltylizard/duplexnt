# 0007 — Библиотека PDF: @cantoo/pdf-lib

## Контекст

M2 «Два прохода и сборка» впервые пишет PDF: собранная из двух проходов пачка сохраняется в
один файл. [[0003-shell-build-delivery]] отложил выбор библиотеки «при планировании M2 своим
ADR» и зафиксировал требования: **JPEG от устройства вкладывается без перекодирования**,
**поворот страницы — свойством страницы** (`/Rotate`), **библиотека поддерживаемая**
(оригинальный `pdf-lib` не обновлялся с 2022). Решено при планировании M2 ответом автора на
развилку; кандидаты — из брейншторма по стеку (`brainstorms/2026-09-17-stack-requirements.md`,
R10): `@cantoo/pdf-lib`, `@pdfme/pdf-lib`, `pdfkit`.

Дополнительные требования из архитектуры: чистый JS без нативных модулей (упаковка в asar,
[[0003-shell-build-delivery]]), TypeScript-типы, permissive-лицензия. Это последняя пометка
`<не определено>` в спеке.

До M2: PDF-кода в `src/` нет; единственный PDF в репозитории — спайк
`spikes/make-calibration-pdf.mjs` (не продуктовый). JPEG от ET-3850 проверен в M1: baseline,
`SOI…EOI`, без EXIF/ICC — пригоден для вложения как есть.

## Решение

### Библиотека — `@cantoo/pdf-lib`

Единственный кандидат, закрывающий все требования без оговорок (проверено веб-исследованием
при планировании M2, октябрь 2026):

- `embedJpg()` кладёт сырые байты JPEG как `DCTDecode` — без перекодирования;
- `page.setRotation(degrees(n))` пишет `/Rotate` — байты изображения не трогает;
- живой форк `Hopding/pdf-lib`: релизы ежемесячно (2.11.1 от 2026-09-15), ~346K
  скачиваний/нед, 6 мейнтейнеров; drop-in совместим с API оригинала;
- MIT, чистый JS, встроенные типы.

Память — риск, который проверяется тестом, а не отмахивается: документ собирается целиком в
памяти, и по замерам M1 худший случай — не «сотни КБ на страницу», а 3,4–3,5 МБ (600 dpi,
цвет); двусторонняя пачка из 50 листов — ~350 МБ JPEG, пик с копией на `save()` — порядка
0,7–1 ГБ. План M2 (KTD-12) требует прогон на эквивалентном объёме; если пик или блокировка
event loop недопустимы — выделенный worker отдельным решением. Известные жалобы на `pdf-lib`
касаются сотен страниц и `copyPages` гигантских документов.

Размещение — `devDependencies`: чистый JS, бандлит Vite (механический критерий из амендмента
[[0003-shell-build-delivery]]).

## Альтернативы

- **`@pdfme/pdf-lib`** — отклонён: живой (6.2.2 от 2026-09-29), но развивается в монорепе
  pdfme под нужды pdfme и уже дрейфует от оригинального API (переход на fontkit v2); для
  стороннего потребителя это риск без выгоды.
- **`pdfkit`** — отклонён: нет API поворота свойством страницы — `rotate()` трансформирует
  контент, а не пишет `/Rotate` (foliojs/pdfkit#476); пришлось бы править словарь страницы
  вручную.
- **`mupdf.js`** — отклонён: лицензия AGPL / коммерческая.
- **`hummus` / `muhammara`** — отклонены: нативные модули, конфликт с упаковкой asar.

## Последствия

- Снята последняя пометка `<не определено>` в `docs/duplexnt.md` (таблица стека, строка PDF) —
  правится при закрытии M2 вместе с остальными доками.
- Новая зависимость `@cantoo/pdf-lib` в `devDependencies`; сборка PDF живёт в ядре
  (`src/core/`), Electron не импортирует.
- Транзитивно тянется `node-html-better-parser` (для SVG/HTML-фич форка, нам не нужных) —
  принято; unpacked-размер пакета 26 МБ — это четыре формата сборки, в бандл попадает одна.
- Поворот на 90° (правка страницы, M3) и аварийные 180° для оборотов (M2) выражаются одним
  механизмом `/Rotate` — перекодирования не появляется ни в одном сценарии.
- Инкрементальной записи у библиотеки нет; появится документ, которому она нужна, — выбор
  пересматривается амендментом.

## Амендмент 2026-10-28 — выправленные страницы перекодируются

Принято автором на брейншторме локального перекоса подачи
(`docs/brainstorms/2026-10-28-local-skew-correction-requirements.md`). Основной текст обещал,
что «перекодирования не появляется ни в одном сценарии»: все правки геометрии выражались
свойством `/Rotate`. Выравнивание «веера» строк — плавная геометрическая сетка по профилю угла,
меняющемуся по высоте листа — свойством страницы PDF не выражается. Такой сценарий появился, и
правило уточняется:

- **Выправленная страница вкладывается в PDF перекодированным JPEG** с качеством, не дающим
  видимой деградации; порог качества — при планировании. Источник — производное изображение,
  собранное из исходника, журнала и профиля калибровки (ADR [[0004-data-model]]).
- **Невыправленные страницы и страницы с откатом коррекции вкладываются байт в байт**, как
  раньше: `embedJpg()` на сырых байтах устройства. Откат восстанавливает исходные байты точно.
- **Поворот по-прежнему `/Rotate`** для всех страниц, выправленных и нет; перекодирование не
  даёт повода «запечь» поворот в пиксели.
- **Исходник страницы не меняется** ни в одном сценарии — перекодирование касается только
  вложения в PDF.
- Отклонено **перекодировать все страницы ради единообразия**: теряет качество и размер там, где
  выигрыша нет, и ломает проверку «байты совпадают» в тестах сборки.

Библиотека прежняя: `@cantoo/pdf-lib` умеет и то и другое одним `embedJpg()`.
