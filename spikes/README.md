# spikes — одноразовый код спайков и съёмок

Скрипты для трёх критериев спайка M0 из
[ADR 0003](../docs/decisions/0003-shell-build-delivery.md) и съёмка живого следа задания для M1.
Это **исследование, а не поставка**: код вне сборки, вне типизированного линта, не рефакторится
и тестами не покрывается. Ценность — записи в журналах вех
([M0](../docs/solutions/0001-m0-scaffold.md), [M1](../docs/solutions/0002-m1-connect-single-pass.md)).
Клиент сканера M1 пишется заново, отсюда ничего не переиспользуется.

Правило приватности действует и здесь: в скриптах нет адресов и идентификаторов устройства —
они приходят аргументами или из `local-test-data/` (вне git). Сырой вывод пишется туда же.

## Живой след задания автоподачи (M1, U1)

`node spikes/escl-job-trace.mjs <адрес> <сценарий> [--ключ значение …]`

Скрипт ведёт **настоящее** задание: сканер подаёт бумагу. Каждый обмен — запрос, статус, сырые
заголовки, времена (TCP, TLS, заголовки, первый байт, конец), тело — ложится в
`local-test-data/device/trace/<время>-<метка>/`: `trace.json` и файлы тел по порядку. По каждой
странице записаны первые и последние байты, байты после маркера конца, размеры из заголовка JPEG
против запрошенного региона, метаданные `sharp` и уменьшенная копия для просмотра глазами.

UUID заданий скрипт **сам** дописывает в `local-test-data/privacy-values.txt`; в stdout адрес и
UUID заменены метками `<сканер>` и `<uuid-N>`.

| Сценарий  | Что делает                                                                             |
| --------- | -------------------------------------------------------------------------------------- |
| `job`     | статус → `POST` → `NextDocument` до не-`200` → статус → `DELETE` → повторный `DELETE`  |
| `abandon` | задание без `DELETE`, затем пробы `POST` раз в 5 с: когда устройство отпустит задание  |
| `wake`    | три запроса статуса подряд: время первого ответа уснувшего устройства против «тёплого» |

Ключи `job` и `abandon`:

- `--label <имя>` — метка каталога следа: что именно снимается (`empty`, `pull`, `jam`, …);
- `--dpi`, `--mode` (`Grayscale8`, `RGB24`, `BlackAndWhite1`), `--xoffset`, `--yoffset`,
  `--width`, `--height` — параметры задания; регион в 1/300 дюйма, по умолчанию A4 от нуля,
  серый, 300 dpi;
- `--wait-loaded` — перед заданием ждать `ScannerAdfLoaded`: скрипт взводится заранее и стартует,
  когда автор положил бумагу; `--wait-limit <сек>` — сколько ждать (по умолчанию 300);
- `--pause <сек>` — пауза перед каждым следующим `NextDocument`, статус раз в 5 с;
- `--max-pages <N>` — перестать запрашивать страницы после N-й;
- `--delete-after <N>` — `DELETE` посреди задания после N-й страницы, затем 20 с наблюдения
  статуса, `NextDocument` и `DELETE` по закрытому заданию;
- `--busy-wait <сек>` — сколько повторять `POST` при `503` (раз в секунду, по умолчанию 60);
- `--keepalive` — держать соединение между запросами (по умолчанию каждое новое).

Ключи `--scheme http --port <N> --out <каталог>` — проверка самого скрипта на локальной заглушке:
вывод и список значений уходят в указанный каталог, а не в `local-test-data/`.

**Взводить по одному сценарию.** Скрипт с `--wait-loaded` стартует от первой же бумаги в лотке;
цепочка из нескольких взведённых сценариев расходится с тем, что делает человек у сканера, если
один из них кончился раньше ожидаемого. **Сбой подачи не воспроизводить придержанным листом:**
после такого прогона устройство держало ошибку автоподачи до перезагрузки.

Калибровочные листы: `node spikes/make-calibration-pdf.mjs` → `temp/duplexnt-calibration.pdf`,
три пронумерованных листа A4 с миллиметровыми линейками от левого и верхнего края. Печатать в
масштабе 100 %. По ним меряется положение листа в поле автоподачи, и ими же удобно гонять
остальные сценарии: порядок страниц читается с любого превью.

Зачистка снятого в фикстуры: `node spikes/sanitize-escl.mjs --traces` — порядок описан в
[`test/fixtures/README.md`](../test/fixtures/README.md).

## Перекос подачи — веер (M6, U1)

Спайк плана M6 ([журнал](../docs/solutions/0023-m6-straighten.md)): листы под веер, прототип
детектора и ресэмплера, анализ сетки, замеры стоимости.

Листы: `node spikes/make-fan-sheets.mjs` → `temp/duplexnt-fan-sheets.pdf`, девять страниц A4
(сетка 10 мм ×3, текст, таблица, две колонки, косая штриховка, бедный лист, «фотография»).
Печатать в масштабе 100 %. Листы калибровки M1 для веера не годятся: три линейки по высоте —
три точки.

`node spikes/straighten-bench.mjs <команда> …`:

| Команда                                       | Что делает                                                                                           |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `grid <скан> [--dpi 300]`                     | углы горизонталей сетки по высоте, наклон и дрейф вертикалей, квадратика и остаток; срез или поворот |
| `measure <скан>`                              | детектор по полосам: углы и уверенность полос, профиль, гейты, контраст строк до/после               |
| `straighten <скан> --out <файл> [--lateral]`  | коррекция измеренным (или `--profile a,b,c`) профилем — посмотреть глазами и прогнать `grid`         |
| `synth --out <файл> [--profile a,b,c]`        | синтетическая страница текста с известным профилем                                                   |
| `distort <картинка> --out <файл> [--lateral]` | искажение рендера листа известным профилем (проверка инструмента)                                    |
| `bench [--dpi 600] [--channels 3] [--worker]` | стадии декод / измерение / warp / энкод, паузы цикла, RSS, размер                                    |

Профиль θ(u) = a + b·(u − 0,5) + c·(u − 0,5)², u — доля высоты, градусы; θ > 0 — правый конец
строки выше. Коррекция: `out(x, y) = in(x, y − (x − xc)·tanθ(y))`; `--lateral` добавляет
горизонтальный проход на боковой дрейф (интеграл tanθ) — для поворота листа целиком.

A/B «зависит ли остановка подачи от нагрузки хоста»: `escl-job-trace.mjs … --load 25` держит
цикл событий занятым кусками по 25 мс с уступкой между ними — как измерение и ресэмплер в
main; статистика нагрузки — в `trace.json` (`load`).

## Критерий 3 — установщик на чистой машине (U16)

1. `npm run dist` — собирает `release/duplexnt-<версия>-setup.exe`.
2. `node spikes/make-sandbox-config.mjs` — кладёт установщик в `release/sandbox-share/` и
   генерирует `release/duplexnt-sandbox.wsb` из шаблона `sandbox.template.wsb`.
3. Двойной щелчок по `release/duplexnt-sandbox.wsb`. Sandbox видит только каталог с
   установщиком, на чтение, сеть выключена.
4. Дальше — по чеклисту в `docs/output/`.

## Критерий 2 — HTTPS с самоподписанным сертификатом (U8)

Адрес сканера в скриптах не записан — он приходит аргументом или из `DUPLEXNT_SCANNER_HOST`.
Перед запросами сканер будят кнопкой на панели.

- Node (OpenSSL): `node spikes/tls-capabilities.mjs <адрес>`
- Electron main (BoringSSL), при снятой `ELECTRON_RUN_AS_NODE`:
  `node_modules\electron\dist\electron.exe spikes\tls-electron-main.cjs <адрес>`

Сценарий один на оба рантайма: `ScannerCapabilities` и `ScannerStatus` через выделенный
`https.Agent`, затем — в том же процессе — негативные проверки: локальный сервер с плохим
сертификатом и сам сканер обязаны быть отклонены через агент по умолчанию, глобальный `fetch` и
(в Electron) сетевой стек Chromium. Сертификат локального сервера делается на лету `openssl` из
поставки Git for Windows; ключ на диске не остаётся. Код выхода 0 — всё прошло.

Сырые ответы и полный отчёт — `local-test-data/device/`. Они же — источник для фикстур (U9).

## Критерий 1 — mDNS без Bonjour (U8)

`node spikes/mdns-discover.mjs [секунд] [each|default]`

**Библиотека спайка удалена из `package.json`** (U11): M1 поставит её уже как зависимость
продукта. Чтобы перезапустить скрипт раньше — `npm i -D --no-save bonjour-service@1.4.4`.

Режим `each` (по умолчанию) явно перебирает внешние IPv4-интерфейсы; `default` отдаёт выбор
интерфейса системе. На машине автора `default` один раз из шести вернул пустой результат без
ошибок; причина не установлена, `each` пустых прогонов не дал. Критерий проверяется при
**остановленной** службе Bonjour (`Stop-Service 'Bonjour Service'` от администратора); состояние
службы записывается до и возвращается после.

## Файрвол из установленного exe (U11)

Правило файрвола Windows привязано к пути исполняемого файла, поэтому проверка идёт из
установленного приложения, а не из `node.exe`. Работает, только пока в установщике включён fuse
`runAsNode` — то есть на установщике до пересборки U12.

1. Тихая установка: `release\duplexnt-<версия>-setup.exe /S` → `%LOCALAPPDATA%\Programs\duplexnt`.
2. Из корня проекта, с `ELECTRON_RUN_AS_NODE=1`:
   `duplexnt.exe spikes\mdns-discover.mjs 40 each` — появится запрос файрвола.
3. Между ветками «разрешить» и «отклонить» и **после** проверки — от администратора:
   `Remove-NetFirewallRule -DisplayName 'duplexnt.exe'`. Забытое блокирующее правило переживает
   деинсталляцию и достанется следующей установке в тот же путь.
4. Деинсталляция: `"Uninstall duplexnt.exe" /currentuser /S`.
